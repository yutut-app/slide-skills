## 1. なぜ作るか

**同じものを指す語が揺れると、読み手は別のものだと読む。**
「不良」「不具合」「手直し」が混ざると、3つの別の数字に見える。

**初めての領域ほど語が揺れる。**作り手が語を知らないまま書き始め、
途中で正しい語を知って直すと、直し漏れが残る。**最初に決める。**

## 2. 台帳の形

`terms.md` として HTML と同じ場所に置く。

```markdown
# 用語台帳

| 用語 | 使う語 | 使わない語 | 定義 |
|---|---|---|---|
| T1 | 手直し | 不具合, 再作業 | 出荷前に作業者が直したもの |
| T2 | 締付トルク | 締め付け力, トルク値 | 規定トルクに対する実測値 |
```

| 列 | 書き方 |
|---|---|
| 使う語 | **資料の中で使う語は1つだけ** |
| 使わない語 | **カンマ区切り。**直した後の照合で「0件」を確かめるのに使う |
| 定義 | 先方が知らない語は、ここに書いた定義を初出の枚にも書く |

## 3. 使い方

| いつ | すること |
|---|---|
| 書くとき | **台帳の「使う語」だけを使う。**新しい語が要るなら、先に台帳に足す |
| 語を変えるとき | 旧い語を「使わない語」に移す。**台帳を先に直してから本文を直す** |
| 直した後 | **照合して、使わない語が0件になったことを確かめてから報告する** |
| 渡すとき | **台帳を引き継ぎ一式に含める**（`49_handoff.md`）。受け取った側も同じ語で直せる |

```bash
python3 scripts/ledger_check.py work/*.html --terms terms.md --numbers numbers.md
```

**0件でなければ報告しない。**残っている枚と語が一覧で出る。
