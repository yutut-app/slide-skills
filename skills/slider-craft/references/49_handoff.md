# 49_handoff — 2人以上で1つの資料を回す

**このスキルを、別の人・別の機械でも使うときに読む。**

段階1は利用者の手元、段階2は提出先や第三者の手元、というように
**担当が分かれることがある**（`48_html.md` 3章）。
そのとき**両方がこのスキルを使う**なら、環境差の問題は相手側で解ける。
**解けないのは受け渡しの方。**

## 1. 相手も同じスキルを使うと、何が解けるか

| 問題 | 相手がこのスキルを使わない場合 | **使う場合** |
|---|---|---|
| 相手の環境の絵をこちらで再現できない | 埋まらない。画像をもらうしかない | **解ける。**相手側が相手の環境で絵を出す |
| 相手が pptx を手で直してしまう | 起きる。次の変換で消える | **起きにくい。**同じ規約が効く |
| 資料が外に出る | 規約が効かない | **効く。**「資料を外に出さない」が両方に効く |

**それでも解けないもの。**

| 問題 | なぜ |
|---|---|
| **どちらが正本を持っているか** | スキルは1人分の作業しか見ていない |
| **どこまで進んだか・何が未決か** | 会話の中にしかない。渡らない |
| **テンプレートが相手の手元に無い** | テンプレートは git に入れない（`.gitignore`） |

以下はその3つを塞ぐためのもの。

## 2. 正本は1つ。同時に直さない

**HTML 一式が正本。** それを持っている人だけが直す。

```
渡す → 相手が直す → 返ってくる → こちらが直す
```

**両方が同時に直さない。** 同じファイルの別の版ができ、統合できなくなる。

| してはいけない | 何が起きるか |
|---|---|
| 渡した後に、こちらでも HTML を直す | 相手の版と食い違う。**どちらが新しいか分からなくなる** |
| 相手が pptx を手で直す | 次の変換で消える（`48_html.md`） |
| 誰が持っているか確かめずに直し始める | 上と同じ |

**手元にあるか分からないときは、直す前に確かめる。**

## 3. 渡すもの

**HTML だけ渡さない。** 相手の手元で同じ絵にならない。

| 渡すもの | 無いとどうなるか |
|---|---|
| HTML 一式（スライドの HTML と `print.html`） | — |
| **`images/`** | ロゴや図が出ない |
| **テンプレート一式**（`template-manifest.md` を含む） | **px→pt の係数が読めず、スライドサイズが狂う**（`48_html.md`）。**両方が同じものを持っているなら、同梱せず一致を確かめるだけでよい**（下記） |
| **引き継ぎメモ**（下の型） | どこまで進んだか、何が未決かが渡らない |
| 直近の pptx（任意） | 相手が見た目の議論をしている場合の出発点 |

**テンプレートは git に入っていない。** 相手の手元にあるとは限らない。
**同梱するか、相手が持っていることを確かめる。**

### md は写し。HTML の代わりにならない ★

**渡すのは HTML 一式。** md を付けるのはよいが、**md だけで渡さない。**

**md から HTML は組み立て直せない。**一度その方式を検討し、
文字1つずつの座標と線の始点・終点が入らないため、
**作図と図表の位置が再現できない**と分かった。

**「HTML が大きすぎる」は、送る手段を変えて解く。**
共有フォルダ・USB・zip・分割送信。**規約を曲げて md で代用しない。**

md を付けるときも、**CSS や座標を書き写さない。**

| 理由 | |
|---|---|
| **相手も同じテンプレートを持っている** | 位置・大きさ・書体・配色はそこにある |
| **写しは古くなる** | テンプレートを直した瞬間、md の座標は嘘になる |
| **同じ決めごとが2箇所になる** | 最頻の事故（`docs/feedback.md` の原因 I） |

md に書くもの（**読む用**。変換には使わない）。

```
1枚ごと:
- どの種別のレイアウトか（表紙／目次／リードあり／付録／フリー）
- 文言（見出し・リード・本文・注記）をそのまま
- 表は md の表で。**中身だけ。列幅は書かない**
- 図は **型と数値**。「パレート図：不良項目と件数、累積比率」
- その枚で言いたいこと（メッセージ）

全体:
- 段階と、段階1が終了宣言済みかどうか
- テンプレート名と**指紋**
- スキルの版
- **未決**と**触っていないもの**
```

**図の絵を指定しない。** 受け取った側が pptx と Excel で作る（`SKILL.md` の担当表）。
**こちらが決めるのは数値と主旨だけ。**

### テンプレートの一致は、名前ではなく中身で確かめる

**「同じものを用意した」だけでは足りない。** 片方だけ直されるとずれる。
実際に、修正を HTML テンプレートに反映して中身が変わっている。

**指紋を取って突き合わせる。** 一致すれば同じ、違えば違う。

```bash
python3 scripts/handoff.py <テンプレ>ディレクトリ --fingerprint
```

```
<テンプレ名>  指紋 <12桁>  スキルの版 <7桁>
```

**計算は必ずこのスクリプトで行う。** 手で `shasum` を打つと、
ファイルの並び順が違って**別の値になり、照合できない**（実際にそうなった）。

**値をここに書き写さない。** テンプレートを直すたびに変わるので、
書いた瞬間から古くなる。**そのつど計算する。**

**指紋は `images/` も見ている。** ロゴなどの画像でも見た目は変わるので、
html だけを見ていると**ロゴが違うのに指紋は一致する。**
実際に、片方が仮のロゴのままでも気づけない状態だった。

**計算のしかたを変えると、以前に配ったメモの値は合わなくなる。**
古い値と突き合わせない。**両方の手元で取り直す。**

**違っていたら、そのまま進めない。** どちらが新しいかを確かめ、揃えてから始める。
**新しい方に揃える。**片方の修正が黙って消える。

**指紋を引き継ぎメモに書く。** 受け取った側が自分で計算して突き合わせられる。

**渡す操作は承認ポイント。** 資料が手元の外に出る（`SKILL.md` 冒頭「資料を外に出さない」）。
**利用者が渡す。こちらが送らない。**

## 3-2. スキルそのものの配り方 ★環境の決めごと

**スキルを直すのは1箇所だけ。受け取った側は使うだけで、直さない。**

| | 直す | 使う |
|---|---|---|
| スキル本体（`SKILL.md`・`references/`・`scripts/`） | **配布元だけ** | 受け取った側 |
| 資料の HTML | **正本を持っている側**（2章） | — |
| テンプレート | **配布元だけ** | 受け取った側 |

### 受け取った側は、スキルを直さない

**直しても次の配布で消える。** 資料テンプレートと同じ構造で、
上書きされて気づかない。

**不具合や不足に当たったら、直さずに配布元へ報告する。**
報告は**配布元のリポジトリ直下** `<slide-skills>/docs/feedback.md` に集約する。
**スキルディレクトリの下に作らない。** そこは配布物であり、記録の置き場所ではない
（実際に `skills/slider-craft/docs/feedback.md` を作って台帳が割れた）。
**台帳が2つに割れると、同じ原因が何回起きたかを数えられなくなる。**

報告に入れるもの。

| 項目 | なぜ |
|---|---|
| 何をしようとしていたか | 場面が分からないと規約を直せない |
| 期待した挙動 / 実際の挙動 | **どこがどう違ったか。数や箇所を書く** |
| スキルの版（下記） | 古い版の既知の不具合かどうかが分かる |

### 版を突き合わせる

スキルは git に入っている。**版はコミットで表す。**

```bash
git -C <slide-skills> log -1 --format=%h
```

```
例: 4c9c21e
```

**配布元と受け取った側で版が違えば、挙動が違う。**
**指摘が再現しないときは、まず版を疑う。**

**版を引き継ぎメモに書く。**

## 4. 引き継ぎメモの型

`HANDOFF.md` として HTML と同じ場所に置く。**会話の中に残さない。**

```markdown
# 引き継ぎ

版: rev3（2026-09-14）
渡す人 → 受け取る人: <誰> → <誰>
**スキルの版: <7桁>**  ← 違えば挙動が違う。指摘が再現しないときはここを疑う

## 今どこ
段階: 2（見た目・装飾・レイアウトを詰めている）
**段階1（テキストと大枠）は終了宣言済み。**

## テンプレート
名前: <テンプレ名>
スライドサイズ: 780×540pt（1pt = 1.641026px）
**指紋: <12桁>**  ← 受け取った側は自分で計算して突き合わせる
同梱した / 相手が持っている（どちらかを書く）

## 直近で直したこと
| スライド | 直したこと |
|---|---|
| 3 | リード帯の文言を「〜」に変更 |

## 図
まだ入れていない / rev3 の pptx に入れた（どちらかを書く）
**図を入れた pptx は再変換すると消える。**入れた版を必ず書く。

## 未決
- 4枚目のコスト内訳、数値の出所待ち
- 表紙のロゴが仮のもの

## 触っていないもの
スライド 1, 2, 5
```

**「未決」と「触っていないもの」を必ず書く。**
無いと、受け取った側は全部を疑って読み直すことになる。

## 5. 受け取った側がすること

**受け取った HTML は、自分が作ったものではない。**

1. **引き継ぎメモを読む。** 無ければ、渡した人に聞く。推測で始めない
2. テンプレートが手元にあるか確かめる。無ければもらう。
   **あっても指紋を突き合わせる。**名前が同じでも中身が違うことがある
3. **段階を確認する。** メモの段階に従う。**自分で段階を進めない**（`48_html.md`）
4. **スキルの版を突き合わせる。** 違えば配布元に新しいものをもらう。
   **自分でスキルを直さない**（3-2）
5. 絵を出して、現状を自分の目で見る

```bash
python3 scripts/html_png.py <受け取った>/print.html -o qa_html
python3 <slider-deck>/scripts/html2pptx.py <受け取った>/print.html -o deck/deck_rev<n>.pptx
python3 <slider-deck>/scripts/qa_render.py deck/deck_rev<n>.pptx -o qa
```

**同じ HTML でも、相手の環境とは絵が違う。** フォントが違えば折り返しが変わる。
**「前の人の環境ではこう見えていたはず」と考えない。**
自分の環境で見えているものが、自分の環境での事実。

**返すときも、同じ型の引き継ぎメモを付ける。** 片道だけ書いても続かない。
