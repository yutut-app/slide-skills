# 10_intent — 意図の確定

手順1で読む。**ここが埋まらないまま骨子を書くと、後で全部作り直しになる。**

## 埋める4点

会話履歴と手元のファイルから先に拾う。**足りない分だけ聞く。全部を質問しない。**

| # | 問い | 確定させること | 埋まらないときの症状 |
|---|---|---|---|
| 1 | 何のプロジェクトで、何が問題か | 背景と課題。**現状と、あるべき姿の差** | 「現状報告」だけの資料になり、で何？と言われる |
| 2 | 誰に、何を判断してほしいか | 相手と、相手に取ってほしい行動、**姿勢と決裁権** | 誰向けか分からない中途半端な粒度になる |
| 3 | どのフェーズの資料か | 提案／中間報告／最終報告／意思決定依頼 | 枚数と構成が決まらない |
| 4 | この資料の成功とは何か | 資料を見た相手が何をしたら成功か | 何を削ってよいか判断できない |

## 5. 作り方に関わる確認（忘れると後で効く）

**この5点は資料の中身ではないが、作り方を決める。**手順1でまとめて聞く。

| 問い | 効くところ | 既定 |
|---|---|---|
| テンプレートのファイル形式は（.pptx / .potx / 無し） | 生成経路が変わる（`<slider-deck>/references/50_build.md`） | 無し |
| スライドサイズをテンプレートに合わせるか | **合わせる。16:9 に直さない**（ブランドが崩れる） | 合わせる |
| **話者がいるか**（説明する／配布だけか） | **情報密度が変わる。**配布だけなら文字を厚く、話者がいれば薄く | 話者あり |
| 聴き手の前提知識 | 用語をどこまで説明するか | 下表で確認 |
| **納品後に利用者自身が編集するか** | する場合は最初から差分修正モードで設計する（`<slider-deck>/references/55_revise.md`） | する |

**「話者がいるか」を聞き忘れると、密度が2倍ずれる。**
配布だけの資料にスピーカーノート前提の薄いスライドを渡すと、読んでも分からない。

## 1. 背景と課題

**「課題」を、現状とあるべき姿の差として書かせる。** 片方だけだと課題にならない。

- ❌ 「不良が多い」（あるべき姿が無い）
- ❌ 「不良率1%を目指す」（現状が無い）
- ⭕️ 「不良率が2.4%。目標1.0%に対し1.4ポイント超過している」

**数値が無いときは、無いと明記する。** 推測値で埋めない。
数値が取れないなら、そのこと自体が資料の1枚目になることもある。

## 2. 相手と、取ってほしい行動

**相手が誰かより、相手に何をしてほしいかが構成を決める。**

| 取ってほしい行動 | 資料に必要なもの |
|---|---|
| 承認する（予算・体制・方針） | 選択肢の比較、推奨案、コスト、リスク、判断の期限 |
| 状況を把握する | 計画との差、差の原因、次にやること |
| 意見を出す | 論点の明示、まだ決めていないことの明示 |
| 実行する | 誰が・いつ・何を、の一覧 |

**行動が2つ以上あるときは止まって聞く。** どれが主かで構成が変わる。

### 姿勢と決裁権も確定する

**`80_audience.md` で先方になりきるときに、厳しさを決める材料になる。**

| 項目 | 選択肢 | 埋まらないときの既定 |
|---|---|---|
| 姿勢 | 賛成寄り／中立／懐疑的 | **中立** |
| 決裁権 | あり／なし（上に諮る） | **あり** |

**相手が複数いるなら、最も厳しい人を基準にする。** その人が納得すれば全員通る。
決裁権が無い相手なら、「上に説明するとき何を聞かれるか」を代わりに問う。

### 相手の前提知識を確認する

| 相手 | 気をつけること |
|---|---|
| 現場 | 用語はそのまま使える。数値の粒度を細かく |
| 自部門の管理職 | 経緯は簡潔に。判断に必要な情報に絞る |
| 他部門・役員 | **専門用語に説明を付ける。**略語は初出で展開する |
| 社外 | 内部の固有名詞（設備番号・人名）を出さない |

## 3. フェーズと枚数の目安

| フェーズ | 本編の枚数 | 構成の重心 |
|---|---|---|
| 提案（初回） | 8〜12枚 | 課題の共有と、やる価値の提示 |
| 中間報告 | 5〜8枚 | 計画との差と、その原因 |
| 最終報告 | 10〜15枚 | 結果と、やったことの再現手順 |
| 意思決定依頼 | 3〜5枚 | 選択肢の比較と推奨。**背景は付録へ** |

**枚数は目安であって規則ではない。** ただし上限の1.5倍を超えたら、
本編と付録に分ける。

## 4. 成功の定義

**「資料を見た相手が何をしたら成功か」を1文で書かせる。**
これが書けないと、何を削ってよいか判断できない。

- ⭕️ 「部長が、治具交換の頻度変更を承認する」
- ⭕️ 「他ラインの担当者が、同じ手順を自分のラインで試す」
- ❌ 「現状を理解してもらう」（何をしたら成功か分からない）

## やらないことを明示する

**資料に載せないことを、先に決めておく。**
決めないと、途中で「あれも入れよう」が積み上がり、枚数が倍になる。

- この資料で扱わない範囲
- 付録に回すもの（詳細データ、経緯、検討したが落とした案）
- 口頭で補足するもの（スピーカーノートに書く）

## 出力の形

4点が埋まったら、次の形で示して**承認を待つ**。

```markdown
## 資料の前提

| 項目 | 内容 |
|---|---|
| 背景・課題 | 不良率が2.4%。目標1.0%に対し1.4ポイント超過 |
| 相手 | 製造部長（決裁権あり・中立）、品質保証課長（決裁権なし・懐疑的） |
| 取ってほしい行動 | 治具交換頻度の変更（年2回→月1回）を承認する |
| フェーズ | 意思決定依頼 |
| 成功の定義 | 部長がこの場で承認し、来月から運用が変わる |
| 扱わない範囲 | 他ラインへの展開（別途提案） |
| 付録に回す | 6ヶ月分の生データ、検討して落とした2案 |
```

**未確定の項目は「未確定」と書き、推測で埋めない。**
埋めた項目と推測した項目が同じ見た目だと、後で間違いに気づけない。
