# 46_numbers — 数値の検算と、数値の連鎖

**資料に出る数値は、1つ変えると他の枚に波及する。**
実案件で、1つの数字を変えると4〜9枚が崩れる構造になった。
**毎回すべての枚を見比べて整合を取った。**規約が無かったため、手作業だった。

## 1. 数値の検算

**資料に出る数値を全部検算する。**「それらしい数値」を置かない。

```
数値の検算:
- [ ] 表の縦計が、合計欄と合っているか
- [ ] 率と件数の関係が合っているか（件数 ÷ 母数 = 率）
- [ ] 層別した件数の合計が、元の総件数と一致するか
- [ ] 前後比較の期間・母数の条件がそろっているか
- [ ] グラフの軸の値と、表の数値が一致しているか
- [ ] 管理限界・規格値など、計算で出す値に根拠があるか
- [ ] 単位が統一されているか（件／%／台／時間）
```

**層別表と管理図は特に間違えやすい。**
層別の合計が元と合わない／管理限界が根拠のない値は、繰り返し起きる。

## 2. 数値の連鎖 ★

**1つの数値が、複数の枚に別の形で出る。**

| 元の数値 | 派生して出るところ |
|---|---|
| 総件数 | 率の分母、グラフの軸、サマリの文、表紙の副題 |
| 上位項目の件数 | 率、パレート図の棒と累積線、リード帯の文言、結論 |
| 期間 | 表の見出し、注記、前後比較の条件、表紙の日付 |
| 対象範囲（台数・工程数） | 母数、図の枠、「〜のうち」の文 |

**片方だけ直すと、資料の中で食い違う。**
読み手は必ず気づく。**気づかれた時点で、資料全体の信頼が落ちる。**

**「直した枚だけ検算する」で済ませない。**
検算は1枚の中の整合しか見ない。**連鎖は枚をまたぐ。**

## 3. 台帳を1つ作る

**元になる数値を1箇所にまとめ、どの枚に出るかを書く。**
これが無いと、変更のたびに全枚を読み直すことになる。

`numbers.md` として HTML と同じ場所に置く。

```markdown
# 数値の台帳

| # | 数値 | 値 | 出所 | 出てくる枚 |
|---|---|---|---|---|
| N1 | 総件数 | 128件 | 不良記録 2026-01〜06 | 3, 6, 7, 16 |
| N2 | 上位項目の件数 | 79件 | 同上 | 6, 7, 11, 16, 18 |
| N3 | N2 ÷ N1 | 62% | **計算** | 3, 6, 16 |
| N4 | 対象期間 | 2026-01〜06 | 依頼時の指定 | 1, 3, 6, 16 |
```

| 列 | 書き方 |
|---|---|
| 値 | **単位を付ける** |
| 出所 | **計算で出すものは「計算」と書き、式を残す**（`N2 ÷ N1`） |
| 出てくる枚 | **全部書く。**1つ落とすと、そこが取り残される |

**台帳は引き継ぎメモと一緒に渡す**（`49_handoff.md`）。
受け取った側が数値を直すときに、同じ連鎖を辿れる。

## 4. 変えるときの手順

**1つの数値を変える依頼が来たら、変える前に影響範囲を出す。**

1. 台帳でその数値の行を引き、**出てくる枚を列挙する**
2. **計算で出している数値（式のある行）も洗う。**元が変われば一緒に変わる
3. **枚の一覧を利用者に見せてから直す。**「3枚直します」ではなく
   「3, 6, 16 の3枚と、それに連なる 7, 11, 18 を直します」
4. 直したら、**台帳の値も直す**
5. **全枚で古い値が残っていないか検索する**

```bash
grep -rn "128件\|62%" work/*.html
```

**台帳が無い資料を引き継いだら、まず作る。**
作らずに直すと、必ずどこかが取り残される。

**「この数値は他に出ていないはず」と推測しない。**検索する。

## 5. 出せない数値の扱い

**計算できないなら「未確認」と書く。** 埋めるために数字を作らない。
出所が言えない数値は、先方に必ず聞かれる（`80_audience.md`）。

| 状況 | 書き方 |
|---|---|
| 値が未着 | **「未確認」**。空欄にしない（抜けと区別できない） |
| 概算しかない | **「約」を付け、根拠を注記に書く** |
| 範囲でしか言えない | **「50〜60件」**。中間値を1つ書かない |

**未確認の数値は引き継ぎメモの「未決」に必ず載せる。**
載せないと、次の担当が確定値だと思って使う。
