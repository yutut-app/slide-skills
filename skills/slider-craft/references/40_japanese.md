## 1. 文体は部位で固定する

**「である調かですます調か」で悩まない。実務が重視しているのは、部位ごとに固定して
混在させないこと。** 混在は「統一感がなくだらしない」と受け取られる。

| 部位 | 文体 | 例 |
|---|---|---|
| 見出し（スライドタイトル） | **体言止め** | 「不良低減の進捗」 |
| メッセージライン | **言い切り**（常体の終止形） | 「3号機に不良の6割が集中している」 |
| ボディの箇条書き | **体言止めで統一** | 「治具の位置決めピンの摩耗」 |
| 図中のラベル | 体言止め | 「1次手段」「代替手段1」 |
| 注記・出典 | 体言止め、または言い切り | 「2026年1月〜6月の実績」 |
| 話す内容 | 敬体でよい | スピーカーノートに置く。スライドには載せない |

### 句点は付けない

**全スライドで統一する。** 体言止めが主体なので、付けない方が自然。
1枚でも付けると混在になる。

#### 例外：説明文が主体の資料 ★

**箇条書きではなく、文が主体の資料では付ける。**
報告書・議事録のように「読ませる」資料は、句点が無いと文の切れ目が消える。

| 部位 | 句点 |
|---|---|
| **文**（主語と述語がある） | **付ける** |
| 箇条書き・表の中・図中のラベル・見出し | **付けない** |

**資料の途中で方針を変えない。** 手順1で「箇条書き主体か、文主体か」を決め、
**引き継ぎメモに書く。**決めた記録が無いと、次の担当が逆に直す。

### 例外は1つだけ

**因果や条件を含む行は、用言止めを許可する。** 体言止めにすると因果が消えるため。

- ❌ 「A工程の遅延によるB工程の連鎖遅れ」（何が起きるか読み取れない）
- ⭕️ 「A工程が遅れるとB工程も連鎖して遅れる」（用言止め）

**ただし、そのスライドの中では統一する。** 1枚の中で体言止めと用言止めを混ぜない。
因果の行が1つでもあるなら、そのスライドは全行を用言止めにする。

## 2. AI感の正体と、その除去

「AI感」は感覚語ではなく、**検出できる4つの癖**の集合。1つずつ潰す。

### 2-1. 禁止語 — そのまま置き換える

これらは文章を翻訳調・論文調にし、かつ中身を薄く見せる。

| 禁止 | 置き換え |
|---|---|
| 〜である、〜であると考えられる | 「〜する」「〜できる」「〜が課題」（言い切り） |
| 〜が求められる、〜が必要とされる | 「〜する」「〜を実施する」（誰がやるかを書く） |
| 〜と言えるだろう、〜ではないだろうか | 断定するか、書かない |
| 〜において、〜における | 「〜で」「〜の」 |
| 〜を行う、〜を実施する（中身が無いとき） | 動詞そのものにする（「検討を行う」→「検討する」） |
| 最適な、効果的な、適切な、シームレスな、抜本的な | **数値か固有名詞に置換する**（下記2-3） |
| さらなる、より一層の、着実な | 削除する |
| 昨今、近年、〜が注目されている | 削除する。スライドに時候の挨拶は要らない |

**検査は grep でできる。**

```bash
grep -nE "である|と考えられる|が求められる|において|最適な|効果的な|適切な|シームレス|さらなる|昨今|注目されて" deck.yaml
```

### 2-2. 意味の薄い3点セットを作らない

**AI感が最も強く出るのがこれ。** 体言止めの抽象語を3つ並べる癖。

- ❌ 「効率化・標準化・可視化」
- ❌ 「品質の向上、コストの削減、納期の短縮」（何をどうするか無い）

**判定基準**：並べた3語のうち2語以上が「〜化」「〜性」「〜向上」「〜削減」で終わり、
かつ具体的な対象（設備名・工程名・数値）を含まないなら、それは中身が無い。

**直し方**：3つに揃えようとするのをやめる。**言えることだけ言う。**
実質2つなら2つ、1つなら1つでよい。

- ⭕️ 「3号機の治具を月1回交換する（現在は年2回）」

### 2-2-2. 無い根拠を、あるように書かない ★

**「推測で直さない」とは別の規約。** 直すときだけでなく、**書くときにも効く。**

出典があるように読める書き方を、出典が無いのに使わない。

| 書かない | なぜ |
|---|---|
| 「一般に〜とされる」 | **誰がそう言ったのかが無い。**読み手は出典があると受け取る |
| 「〜が知られている」 | 同上 |
| 「業界では〜が標準」 | 調べていないなら、標準かどうか分からない |
| 「〜と言われている」 | 伝聞の形だが、伝聞元が無い |

**書いてよいのは3つだけ。**

| | 書き方 |
|---|---|
| **調べた** | 出典を注記に書く（発行元・年） |
| **測った・数えた** | 数値と、その取り方を書く |
| **こちらの案** | **「案」と分かる形にする。**「〜を提案する」「〜としたい」 |

**根拠の強さを混ぜない。** 測った値と、こちらの案を、同じ書き方で並べない。

### 2-3. 抽象形容詞は、数値か固有名詞に置き換える

**「最適な」「効果的な」は、何も言っていない。**

| ❌ | ⭕️ |
|---|---|
| 最適な生産計画を策定する | 段取り替えを1日3回から1回に減らす |
| 効果的な改善施策を実施する | 3号機の治具交換を月1回にする |
| 抜本的な体制の見直し | 検査工程を2名から3名に増やす |
| 大幅なコスト削減 | 年間420万円の削減 |
| 早期に対応する | 3月末までに対応する |

**判定基準**：形容詞を消しても文の意味が変わらないなら、その形容詞は不要。

### 2-4. 全スライドが同じ形をしていない

箇条書き3点のスライドが5枚続くと、それだけでAI感が出る。
**`30_visual.md` の対応表で図解の型を選べば、自然に形が散る。**

**判定基準**：同じ型のスライドが3枚以上続いたら、型を選び直す。

## 3. 文字量の上限

16:9（13.333インチ幅）、ボディ14〜18ptを前提とした上限。**全角文字数で数える。**

| 対象 | 上限 | 超えたときの対処 |
|---|---|---|
| メッセージライン | **2行、各行 全角40字**（1行目＝この枚で何をするか、2行目＝結論。`20_story.md`） | 根拠を本文の箇条書きへ落とす |
| 箇条書きの1行 | **全角30字** | 体言止めにして修飾を削る。2行に折り返さない |
| 箇条書きの行数 | **6行** | 図解に変える。7行目が要るなら分割 |
| 1スライドの総文字数 | **全角300字** | 図解に変えるか、スライドを分ける |
| 表のセル | **全角15字** | 略称にして、凡例で正式名称を出す |
| 図中のラベル | **全角12字** | 番号を振り、凡例で説明する |

**上限を超えたら、文字を小さくして収めない。** 12pt未満は会議室のスクリーンで読めない。
**削るか、図にするか、分けるかの3択。**

### 上限の根拠

これは「読みやすさ」の一般論ではなく、**16:9のスライドで14pt以上を保ったまま
収まる量**の上限。フォントサイズを変えたら数え直す。

### 表・図が主体の資料では、総文字数を数え直す ★

**「1スライド全角300字」は、文章が主体の資料の数字。**
表やグラフが主体だと、**表のセルを全部足すだけで超える。**
超えていても、読み手の負荷は文章300字とは違う。

| 数える対象 | 上限 |
|---|---|
| **文章の部分だけ**（リード・本文・注記） | **全角300字** |
| 表のセル・図中のラベル | **総文字数に数えない。**各セル・各ラベルの上限で見る |

**表が主体の枚は、行数と列数で見る。**

| 対象 | 上限 | 超えたときの対処 |
|---|---|---|
| 表の行数（ヘッダーを除く） | **8行** | 上位だけ載せ、残りは別紙。**「その他」でまとめる** |
| 表の列数 | **6列** | 列を統合するか、2枚に分ける |

**上限を緩めた記録を残す。** どこを何字にしたかを引き継ぎメモに書く。
**書かないと、次の担当が「超過している」と報告して直しにかかる。**

## 3-2. スライドに載せないもの ★

**口で言えばいいことを書かない。** 書くと、そのスライドで何を伝えたいのかが埋もれる。

| 載せる | 載せない（口で言う・ノートに置く） |
|---|---|
| **数値と、その出所** | 一般論（「品質は重要である」） |
| **定義**（用語・範囲・前提） | 教訓・所感（「連携が大切だと分かった」） |
| **判断に要る根拠** | 経緯の説明（「まず〜し、次に〜した」） |
| **決めたこと・依頼したいこと** | 手順の細部（聞かれたら答える） |

**線引きの基準は1つ。「これが無いと、先方は判断できないか」。**
判断に要らないなら落とす。**惜しいと思ったらスピーカーノートへ。**

### 同じことを2箇所に書かない ★

**リード帯に書いたことを本文にも書かない。**
これは実案件で**最も多く出た指摘**（1つの資料で3箇所）。

```
❌ リード帯「ネジの緩みが62%を占める」
   本文  「・ネジの緩みが62%で最多」          ← 同じ
⭕️ リード帯「ネジの緩みが62%を占める」
   本文  「・締結トルクの管理値が未設定」      ← リードの根拠
```

**リード帯は結論、本文はその根拠か内訳。**
本文がリードの言い換えになっていたら、本文が空だということ。

**検査は機械でできる。** リード帯の数値が本文にも出ていたら疑う。

## 3-3. 読み手の側から書く ★

**スライドを読むのは、作る過程を知らない人。**作り手の頭の中にある
「前の版」「作り方の注意」「中身」は、読み手には無い。

### 前の版を知らない人が読んで、意味が通るか

**直した経緯や、前の版との対比を書かない。**読み手は前の版を見ていない。

| ❌（前の版を知っている人にしか通じない） | ⭕️ |
|---|---|
| ステップは一方通行ではない | 必要なら前のステップに戻る |
| 教科書どおりの手順ではなく | （対比を消し、この資料での手順だけを書く） |
| 逆算ではなく積み上げで見る | 実績を足し上げて見る |

**「〜ではなく」「〜ではない」は、書いたら必ず見直す。**
打ち消す相手が資料の中に無ければ、それは**前の版か、作り手の頭の中**にある。

### 作り手の作法と、聞き手に伝える内容を分ける

**作るときに守る注意を、スライドに書かない。**聞き手が知りたいのは結果。

| 作り手の作法（載せない） | 聞き手に伝える内容（載せる） |
|---|---|
| 件数ではなく率で比べる | 3号機の不良率は2.4%で、他の倍 |
| 母数の小さい条件を見落とさない | 夜勤は母数12件と少なく、判断は保留 |
| 1次手段は真因を言い換えたもの | 1次手段：締付トルクを管理値に入れる |

**見分け方。**文が「〜する」「〜しない」の**やり方**なら作法、
「〜だった」「〜である」の**事実や判断**なら内容。

### 全体像・目次は、その枚を読まずに意味が通るように書く

**目次や全体像の項目は、中身を読む前に読まれる。**
中身を読まないと分からない言い方にしない。

| ❌ | ⭕️ |
|---|---|
| ここで決めること | 対策を2つに絞る |
| 検証 | 対策後の不良率を3ヶ月測る |

**検査：目次の1行だけを読み、その枚で何をするかが言えるか。**

## 4. 改行と禁則

日本語は英語と違い、単語の途中でも折り返される。**自動折り返しに任せると、
意味の切れ目でない場所で改行される。**

### 4-1. 意味の切れ目で手動改行する

- ❌ 自動折り返し：「3号機の治具の位置決めピンが摩耗して<br>いる」
- ⭕️ 手動改行：「3号機の治具の位置決めピンが<br>摩耗している」

**手動改行を入れる位置**：助詞（は・が・を・に・で・と）の直後、または読点の直後。
**名詞の途中、送り仮名の途中では絶対に切らない。**

### 4-2. 行頭に置いてはいけない文字

次の文字が行頭に来たら、手動改行の位置を1文字ずらす。

```
閉じ括弧  ）」』】〕
句読点    。、
小書き    ぁぃぅぇぉっゃゅょァィゥェォッャュョ
長音・繰返 ー々
記号      ・：；？！
```

行末に置いてはいけないのは開き括弧 `（「『【〔`。

### 4-3. 実装上の注意

- **PowerPoint のテキストは、改行を段落として入れる。**
  1つの run に `\n` を入れると、2行目だけ配置がずれる（実際に発生した）
- **表のセルでは手動改行を使わない。** 列幅を変えると位置がずれる。
  セルに収まらないなら略称にする
- **英数字と日本語の間の半角スペースは、入れるか入れないかを資料内で統一する。**
  どちらでもよいが、混在させない。**テンプレートがある場合はその流儀に合わせる**

## 5. フォントとサイズ

**フォントと文字サイズは、資料テンプレートが決める。本スキルで固定しない。**

テンプレートがあるなら、まず読み出す。

```bash
python3 scripts/read_template_style.py ../../assets/templates/deck/<file>.pptx
```

出力（テーマの見出し用・本文用フォント、レイアウトごとの文字サイズ、テーマの配色）を
`assets/template-map.md` に書き写す。**そのうえで、図のテンプレートを同じフォントで
作り直す。** 図だけ別のフォントだと、貼った瞬間に浮く。

```bash
python3 scripts/gen_chart_templates.py --font '<日本語フォント名>'
python3 scripts/gen_qc7_templates.py   --font '<日本語フォント名>'
python3 scripts/gen_pptx_templates.py  --font '<日本語フォント名>'
```

配色も同じ。**テンプレートのテーマ配色に合わせる。**
本スキルの既定の4色は、テンプレートが無いときだけ使う。

### テンプレートが無いときの既定値

| 用途 | フォント | サイズ |
|---|---|---|
| 見出し | 游ゴシック Medium | 20〜24pt |
| メッセージライン | 游ゴシック Bold | 13〜16pt |
| ボディ | 游ゴシック | 14〜18pt |
| 表・図中のラベル | 游ゴシック | 9〜12pt |
| 注記・出典 | 游ゴシック | 8〜9pt |

游ゴシックは Windows 8.1 以降に標準搭載されているため、配布先が Windows なら
これで崩れない。**ただし macOS には無いことがある。**
その場合、この端末での検査は代替フォントでの表示になる（`<slider-deck>/references/60_qa.md` を見る）。

- **1つの資料で使うフォントは1種類。** 明朝とゴシックを混ぜない
- **強調は太字だけ。** 下線・斜体・影・袋文字を使わない。
  斜体は日本語フォントでは擬似的に傾けられ、字形が崩れる
- **色による強調は1スライドに1箇所。** 全部が強調なら、どれも強調でない
- **テンプレートがある場合は、テンプレートのフォント設定が優先する。**
  上の表は、テンプレートが無いときの既定値

## 6. 検査の手順

手順5で次を順に行う。**1つでも不合格なら手直しする。**

```
文章の検査:
- [ ] 禁止語が残っていないか（grep）
- [ ] 意味の薄い3点セットが無いか
- [ ] 抽象形容詞が数値か固有名詞になっているか
- [ ] 文体が部位ごとに固定され、1枚の中で混在していないか
- [ ] 句点が全スライドで統一されているか（付けない）
- [ ] 文字量が上限内か（メッセージライン40字、箇条書き30字×6行、合計300字）
- [ ] 手動改行が助詞・読点の直後にあるか
- [ ] 行頭禁則に触れていないか
- [ ] 同じ型のスライドが3枚以上続いていないか
```

### 不合格のときの報告の形

**「文章を修正しました」で済ませない。** 何がどう変わったかを、対で示す。

```markdown
| スライド | 検査項目 | 修正前 | 修正後 |
|---|---|---|---|
| 4 | 抽象形容詞 | 効果的な改善施策を実施 | 3号機の治具交換を月1回にする |
| 7 | 文字量 | 箇条書き9行 | 表に変更（`charts/02_横棒グラフ`） |
```

この表を出すと、利用者は直った範囲を確認でき、直っていない箇所に気づける。
