## 1. 何が正か

```
資料テンプレート(.pptx)  ← 体裁の出どころ。書き換えない
        ↓
     HTML  ← **これが正。人が直すのはここだけ**
        ↓ html2pptx.py
     pptx  ← 派生物。レビューのために作る。**手で直さない**
        ↓ 検査（fit_check / qa_render / 先方の目）
     指摘 → HTML に戻る
```

**要るのはテンプレートであって、元の pptx ではない。**
テンプレートが無ければ汎用のものを使う（`slider-reskin/references/20_templates.md`）。

**pptx を手で直さない。** 次の変換で消えるうえ、同じ症状が次回も出る。
利用者が pptx を手で編集した場合は `<slider-deck>/references/55_revise.md` の差分修正モードに入る。

## 2. 2つの入り口

### A. 最初から作る

**土台はテンプレートの HTML。白紙から書かない。**
テンプレートの形で起こし方が変わる（`SKILL.md` 手順0で見分ける）。

**テンプレートが HTML 一式のとき（`template-manifest.md` がある）は、
下の「3-2」が本線。**種別ごとの HTML をコピーして文字だけ差し替える。
`make_html.py` は使わない。座標を作り直してしまい、実測値が失われる。

テンプレートが `.pptx` のときだけ、編集用の HTML を起こす。

```bash
python3 scripts/make_html.py --template <テンプレ>.pptx -o work/deck.html
python3 scripts/make_html.py --template <テンプレ>.pptx --outline outline.md -o work/deck.html
```

`--outline` は1行1要素の素案。手順2で作った骨子をそのまま流し込める。

```
# 見出し（# の行が新しいスライド）
> メッセージライン
- 箇条書き
  - 入れ子
: 出典・期間・件数
// スピーカーノート
```

**骨子（手順2）の承認が先。** HTML を起こすのはその後。

### B. 受け取った HTML を直す

**元の pptx は要らない。テンプレートだけ確かめる。**

```bash
grep -o '<meta name="template"[^>]*>' <もらった>.html
```

無ければどのテンプレートに載せるかを利用者に聞き、`--template` で渡す。
**勝手に決めない。**テンプレートの選択は見え方すべてを決める。

第三者が作った HTML は、このスキルの書き方に従っていないことがある。
その場合 `html2pptx.py` は中身を推測して載せる。
**変換後の割付表を見て、妥協が起きていないか確かめる。**

## 3. 往復のループ — 2つの段階に分ける

**見るものが段階で変わる。混ぜると、指摘の種類が混ざって両方が中途半端になる。**

```
段階0. 1枚だけ pptx にして、テンプレート自体のずれを潰す
        ↓
段階1（HTML / 利用者の手元）        テキストと大枠のレイアウトを詰める
  1. 直した HTML を Claude Code 上に出す（Browser ペイン）
  2. 利用者が HTML を見て指示する
  3. 絵で意図を確かめてから HTML を直す → 1 に戻る
        ↓  利用者が「テキストと大枠は終わり」と宣言する ★承認ポイント
段階2（pptx / 提出先の環境）        見た目・装飾・レイアウトを詰める
  4. pptx にして渡す
  5. 見た目の指摘を受ける
  6. 絵で意図を確かめてから **HTML を** 直す → 4 に戻る
        ↑  利用者が「段階1に戻る」と宣言したら戻る ★承認ポイント
```

**段階2でも直すのは HTML。** pptx を手で直すと次の変換で消える。

### 段階の切り替えは利用者が宣言する。こちらから打ち切らない

**宣言があるまで、その段階を回し続ける。**

| してはいけない | なぜ |
|---|---|
| 「そろそろ次の段階では」と促す | **利用者が決めること。**促しは打ち切りの圧になる |
| 回数で打ち切る（3回直したから次へ、など） | 回数と、詰まったかどうかは無関係 |
| 指摘が減ったから終わったとみなす | 見ている箇所が変わっただけかもしれない |

**段階1は行き来の起点。** 段階2から戻ってよい。

### 段階2 から段階1 へ戻る

**戻ってよい。** ただし**戻ると段階2で詰めたものは崩れうる**ので、それを述べてから戻る。

| 戻る理由 | 戻ったとき何が起きるか |
|---|---|
| 文言を変えたくなった | **折り返しが変わる。**詰めた行数・改行位置は詰め直し |
| 枚数を増減したくなった | ページ番号と前後のつながりが変わる（`20_story.md`） |
| 図や表を足したくなった | 1枚に入る量が変わる（`45_layout.md`） |

戻るときは、**段階2で詰めた内容のうち、何が崩れるかを先に一覧で出す。**
「戻ります」とだけ言うと、直したはずの箇所が黙って戻る。

**戻った後は段階1の回し方に従う。** 再び宣言があるまで段階2へは進まない。

### 段階1の「1」で見せるのは HTML ★

**利用者が見るのは HTML。** PNG を見せない。PNG はこちらが意図を確かめるためのもの。

#### 既定は「こちらの操作だけで、利用者が見られる状態になる」手段 ★

**利用者のUI操作が要る手段を既定にしない。** 毎回そこで止まる。

| 手段 | こちらで完遂できるか | 使いどころ |
|---|---|---|
| **利用者だけが開ける Artifact** | **できる。**リンクを渡せば開ける | **既定** |
| ローカル HTTP + Browser ペイン | **ペインが開いていれば**できる | ペインが既に開いているとき |
| Browser ペインに `file://` | **できない**。静的スナップショットになる | 使わない |

```bash
# ペインが開いているときは、ローカルサーバ経由にする。file:// は静的になる
python3 -m http.server 8765 --bind 127.0.0.1 --directory <HTMLのある場所>
# preview_start に http://127.0.0.1:8765/print.html を渡す
```

**実績: ペインが hidden のままで見えず、往復が止まった。**
`preview_start` / `tabs_select` / `tabs_create(foreground)` のいずれでもペインを
前面化できず、hidden の間はページが描画されないのでスクロールも失敗する
（`computer timed out after 30s`）。**ペインの表示はこちらから変えられない。**

**ペインが開いていないなら、開いてもらうよう頼むのではなく、Artifact を使う。**
依頼にすると、利用者の手番が1つ増える。

#### 公開はしない

| | |
|---|---|
| 利用者だけが開ける Artifact | **よい。**ただし中身は claude.ai 上に載る |
| **共有リンクを出す・公開する** | **しない**（冒頭「資料を外に出さない」） |

**既存の非公開 Artifact を消すよう促さない。** 消すかどうかは利用者が決める。

### 段階0 を飛ばさない

```bash
python3 <slider-deck>/scripts/stage0.py <テンプレ>/003.html -o work/stage0
```

1コマンドで、HTML の絵・pptx・pptx の絵・レイアウト検査を出す。
**最後に2枚を並べて自分の目で見る。** ここを飛ばすと段階0の意味がない。

**2回通す。**

| 回 | 対象 | 見るもの |
|---|---|---|
| 1回目 | **テンプレートの1枚** | テンプレート由来のずれ |
| 2回目 | **直した後の、自分の資料の1枚** | ずれが自分の資料から消えたか |

**1回目だけで終えない。** 既存の資料を直す仕事では、
テンプレートを直しても**手元の資料に古いずれが残っている**ことがある。

#### テンプレートを書き換えるのは承認ポイント ★

**資料テンプレートは案件ディレクトリの外にある共有資産。**
直せば、他の案件と第三者の手元にも影響する。

**勝手に書き換えない。** 何をどう直すかを述べて承認を取る。
承認が出ないなら、**案件側で回避する**（その資料の中だけで座標を上書きする）。
回避したときは、**テンプレート側に同じずれが残っていることを報告に書く。**

#### なぜ要るか


**テンプレート自体のずれは全ページに効く。**
20枚書いてから段階2で見つかると、20枚分の手戻りになる。

実績: リード帯の縦位置が **HTML は上寄せ、pptx は中央**だった（`anchor="ctr"`）。
1枚で当たりを取っていれば、そこで潰せた。

### 段階1 と段階2 では、見ている人も環境も違う

| | 段階1 | 段階2 |
|---|---|---|
| 見る人 | 利用者本人 | **提出先・第三者のこともある** |
| 環境 | 利用者の手元 | **別の OS・別のフォント** |
| こちらが同じ絵を見られるか | **見られる。**同じ機械で同じブラウザ | **見られないことがある** |

**段階2で、こちらの環境に相手のフォントが無いなら、折り返し位置は再現できない。**
和文フォントが違えば1行に入る文字数が変わる。**実装では埋まらない。**

#### 相手の環境を再現できないときにやること

| やること | なぜ |
|---|---|
| **指摘に画面の画像を添えてもらう** | **これが唯一確実。**相手が見た絵そのものが手に入る |
| 文字量に余裕を持たせる（`45_layout.md`） | 折り返しが1〜2文字ずれても破綻しない |
| **自分の絵は「近似」と明示して報告する** | 「確認しました」と言わない。相手の環境は見ていない |

**相手もこのスキルを使うなら、画像は要らない。**
相手側が相手の環境で絵を出して直す。**受け渡しの型は `49_handoff.md`。**

**画像がもらえず、相手もこのスキルを使わないときは、指摘を言葉で特定してから直す。**
どのスライドの、どの要素の、何が、どうなってほしいのか。
**推測で直さない**（`48_html.md` 下記）。

### 3 を飛ばさない ★このループの要

**利用者は絵を見て指示する。こちらは HTML の文字列しか見ていない。**
同じものを見ていないので、**指示の意図は HTML からは分からない。**

| 利用者の指示 | HTML だけ見て分かるか |
|---|---|
| 「ここの文字が大きい」 | **どこか分からない。**「ここ」は絵の中の位置 |
| 「帯の中で文字が上に寄っている」 | **分からない。**CSS からは読み取れない |
| 「右が詰まって見える」 | **分からない。**値は入っているので異常に見えない |

**指示を受けたら、まず絵を出す。**そのうえで、
どこを指しているかと、直した後どうなるかを述べてから直す。

```bash
python3 scripts/html_png.py work/*.html -o qa_html    # 利用者が見たのと同じ絵
```

**推測で直さない。** 絵を見ずに直すと、別の箇所を直して「直しました」と言うことになる。
どの指示か特定できなければ、**絵を見せて「これですか」と聞く。**

### どちらの絵を出すか

**既定は HTML の絵。** 利用者が見たのは HTML であり、指示の出どころがそこだから。

```bash
python3 scripts/html_png.py work/*.html -o qa_html      # 既定。毎回これ
```

**pptx の絵は、既定では使わない。** 指定の書体が実行環境に無いと
LibreOffice が別の書体に置き換え、**折り返し位置が変わる。**
利用者が見た絵と違うものを見て「ここですね」と言うことになる。

#### pptx の絵も出す条件 — どれか1つでも当てはまったら

| 条件 | なぜ |
|---|---|
| **HTML を3回直した**（前回 pptx を出してから） | 間隔が空くほど、崩れを見つけたときの手戻りが大きい |
| 枚数を増やした・減らした／図や表を足した | 変換の経路が変わる。1枚に収まるかも変わる |
| **書体・文字サイズ・行間・縦位置を変えた** | **pptx で最も崩れる。**HTML では正しく見える |
| テンプレートを差し替えた | 体裁の出どころが変わる |
| 利用者に渡す前（最終） | 渡すのは pptx。見ずに渡さない |

```bash
python3 <slider-deck>/scripts/html2pptx.py work/*.html -o deck/deck_rev<n>.pptx
python3 <slider-deck>/scripts/qa_render.py deck/deck_rev<n>.pptx -o qa
python3 <slider-deck>/scripts/fit_check.py check deck/deck_rev<n>.pptx
```

**出したら HTML の絵と並べて、ずれを探す。** 片方だけでは出ない。

実績: リード帯の縦位置が **HTML は上寄せ、pptx は中央**だった（`anchor="ctr"`）。
16:9・A4 の両テンプレートで起きており、**利用者が承認した絵と、出てくる絵が違う。**

#### 例外 — 書体が入っている環境なら

**指定の書体が入っていれば、pptx の絵は利用者が見る姿にほぼ一致する。**
その場合は上の条件を緩めてよい。**入っているかを確かめてから緩める。**

```bash
python3 <slider-deck>/scripts/qa_render.py --probe
```

**どこにも公開しない。** ローカルに PNG を書くだけ。

**区切りごとに版を残す。** 出力は毎回別名にし、前の版と比べられるようにする。

```bash
python3 <slider-deck>/scripts/diff_slides.py deck/deck_rev1.pptx deck/deck_rev2.pptx
```

**重なり・はみ出し・溢れはゼロになるまで回す。**回数で打ち切らない
（`45_layout.md`）。見た目の好みのループとは区別する。

## 3-2. テンプレートが HTML 一式のとき（マニフェスト方式）

テンプレートが `.pptx` ではなく、**px 絶対座標の HTML 一式**で渡されることがある。
元 PPTX の図形座標を px 換算した実測値が入っていて、
**値を変えずにテキストだけ差し替えれば元 PPTX と同じ見た目に戻る**作りになっている。

```
テンプレート一式/
├── template-manifest.md   種別一覧・配色・フォント・共通パーツの座標
├── 001.html 〜 004.html   1ファイル = 1スライド種別
├── free.html              ヘッダーとフッターだけの土台
├── print.html             全スライドを iframe で連結したビューア
├── images/                ロゴなど
└── preview/               **確認用に出した .pptx。テンプレートの正本ではない**
```

**この形は自動で判別する。** `.slide` に px の寸法があり、
`position: absolute` を使っていれば絶対座標の経路に入る。

```bash
# print.html を渡すと、中の iframe の並びをそのまま使う
python3 <slider-deck>/scripts/html2pptx.py <テンプレ>/print.html -o deck/deck.pptx

# ファイルを個別に、順番に渡してもよい
python3 <slider-deck>/scripts/html2pptx.py 001.html 003.html 003.html 004.html -o deck/deck.pptx
```

**テンプレートの .pptx は要らない。** HTML に書かれた座標をそのまま写す。

### px→pt の換算係数は 96dpi とは限らない ★間違えるとスライドサイズが狂う

HTML を起こした人が、元 PPTX の pt 座標を**どの係数で px にしたか**はテンプレートごとに違う。

| テンプレート | キャンバス | 1pt = | 元 PPTX |
|---|---|---|---|
| 16:9 版 | 1280×720px | 1.333333px（96dpi） | 960×540pt |
| **A4 版** | 1280×886px | **1.641026px** | **780×540pt** |

**96dpi 決め打ちにすると、A4 版は 960×664pt で出て元 PPTX と一致しない。**
見た目は整っているので、スライドサイズを見ない限り気づけない。

`html2pptx.py` は同じ場所の `template-manifest.md` から `1pt = <n>px` を読む。
無ければ 96dpi に落ちる。**マニフェストにこの行を必ず書く。**
変換後に出る「px→pt 換算: 1pt = … / 出どころ: …」を毎回読み、
**「既定（96dpi）」と出たら、それでよいか確かめる。**

```bash
python3 <slider-deck>/scripts/html2pptx.py <テンプレ>/print.html -o out.pptx --px-per-pt 1.641026
```

### 使い方

1. 作りたいページの種別に合う HTML をコピーする（本文なら `003.html`）
2. **座標・サイズ・フォントサイズは変えない。** テキストだけ差し替える
3. 並べる順に番号を付け、`print.html` の iframe を並べ替える
4. 変換して検査する

`template-manifest.md` に共通パーツの座標と、使ってよい領域が書いてある。
**本文領域の外に置かない。**

### 実物で確かめる

**HTML の見た目が意図どおりでも、PowerPoint での見え方は別。**
テンプレートを作った直後と、大きく直した後は、実物で確かめる。

```bash
python3 <slider-deck>/scripts/html2pptx.py <テンプレ>/print.html -o <テンプレ>/preview/<名前>.pptx
```

**確認用の pptx はテンプレート直下に置かない。** `preview/` に入れる。
直下に置くと、次にこのテンプレートを使うとき
**どれがテンプレートの正本か分からなくなる**（`.pptx` を正本と誤認する）。

**`.pptx` で出す。** 開いてそのまま見比べられ、検査スクリプトもかけられる。

`--potx` で PowerPoint テンプレート形式にもできるが、**確認には使わない。**
python-pptx が potx を開かないため、`fit_check.py` などの検査が通らなくなる。
potx が要るのは、PowerPoint にテンプレートとして登録するときだけ。

**ずれていたら直すのは HTML テンプレート。** 出力された pptx を手で直さない。
次の変換で消えるうえ、テンプレートとして配ったときに同じずれが再発する。

```
HTML テンプレを直す → pptx で出す → PowerPoint で見る → ずれを見つける → 先頭へ
```

**確認する順**（ずれやすい順）。

1. スライドサイズと余白（元 PPTX と同じか）
2. 共通パーツの位置（ロゴ・フッター帯・ページ番号・区切り線）
3. 書体と文字サイズ（**指定の書体が入っている環境で見る**）
4. 色（テーマ色と一致するか）
5. 行送りと折り返し位置

### 書体は3箇所に書く

`font-family` から、欧文（`latin`）と和文（`ea`）を取り出して pptx に書く。
**書く先は3箇所ある。**

| 書く先 | 書かないとどうなるか |
|---|---|
| 各文字（run）の latin / ea / cs | 既存の文字が既定の書体になる |
| テーマの majorFont / minorFont | **PowerPoint のフォント欄に既定が出て、新しく打った文字がその書体になる** |
| テーマの script 別フォント `Jpan` | 日本語だけ別の書体になる |

**2つ目と3つ目は、既存の文字が正しく見えるので気づけない。**
テンプレートとして配り、誰かが文字を足したときに初めて露見する。

和文の書体名は、`font-family` に日本語表記の別名（`'メイリオ'`）があればそちらを採る。
元 PPTX の表記に合わせると、PowerPoint のフォント欄の表示が一致する。

### 図と表 — HTML は設計図。pptx では作り直す ★

**HTML の `<svg>` を線ごとに写しても意味がない。**
写せたとしても、受け取った側は**数字を直せない画像**を受け取るだけになる。
資料を渡す目的は、相手が読んで判断し、必要なら手を入れられることにある。

**分かれ目は「絵から元の情報が戻せるか」。**

| HTML に書くもの | pptx での姿 | 受け取った側 |
|---|---|---|
| `<table>` | **ネイティブの表**（自動で変換する） | **数字を直せる** |
| `<svg>` の**線と矢印** | **ネイティブのコネクタ**（自動で変換する） | **線を動かせる** |
| `<svg>` の**数値グラフ**（数を書いた） | **ネイティブのグラフ**（自動で変換する） | **PowerPoint の中で直せる** |
| `<svg>` の数値グラフ（数が無い） | `charts/` `qc7/` の Excel で作って貼る | データを直せる |
| 写真・スクリーンショット | `<img>` のまま | 直せない（それでよい） |

**線は写す。数値は写さない。**

- 特性要因図の骨、系統図の接続、アローダイアグラムの矢線は、
  **線そのものが中身。**写せば編集できる図形になる。
  写さないと「文字が浮いているだけ」になる
- 棒グラフの高さ、折れ線の座標は**数値の見た目**でしかない。
  写しても**元の数字は戻せず、直せない絵**になる

写すのは `<line>` と `<polyline>`。`stroke`＝線色、`stroke-width`＝太さ、
`stroke-dasharray`＝破線、`marker-end`＝終端の矢印。

**座標の対応はこう決まる。**

| svg の書き方 | 倍率 |
|---|---|
| `viewBox` があり、CSS に `width`/`height` がある | **枠の寸法 ÷ viewBox** |
| `viewBox` が無い | **等倍。**svg の座標をそのまま px とみなす |
| 寸法が取れない | 等倍。**枠の寸法から倍率を作らない** |

**枠と `viewBox` が噛み合っていないと、線がスライドの外へ飛ぶ。**
変換は**外へ出た本数を数えて止める**ので、気づかずに進むことはない。

```
**svg の線がスライドの外へ出た（76本中 76本がスライドの外）。**
枠の left/top/width/height と viewBox が噛み合っていない。
```

#### 帯や箱の上に文字を載せるときは、同じ枠にする ★

**長方形と、その上の文字を別の枠にするなら、`left` と `width` をそろえる。**
幅が違うと、文字はその狭い枠の中で中央ぞろえされるので、
**長方形に対しては左右どちらかへ寄って見える。**

実績: 帯 1198.7px の上に本文の枠 954.7px を置き、**中心が 122px ずれていた。**
同じ型が1つの資料で 24 組あった。**HTML のプレビューでは気づきにくい。**

| やり方 | 可否 |
|---|---|
| 長方形と同じ `left`/`width` の枠に、中央ぞろえで書く | ⭕️ **これにする** |
| 長方形の中に文字を入れる（枠を分けない） | ⭕️ いちばん安全 |
| 幅の違う枠を載せて、中央ぞろえ | ❌ 中心がずれる |
| 幅の違う枠を載せて、**左ぞろえ** | 🔺 ずれて見えないが、中央に見せたい意図は消える |

**片側へ寄せたいバッジは別。**幅が長方形の6割に満たないものは、
意図した片寄せとみなす（変換側の検査もその線で拾う）。

#### 数値グラフは「数を書く」

**絵を写さない。数を渡す。** pptx のグラフは中にワークシートを持つので、
**受け取った側は PowerPoint の中で数字を直せる。**Excel を別に添えなくてよい。

**`<div>` を並べて棒に見せない。** ★
CSS の高さで棒を描くと、HTML のプレビューでは正しく見えるが、
**pptx にはただの塗り図形として入る。**中に数字が無いので、
受け取った側は PowerPoint でも Excel でも直せない。
実績: 実案件で、棒グラフが全部この形になっていた。**絵は正しいので気づけない。**
数値のグラフは、**必ず `data-chart` と `data-values` を書く。**

```html
<svg data-chart="column" data-series="不良件数"
     data-labels="ネジ締め忘れ,はんだ不良,部品欠品"
     data-values="62,18,11" style="left:40px;top:60px;width:560px;height:300px">
  <!-- 中の絵は HTML プレビュー用。pptx には写らない -->
</svg>
```

系列を増やすときは `data-values-2` `data-series-2` と続ける。

| `data-chart` | 種別 |
|---|---|
| `column` / `bar` | 縦棒 / 横棒 |
| `column-stacked` / `bar-stacked` / `-100` | 積み上げ / 100%積み上げ |
| `line` / `line-plain` | 折れ線（点あり / 点なし） |
| `pie` / `doughnut` | 円 / ドーナツ |
| `area` / `area-stacked` | 面 / 積み上げ面 |
| `radar` / `scatter` | レーダー / 散布図 |

**用途の名前（「パレート図」など）では分けない。型で決める。**
用途で分けると、案件が増えるたびに種別が増え続ける。

**第2軸は入れられない。** 累積線つきのパレート図のように、
軸が2つ要る図は `qc7/01_パレート図.xlsx` で作る。
`data-line` を書くと、その旨が変換時に出る。

```html
<!-- 数が書けないときは、名前だけ書いてテンプレートに送る -->
<svg data-figure="パレート図" ...>…</svg>

<!-- 作図は名前を書かなくても線が写る。書くと報告に出て分かりやすい -->
<svg data-figure="特性要因図" viewBox="0 0 800 400">
  <line x1="0" y1="200" x2="800" y2="200" stroke="#1F4E79" stroke-width="3"/>
</svg>
```

```
- **svg は変換しない**（パレート図）。HTML の図は**設計図**であって、pptx の図ではない。
  → `qc7/01_パレート図.xlsx`
```

`data-figure` が無ければ、`assets/templates/INDEX.md` で内容の性質から選ぶ
（`30_visual.md`）。**図を作ったら、元の Excel も一緒に渡す**（`<slider-deck>/references/50_build.md`）。

**表は自動でネイティブの表になる。** 列幅は `<colgroup>` に書けば、その比で移る。

```html
<table><colgroup><col style="width:600px"><col style="width:200px"></colgroup>
```

**書かないと均等割りになり、項目名の列と数値の列が同じ幅になって折り返す。**
罫線と塗りは PowerPoint の既定に従い、CSS で作った罫線の色や太さは写らない。
HTML で凝った表組みを作り込まない。

### 解釈する CSS は限られている

`html_abs.py` が見るのは、位置・大きさ・文字・塗り・枠線・余白だけ。
擬似クラス（`:first-child`）、メディアクエリ、`flex` の細かい配置、
`transform`、影、グラデーションは**見ない**。

**テンプレートの CSS をむやみに足さない。** 見た目が変わっても pptx に乗らない。

## 3-3. 直すときの決まり ★

| 決まり | なぜ |
|---|---|
| **本文の差し替えは `splice.py` を使う。自作しない** | 自作の関数は2段落・入れ子で崩れる（実績：リード帯の2段落目が消えた）。18枚入りの資料では `--slide N` で枚を指定する |
| **書き込みは中身ができてから** | 中身が固まる前に書くと、同じ枚を何度も書き直し、古い文言が残る |
| **置換で直したら、当たった件数を確かめる。0件なら止める** | HTML の空白（`&nbsp;`）や改行で当たらないことがある。**0件のまま「直した」と報告しない** |
| **数値は置換で変えない。その枚を作り直す** | 同じ数字が別の項目にも出る（`46_numbers.md`） |
| **直した後に台帳で照合する** | 使わない語・以前の値が **0件** になったことを `ledger_check.py` で確かめてから報告する |

## 4. HTML の書き方

1スライド = `<section class="slide" data-layout="...">`。

| data-layout | 使う場面 |
|---|---|
| `title` | 表紙。`<p class="subtitle">` を添える |
| `section` | 章の扉 |
| `message-body` | メッセージライン＋箇条書き |
| `message-visual` | メッセージライン＋図（`<img>`） |
| `table` | メッセージライン＋表（`<table>`） |
| `blank` | 何も枠を使わない |

省略すると中身から推測する。**明示した方が確実。**

```html
<section class="slide" data-layout="message-body">
  <h1>現状の課題</h1>
  <p class="message">不良の6割が3号機に集中している</p>
  <ul>
    <li>不良率2.4%（目標1.0%）
      <ul><li>1.4ポイントの超過</li></ul>
    </li>
  </ul>
  <p class="source">2026年1月〜6月、n=600</p>
  <aside class="notes">話す内容。スライドには出ない</aside>
</section>
```

文言の規約（体言止め・言い切り・句点なし・文字量）は `40_japanese.md` のまま。
**HTML でも同じ規約が効く。**

## 5. 効かないこと

**HTML の見た目と pptx の見た目は一致しない。** 何が反映され、何が反映されないかを
先に知っておく。

| HTML で書いたもの | pptx への反映 |
|---|---|
| `<h1>` `<p class="message">` `<ul>` `<table>` `<img>` の**中身** | **される** |
| `data-layout` | **される**（レイアウトの選択） |
| `<aside class="notes">` | される（スピーカーノート） |
| `style` / `class` による位置・色・大きさ | **されない。**テンプレートが決める |
| CSS で作った装飾（影・グラデーション・角丸） | **されない** |
| `<div>` の入れ子による独自レイアウト | **されない** |

**位置を CSS で調整しても無駄になる。** 位置は `data-layout` と
テンプレートのレイアウトが決める。収まらないなら
[文言を減らす](45_layout.md)か、スライドを分ける。

**ブラウザで見た目を詰め込みすぎない。** pptx にした時点で崩れる。
`make_html.py` が書き出す CSS はテンプレートの体裁を写した**目安**であり、
一致を保証しない。**最終確認は必ず pptx を画像にして行う。**

### 図をどう入れるか

| 図 | 入れ方 |
|---|---|
| 表 | `<table>`。**ネイティブの表になり、数字を後から直せる** |
| グラフ | `charts/` `qc7/` のテンプレートで作り、**画像でなく元ファイルも渡す** |
| 作図（特性要因図など） | `n7/` `qc7/` の pptx テンプレートのスライドを持ち込む |
| 写真・スクリーンショット | `<img src="figures/...">` |

**`<img>` で貼った図は画像のまま。**受け取った側が数字を直せない。
数字を含む図は `<table>` にするか、元ファイルを別添する（`<slider-deck>/references/50_build.md`）。
