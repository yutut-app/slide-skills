# 31_chart — グラフと図の作り方の既定

**図解の型を選んだ後**（`30_visual.md`）、実際に描くときに読む。
型が正しくても、ここを外すと「対応していない」「値がない」と必ず指摘が返る。

## 1. 2つの図を並べて対応を主張するなら、軸を共有する ★

**最も時間を溶かす。**同一案件で3回指摘された。

| 守ること | 理由 |
|---|---|
| **同じ軸・同じ目盛・同じ原点を共有させる** | 上下に並べた時点で、聞き手は「同じ物差し」と読む |
| **カテゴリ軸と連続軸を混ぜない** | 「3月末・4月末」のような区切りと、日付の連続した軸は別物 |
| **共有できないなら並べない** | 並べずに、片方の図の中に印として入れる |

**例。**棒グラフが月末の区切り（カテゴリ）、工程表が日付の連続軸だと、
**棒の3月末の下に工程表の4月が来る。**両方を同じ列（3月／4月／5月／6月）にそろえて初めて対応する。

**並べる前に、この2つを書き出す。**書けないなら軸が違う。

```
上の図: 軸=月（カテゴリ4列）/ 目盛=3月,4月,5月,6月 / 原点=左端の3月
下の図: 軸=月（カテゴリ4列）/ 目盛=3月,4月,5月,6月 / 原点=左端の3月
```

## 1-1. グラフには数を持たせる ★

**箱と線で描いただけの図は、後工程で Excel のグラフにできない。**
実績として、19枚・図186件すべてで数が読めず、Excel 化の経路が**丸ごと成立しなかった。**

| 持たせるもの | 書き方 |
|---|---|
| `data-chart` | グラフの型（`bar` / `line` / `pie` / `area` / `pareto`） |
| `data-values` | **数そのもの。**区切りはカンマ。桁区切りは使わない |
| `data-labels` | 軸の項目名。カンマ区切り |

```html
<div class="chart" data-chart="bar"
     data-labels="3月,4月,5月,6月" data-values="62,18,11,8">…見た目の箱…</div>
```

**見た目の箱は今のまま描いてよい。**数を属性として添える。
これが無いと、変換側は「数が読めない」として**対象0で異常終了する**（それが正しい動き）。

**表で足りるならグラフにしない。**表は後工程でそのまま表になる。

## 2. 棒グラフの既定

**目分量で置かない。**既定が無いと毎回ずれ、毎回指摘される。

| 項目 | 既定 |
|---|---|
| 棒の幅 | **列幅の 70〜80%**。これより細いと「離れすぎ」に見える |
| 棒の位置 | **列の中央**。区切り線を引くなら、棒はその線の中央に来る |
| 積み上げの段 | 下から大きい順。**段の中に値が入らないときは外に出す**（下記3） |
| 基準線 | **何を根拠にした線かを図中に書く**（目標値、前年、規格） |

**この数値はテンプレートと投影環境で変わる。**案件の `template-manifest.md` に
`bar-width-ratio` を持たせ、そちらを正とする。

## 3. 値が消えるのを許さない ★

**段の高さが文字の高さに足りないと、数字が黙って消える。**
実績として、7件の段が14.5pxしかなく、値が出ないまま人に見せた。

| 条件 | どうするか |
|---|---|
| 段・枠の高さ < 文字の高さ×1.1 | **枠の外（右または上）に引き出して置く** |
| 外にも置けない | **その図では値を出さず、表を併記する** |
| どちらもしない | **禁止。**消えたことに誰も気づかない |

`scripts/visual_check.py` が「枠に値が入らない」として落とす。

## 4. ラベルを重ねない、二重に出さない

| 守ること | 理由 |
|---|---|
| **ラベルは線・軸・他のラベルから 8px 以上離す** | 重なると、どちらも読めなくなる |
| **同じ値を1枚に2回出さない** | 右軸に 100% があるなら、折れ線の末端に 100% のラベルは要らない |
| 読めない大きさにしない | 下限は `template-manifest.md` の `min-font` |

## 5. 描いたら、判定表を出す ★

**図版の指摘は症状の言葉で来る**（「値がない」「対応していない」）。
どの観点を見たかが残っていないと、同じ往復を繰り返す。

**案件の `visual-review.md` に、図のある枚ごとに1行書く。既定は「未確認」。**

```markdown
| 枚 | 軸は何か | 目盛は共有か | 原点 | 単位 | ラベルは全部読めるか | 基準線の根拠 |
|---|---|---|---|---|---|---|
| 5 | 月（4列） | 下の図と共有 | 左端の3月 | 件 | 合 | 目標値 0.20 |
| 7 | 未確認 | 未確認 | 未確認 | 未確認 | 未確認 | 未確認 |
```

**「未確認」が1つでも残っていれば、`visual_check.py` が落とす。**
埋めずに人に見せない。

## 6. 検査

```bash
python3 scripts/visual_check.py work/*.html \
    --manifest <テンプレの manifest> --review work/visual-review.md
```

**絵を人に見せる前に通す。**上下端・文字サイズ・文字の重なり・枠に入らない値・
同じ数値の二重・判定表の未確認を見る。**指摘があれば異常終了する。**

**この検査の限界。**全枚に出る文字（透かし・ヘッダ）との重なりは「共通パーツ」として
まとめて要確認に出す。図の中のラベルの近接も要確認に落とす（目盛との近接は普通に起きる）。
**同じ数値の二重は、80px 以内に並んでいるときだけ見る。**離れた場所の同じ値は正常。

**実案件で19枚を通した結果は、指摘3件・要確認31件だった**（最初は40件以上の誤検出が出て、
検査の側を直した）。**誤検出が出たら資料を曲げず、検査を直す。**

**この検査が見ないもの。**軸が実際に共有されているか、基準線の根拠が妥当か、
図の型が内容に合っているか。**そこは1章と5章の表で人が見る。**
