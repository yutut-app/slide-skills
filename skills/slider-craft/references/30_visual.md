# 30_visual — 図解の型の選定

手順3で読む。**箇条書きを既定にしない。**
「箇条書きにするな」ではなく、**内容の性質から型を機械的に決める。**

## 選定の手順

1. そのスライドで伝えたい内容の**性質**を1つに定める
2. 下の対応表で型を引く
3. 引けないなら、[型が引けないとき](#型が引けないとき)へ

## 型が引けないとき

**そのスライドが不要な可能性が高い。** 順に疑う。

1. **メッセージラインが「図の説明」になっていないか。**
   「対策の検討結果」はメッセージではない。言い切りに直すと、型が決まることが多い
2. **1枚に2つのことを言おうとしていないか。** 分ければ両方とも型が決まる
3. **本当に文字だけでよい内容か。**
   結論スライド、章の扉、リスクの列挙は文字だけでよい。**無理に図を入れない**
4. **消せないか。** 前後のスライドに吸収できるなら消す

**「全スライドにビジュアルを入れる」は本スキルの方針ではない。**
公式 `pptx` スキルはそう指示するが、報告資料では意味の無い図が増えるだけ。

## 型を選んだ後の確認

| 確認 | 不合格のときの対処 |
|---|---|
| 必要な件数があるか（`assets/templates/INDEX.md` の必要件数） | **推測値で作らない。**件数不足を明記し、型を変えるか、図をやめる |
| 数値の出所が分かるか | 出所を注記に書く。分からないなら止まって聞く |
| 同じ型が3枚以上続いていないか | 型を選び直すか、統合する |
| 図の中の文字が上限内か（ラベル全角12字） | 番号を振り、凡例で説明する |

## 図の作り方の共通規約

- **強調は1つ。** 主張したい系列だけ濃紺、残りはグレー
- **凡例は、系列が1つなら消す。** 軸名かタイトルで足りる
- **縦軸は0から始める。** 始めない場合は軸か注記に明示する
- **3D・影・グラデーションを使わない。** 面積や長さの比較が狂う
- **赤は基準線・目標線・逸脱の指摘にだけ使う。** 装飾に使わない
- **図のタイトルは、図が何かを言う。** 主張はメッセージラインの役目

## テンプレートの使い方

1. `assets/templates/` から該当ファイルを作業ディレクトリにコピーする
2. サンプルデータを実データに差し替える
3. Excel は「使い方」欄、PowerPoint はスピーカーノートに注意書きがある。**読む**
4. **PowerPoint のノートは、埋め終わったら消す。** 資料に残さない
5. 見た目は手順5（`<slider-deck>/references/60_qa.md`）で必ず確認する

**テンプレートを手で改造しない。** 型そのものを変えたいなら
`scripts/gen_*.py` を直して再生成する。手で直すと次回に引き継がれない。
