# 80_audience — 先方の目で読む

**作り手は自分の資料を読めない。** 書いてある文字の裏に、自分の頭の中の説明が
勝手に補われるため、抜けに気づけない。

そこで、**資料を渡される側（先方）になりきって読み、その場で浮かぶ疑問を全部出す。**
これは褒める作業ではない。**落とす作業。**

## 1. いつやるか

| 時点 | 何を見るか | 効き方 |
|---|---|---|
| **手順2（骨子の承認前）** | メッセージラインの通し読みだけ | **最も効く。**構成の穴をここで潰せば手戻りが小さい |
| **手順5（完成後の検査）** | 全スライドの中身 | 抜けた根拠・答えられない質問が出る |

**骨子の段階を飛ばさない。** 作り込んでから構成の穴が出ると、作り直しになる。

### やり直すきっかけ ★

**「手順2と手順5で1回ずつ」では足りない。**
途中で中身が大きく変わったのに、通し読みをやり直さない事故が起きる。

**次のどれかが起きたら、手順4-1（通し読み）からやり直す。**

| きっかけ | なぜ |
|---|---|
| **枚数が2割以上変わった** | 話の流れが変わっている。前の通し読みは別の資料のもの |
| **メッセージラインを3枚以上書き換えた** | 同上 |
| **結論・提案が変わった** | 根拠の並びが結論を支えていない可能性がある |
| **相手・目的が変わった** | 役が変わる。3章からやり直す |
| **数値の前提が変わった** | 数値が連鎖する（`46_numbers.md`） |

**「直した箇所だけ見る」で済ませない。** 通し読みは並びを見る検査で、
1枚ずつの検査では代わりにならない。

**やり直した回数と、そのきっかけを報告に書く。**

## 2. 絶対の規則

**スライドに書いてあることだけで判断する。**

作った側は経緯を知っているので、書いていないことを頭で補ってしまう。
**先方はそれを持っていない。**補って読んだ時点で、この作業は無意味になる。

| 使ってよい | 使ってはいけない |
|---|---|
| スライド上の文字・図・数値 | 会話でのやり取り |
| 手順1で確定した相手の前提知識 | 手元のファイルや元データ |
| その立場の人なら当然知っていること | スピーカーノートの内容 |

**スピーカーノートを読まない。** 先方はノートを見ない。
「口頭で補える」は、資料が答えていないことの言い換えでしかない。

## 3. 役を確定する

`10_intent.md` で確定した相手から作る。**勝手に人物像を作らない。**

| 項目 | どこから取るか | 無いとき |
|---|---|---|
| 役職・立場 | 手順1の「誰に」 | 聞く |
| 何を判断するのか | 手順1の「取ってほしい行動」 | 聞く |
| 前提知識 | 手順1の相手の区分（現場／管理職／他部門／社外） | 聞く |
| **姿勢** | 賛成寄り／中立／懐疑的 | **中立として扱う** |
| **決裁権の有無** | 手順1 | 決裁権ありとして扱う |

**姿勢と決裁権で、出すべき疑問の厳しさが変わる。**

- 懐疑的 ＋ 決裁権あり → コスト・リスク・前例・代替案を最も厳しく突く
- 賛成寄り ＋ 決裁権なし → 「上に説明するとき何を聞かれるか」を代わりに突く

**相手が複数いるなら、最も厳しい人を基準にする。** 一番厳しい人が納得すれば全員通る。

## 4. 手順

```
先方の目で読む:
- [ ] 役を確定する（立場・判断すること・前提知識・姿勢・決裁権）
- [ ] 通し読み：メッセージラインだけを上から読む
- [ ] 「で、私は何をすればいいのか」に答えられるか
- [ ] 1枚ずつ、初見で浮かぶ疑問を書き出す
- [ ] 各疑問が資料内で答えられているか判定する
- [ ] 未回答の疑問を分類し、対処を決める
- [ ] **カンペがあるなら、同じ検査を台本にも掛ける**（4-1-2）
```

### 4-1. 通し読み

**メッセージラインだけを順に読む。** 図も本文も見ない。
話が通らないなら、そこが構成の穴。

続けて次の3つに答えられるか見る。答えられないものは**資料の欠陥**。

1. この人は私に何をしてほしいのか
2. なぜそれをすべきなのか
3. いつまでに、いくらかかるのか

### 4-1-2. カンペ（話す台本）にも掛ける ★

**スライドだけでなく、話す台本も受講者・聞き手の目で読む。**
台本はスライドより長く、飛びや断絶が隠れやすい。実績では初版に
**計算の飛び・用語の未定義・スライド間の断絶**があり、利用者に
「これを聞いて理解できるか」と問われて初めて見つかった。

| 見る点 | 典型 |
|---|---|
| 計算が飛んでいないか | 途中の数字を言わずに結論の数字だけ言う |
| 用語を定義してから使っているか | 初出の略語・社内用語をそのまま話す |
| 前の枚からつながっているか | 「次に」で急に別の話題に変わる |
| 口で言うと長すぎないか | 1枚あたり、目安の時間に収まるか |

**手順は4-1〜4-3と同じ。**台本を上から読み、初見で浮かぶ疑問を書き出す。

### 4-2. 1枚ずつ疑問を出す

各スライドを初見で見て、**頭に浮かぶ疑問をそのまま書く。**
遠慮しない。「聞くまでもない」と思ったものも書く。

疑問は次の3つに分類する。

| 分類 | 意味 | 対処 |
|---|---|---|
| **答えられる** | そのスライドか前のスライドに書いてある | 対処不要 |
| **後で答えられる** | 後のスライドか付録に書いてある | **順序が悪い可能性。**疑問が出る前に答えるべきか検討 |
| **答えられない** | 資料のどこにも無い | **欠陥。**下記で処理する |

### 4-3. 未回答の疑問を処理する

| 処理 | 選ぶ条件 |
|---|---|
| 本文に足す | 判断に必要。無いと決められない |
| 付録に足す | 聞かれたら出す。本文に入れると流れが濁る |
| 調べ直す | データが無い。**推測で埋めない** |
| 答えない、と決める | 今回の範囲外。**その旨を資料に書く**（「本件では扱わない」） |

**「口頭で補う」を選択肢にしない。** 資料は残り、口頭は残らない。
配布されて後から読まれたとき、その説明は付いていない。

## 5. 立場別の観点

**役に応じて、最初に出す疑問が違う。** 下から該当する列を使う。

### 決裁者（部長・役員・客先の決裁権者）

- いくらかかるのか。**その数字の根拠は**
- いつまでにやるのか。遅れたらどうなるのか
- 失敗したらどうなるのか。**やめる判断はいつできるのか**
- 他にどんな案があったのか。**なぜそれを落としたのか**
- **なぜ今なのか。**今やらないとどうなるのか
- 誰が責任を持つのか
- 前例はあるのか。他社・他ラインはどうしているのか

### 実務担当（現場・運用を引き受ける人）

- 誰がやるのか。**今の人員でできるのか**
- 今の仕事にどう影響するのか。何が増えるのか
- 手順は決まっているのか。教育は誰がやるのか
- うまくいかなかったとき、誰に言えばいいのか
- いつから始まるのか

### 技術者・専門家（品質保証・設計・監査）

- **その数字はどう取ったのか。**期間・件数・条件は
- 条件を変えても同じ結果になるのか
- 例外はないのか。**都合の悪いデータを外していないか**
- 因果と相関を取り違えていないか
- 規格・法令・社内基準に対してどうなのか

### 社外（客先・取引先）

- **こちらにどんな利益があるのか**
- 契約・費用負担はどうなるのか
- 他社と比べて何が違うのか
- そちらの都合ではないか
- 情報はどこまで開示されるのか

### 全立場に共通

- **この略語・専門用語は何か**（手順1の前提知識に照らす）
- この図は何を言いたいのか。**メッセージラインと合っているか**
- 「大幅に」「効果的に」は具体的にいくらか
- 前と比べているが、条件はそろっているのか

## 6. 出力の形

**感想を書かない。疑問と、その処理を書く。**

```markdown
## 先方の目で読んだ結果

**役**: 製造部長（決裁権あり・姿勢は中立）／判断すること: 治具交換頻度の変更を承認するか

### 通し読み
「で、私は何をすればいいのか」→ **答えられる**（1枚目に承認依頼と期限がある）
「なぜそれをすべきか」→ **答えられる**（2〜3枚目）
「いくらかかるか」→ **答えられない。**交換工数の増加分が資料に無い

### 1枚ずつ

| # | 先方が抱く疑問 | 資料内で答えられるか | 対処 |
|---|---|---|---|
| 2 | 6割が3号機というのは、いつからいつまでの話か | 答えられない | 本文の注記に期間と件数を足す |
| 3 | 摩耗が原因と言い切れるのか。他の要因は見たのか | 後で答えられる（付録2） | **順序が悪い。**本文に1行足して付録へ誘導 |
| 4 | 420万円の内訳は何か | 答えられない | 本文に足す。無いと決裁できない |
| 4 | 交換工数が増える分のコストは引いてあるか | 答えられない | **調べ直す。**推測で埋めない |
| 6 | 他ラインにも展開するのか | 答えられない | 「本件では扱わない」と明記する |

### 最も痛い指摘
**4枚目でコストの内訳が無いこと。**決裁者はここで止まる。
「420万円」だけでは、他の投資案件と比べられない。
```

**「最も痛い指摘」を必ず1つ挙げる。** 全部を並べると優先順位が消える。

## 7. やってはいけないこと

| してはいけない | なぜ |
|---|---|
| **褒める** | 作業の目的は穴を見つけること。良い点の指摘は resources を使わない |
| 忖度して指摘を弱める | 弱めた指摘は本番で先方から出る。**そのときは直せない** |
| 資料の外の知識で補って読む | 先方はそれを持っていない |
| スピーカーノートを読む | 先方は見ない |
| 疑問を出すだけで終わる | 処理（本文／付録／調べ直す／扱わないと明記）まで決める |
| 全部を「本文に足す」で処理する | 枚数が膨らみ、主張が薄まる |
| 人格を演じる（口調を作る） | 芝居は要らない。**必要なのは疑問の中身だけ** |
