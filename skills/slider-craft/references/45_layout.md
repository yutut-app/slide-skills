# 45_layout — レイアウトの検算

**手順3（1枚ずつ中身を決める）で、文言を書く前に読む。**

**生成してから直すのではなく、書く前に入る量を決める。**

## 1. 先に縦グリッドを固定する

**中身を書いてから場所を探さない。** 必ずどこかが重なる。

```bash
python3 <slider-deck>/scripts/fit_check.py budget --template <テンプレ>.pptx --layout 1
```

次が出る。**スライドサイズはテンプレートから取る。決め打ちしない。**

| 位置 | 意味 |
|---|---|
| title_top / title_bottom | タイトル |
| lead_top / lead_bottom | メッセージライン（リード帯） |
| body_top / body_bottom | 本文。**ここが使える高さのすべて** |
| footer_top | フッター |

グリッドは**スライドの高さに対する比率**で持つ。
4:3 でも 16:9 でも同じ割り付けになり、テンプレートが変わっても崩れない。

### 要素どうしの隙間は 0.15 インチ以上

配置前に、**各ブロックの下端を計算して次の要素との隙間を確かめる。**

```
次の要素の上端 − （前の要素の上端 ＋ 高さ） ≧ 0.15
```

**例外は1つ。** 見出しとその直下の説明文は1つのまとまりなので、
近づけてよい（近接の原則）。それ以外は空ける。

## 2. 入る文字数を計算する

日本語の見積もりは次の式で足りる。

```
全角1文字の幅 ≒ フォントpt ÷ 72 インチ
半角1文字の幅 ≒ その半分
1行の高さ     ≒ フォントpt × 1.25 ÷ 72 インチ

1行の最大文字数 = （枠幅 − 左右余白） ÷ 全角1文字の幅
最大行数        = 枠の高さ ÷ 1行の高さ
```

```bash
python3 <slider-deck>/scripts/fit_check.py budget --template <テンプレ>.pptx --box 9.0x3.2 --pt 16
```

**この上限を超える文言は書かない。** 書いてから縮めるのではなく、
上限を見てから文言を決める。

### 見積もりの限界

**目安であって保証ではない。** 書体によって1割程度ずれる。
プロポーショナル書体（游ゴシック、メイリオなど）では半角の幅が一定でない。

**最後は必ず画像にして目で見る**（`<slider-deck>/references/60_qa.md`）。計算だけで終わらせない。

## 3. 表の高さを計算する

```
表の高さ = ヘッダー高 ＋ 行高 × （行数 − 1）
ヘッダー高 = ヘッダーのpt × 1.25 ÷ 72 ＋ 上下余白 × 2
行高       = 本文のpt   × 1.25 ÷ 72 ＋ 上下余白 × 2
```

**行数を決める前に、本文領域の高さから入る行数を逆算する。**
表が body_bottom を越えるなら、行を減らすか、付録に回す。

セル内で折り返すと行高が倍になる。**セルの文字数は[2](#2-入る文字数を計算する)で
計算した上限内に収める**（`40_japanese.md` の全角15字は、この計算から出た目安）。

## 4. 入らないときの処理

**フォントを縮めて収めない。** 12pt 未満は会議室のスクリーンで読めない。

| 処理 | 選ぶ条件 |
|---|---|
| **内容を削る** | いちばん先に検討する。**言わなくても伝わることを消す** |
| 図に変える | 並列・比較・構造なら、文字より図の方が入る（`30_visual.md`） |
| スライドを分ける | 削れない情報量がある。連番のある構造なら[1項目1枚](20_story.md) |
| 付録に回す | 判断に不要だが、聞かれたら出す |

**この4つ以外を選ばない。** 特に「フォントを1pt下げる」は、
その場は収まっても次の修正でまた溢れる。

## 5. 作った後の検出

```bash
python3 <slider-deck>/scripts/fit_check.py check <deck>.pptx
```

検出するものと、その扱い。

| 種別 | 扱い | 直し方 |
|---|---|---|
| **重なり** | **不合格** | 位置を変える。どちらかを消す |
| **はみ出し** | **不合格** | グリッド内に戻す |
| **溢れ**（枠の行数を超える） | **不合格** | [4](#4-入らないときの処理)の4択 |
| 隙間不足 | 注意（設計の余地あり） | 見た目の好みで判断してよい |

**不合格はゼロになるまで直す。回数で打ち切らない。**
「修正3回まで」のような打ち切りは、見た目の好みのループには要るが、
**重なり・はみ出し・溢れには適用しない。**客観的な欠陥だから。

終了コードは、不合格があれば 1、無ければ 0。

### 検出できないもの

- 文字と図形の**視覚的な**近さ（機械では窮屈さが測れない）
- 色のコントラスト
- 図の中の要素どうしの重なり（グループの内側は見ていない）

**だから画像で見る工程を省けない。**
