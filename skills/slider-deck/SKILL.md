# HTML → PowerPoint

受け取った HTML を pptx にし、検査し、**ずれを HTML に差し戻す。**

**このスキルだけで完結する。** 資料を作るスキルが同じ機械に無くてよい。

**このスキルの価値は「pptx が出ること」ではなく「出てきた pptx が、
承認された HTML と同じ絵になっていること」にある。**

```
HTML（正本。作った側から受け取る）
  ↓ 変換          ← ここが本スキル
pptx（派生物）
  ↓ 検査          ← ここも本スキル
ずれ・溢れの指摘
  ↓ 差し戻し      ← 直すのは HTML
HTML
```

**pptx を手で直さない。** 次の変換で消えるうえ、同じ症状が次回も出る。
**図・グラフ・表だけが例外**（HTML に書けないので、最後に pptx 側で作る）。

### 役割 — 誰として、何を優先するか

| | |
|---|---|
| 誰として | 承認された絵を、提出できる形に落とす担当として |
| 最優先 | **HTML で承認された絵と、pptx の絵が一致すること** |
| **誰の側に立つか** | **HTML を承認した人の側。**変換が通ったことを喜ぶ側ではない |
| しないこと | 中身を書き換えない。pptx を手で直さない（**図を除く**）。資料を外に出さない |

**「誰の側に立つか」が、変換しきれないときの判断を決める。**
図や線が再現できないとき、**黙って近いもので埋めない。**
埋めれば見た目は通るが、承認された絵ではなくなる。
**何が再現できなかったかを出して、どうするかは利用者に決めてもらう。**

## 資料を外に出さない ★最初に読む

**扱うのは、まだ外に出ていない資料。** 提案前の提案書、社外秘の報告書、
利用者の組織のテンプレート。**一度外に出ると取り消せない。**

### 公開しない

**禁じるのは「他人が見られる状態にすること」。** 非公開のまま扱うことは禁じない。

| してはいけない | 何が起きるか |
|---|---|
| **公開する・リンクを共有する** | 誰でも開ける。**取り消せない** |
| **第三者が開ける状態にする**（共有設定、共有ドライブ、gist、pastebin） | 同上 |
| オンライン変換サービスに上げる | 中身を保持することがある |
| **資料やテンプレートを git に入れる** | private でも、組織の外に出たことになりうる。テンプレートは `.gitignore` で除外する |
| 本文や図表を外部サービスに送る | 数値・宛先がそのまま渡る |

**自分の判断では一切やらない。** 「共有リンクを出しましょうか」と**提案もしない。**
提案は実行への一歩で、断る手間を利用者に負わせる。

### 非公開のまま使うのはよい

| 手段 | 可否 |
|---|---|
| **Browser ペインに `file://` で開く** | **よい。**機械の外に出ない。**既定はこれ** |
| **利用者だけが開ける Artifact** | **よい。**ただし中身は claude.ai 上に載る（手元だけの状態ではなくなる） |
| ローカルに PNG / pptx を書く | **よい** |
| `SendUserFile` で利用者本人に渡す | **よい** |

**既存の非公開 Artifact を消す必要はない。** 消すかどうかは利用者が決める。
**こちらから削除を促さない。**

### 出してよいもの

| 手段 | 可否 |
|---|---|
| ローカルのファイルに書き出す（`deck/`、`work/`、`qa/`） | **よい。**これが既定 |
| 会話の中に文言・構成を書く | よい |

**「利用者に見せる」と「外部に載せる」を混同しない。**
前者はこの仕事そのもので、後者は禁止。

## 絶対の制約

**直すのは HTML。出力された pptx を手で直さない。**

**例外は1つ。図・グラフ・表を入れるときだけ**（後述）。
HTML に書けないものなので、pptx 側で作る。
**それ以外の直しを pptx でやらない。**次の変換で消える。

| 変える | 変えない |
|---|---|
| 変換のしかた（係数・座標の読み方） | **文章・数値** |
| 検査で見つけたずれを **HTML 側で** | **出力された pptx を手で**（図を除く） |
| **最後に図・グラフ・表を pptx 側で作る** | 図を入れた版を再変換すること |
| 出力ファイル名 | 元の HTML 以外の資産 |

**中身を作らない。** 構成・メッセージ・図解の選定・文章は**配布元の担当。**
**見つけたら直さずに報告する。**（`slider-craft` を持っているなら、そちらで直す）
**器を替えない。** 別テンプレートへの載せ替えは `slider-reskin` の役目。

### 段階の切り替えは、こちらで決めない

段階1（HTML でテキストと大枠を詰める）と段階2（pptx で見た目を詰める）の
**切り替えは利用者の宣言による。こちらから決めない。**

| | |
|---|---|
| 宣言があるまで | **その段階を回し続ける。**「そろそろ次では」と促さない |
| 回数・指摘の減り | **打ち切る理由にしない** |
| 前の段階に戻る | **戻ってよい。**ただし**何が崩れるかを先に一覧で出す** |

**自分で段階を進めない。** 受け取った側なら、引き継ぎメモの段階に従う。

## 公式 pptx スキルとの役割分担 ★最初に読む

公式 `pptx` スキル（`anthropic-skills:pptx`）には、性質の違う2つが同居している。
**技術は委譲し、思想は上書きする。**

| 層 | 中身 | 扱い |
|---|---|---|
| **技術** | pptxgenjs の落とし穴、テンプレートの unzip→XML差し替え、`validate.py` | **公式に委譲する。**再実装しない |
| **思想** | Design Ideas 節（派手なパレット、全スライドにビジュアル要素） | **使わない。**フォント・文字サイズ・配色は**資料テンプレートが決める** |

**公式スキルが単独で先に発火した場合は、そこで止めて本スキルの手順1に戻る。**
いきなり pptx を作り始めない。

## 進め方

```
作業の進捗:
- [ ] 0. 受け取りの確認（HTML 一式・テンプレート・道具）
- [ ] 1. 段階0（1枚だけ変換して、テンプレート自体のずれを潰す）
- [ ] 2. 変換
- [ ] 3. 検査（pptx の絵 ＋ 溢れ ＋ HTML の絵と並べる）
- [ ] 4. ずれを HTML に差し戻す
```

このチェックリストを回答に写し、進むたびに埋める。

### 0. 受け取りの確認

**何を受け取ったかを先に確かめる。** 推測で変換しない。

| 確かめること | 無いとどうなるか |
|---|---|
| HTML 一式（各スライドと `print.html`） | — |
| `images/` | ロゴ・図が出ない |
| **テンプレート一式（`template-manifest.md` を含む）** | px→pt の係数が読めず、スライド寸法が狂う。**無ければ作れる**（下記） |
| **引き継ぎメモ**（担当が分かれているとき） | どこまで進んだか、何が未決か、**今どの段階か**が渡らない |

### テンプレートが手元に無ければ、作る ★

**テンプレートは git に入らない。** 別の機械では手元に無いのがふつう。
**受け取った資料の HTML から作り直す。**

```bash
python3 scripts/gen_template.py <受け取った>/print.html -o assets/templates/deck/<名前>
```

資料の HTML は**テンプレートと同じ `<style>` を持っている**ので、
px→pt の係数・スライド寸法・共通パーツの座標・配色・文字サイズが取れる。

**使うたびに作り直す。** 手で写すと、配布元がテンプレートを直したときに
古いまま残る。**毎回 HTML から作れば、受け取ったものと必ず一致する。**

| | |
|---|---|
| 係数の出どころ | HTML の `<meta name="px-per-pt">`。無ければ `--px-per-pt` |
| **どちらも無いとき** | **作らない。**既定で作ると、狂った寸法を正しいものとして固定する |

**作ったら、変換して寸法を確かめる。**
出力の「スライドサイズ」が、元 PPTX と同じ pt になっていること。

**テンプレートは名前が同じでも中身が違うことがある。**始める前に突き合わせる。

```bash
python3 scripts/handoff.py <テンプレ> --fingerprint
```

**引き継ぎメモの値と違ったら、そのまま進めない。**どちらが新しいかを確かめる。

```bash
python3 scripts/qa_render.py --probe
```

**道具が無いなら、無いと報告する。** 「検査した」と書かない。

### 受け取るのは HTML 一式 ★

**変換する元は HTML。** md は**中身の写し**で、正本ではない。

| 渡されるもの | 役割 |
|---|---|
| **HTML 一式**（各スライドと `print.html`） | **正本。これを変換する** |
| テンプレート一式（`template-manifest.md`・`images/`） | 寸法・ロゴ。**無いと寸法が狂う** |
| 引き継ぎメモ | 段階・指紋・未決 |
| 内容の md（あれば） | **読む用。**検索や見直しに使う。**変換に使わない** |

**md と HTML が食い違っていたら、HTML が正しい。**
md は書き出した時点の写しで、後から HTML だけ直っていることがある。

#### 会話に貼られた HTML を受け取ったとき ★

**ファイルで渡らないことがある。**長すぎて送れない、共有の手段が無い、など。
そのときは**会話に貼られた中身をそのままファイルに書き出してから始める。**

```bash
# 貼られた中身を保存する。**ここから先は、いつもの手順と同じ**
cat > deck/deck.html <<'EOF'
（貼られた HTML をそのまま）
EOF
```

| やること | 理由 |
|---|---|
| **まずファイルに落とす** | 道具はファイルを受け取る。会話の中身は検査できない |
| **`.slide` の数を数える**（`pptx_diff_html.py` が出す） | 途中で切れて届くことがある。**枚数が合わなければ止める** |
| **テンプレート一式が別に要る** | 貼られるのは中身だけ。**寸法とロゴは付いてこない** |
| 係数を確かめる | `<meta name="px-per-pt">` が無ければ、手元のテンプレートから採る |

**切れたまま変換しない。**足りない枚数は、**足りないと報告する。**

### md しか無いときは、受け取っていないのと同じ ★

**md から HTML を組み立て直さない。**
一度その方式を検討し、**再現できないと分かった。**

| md に入らないもの | 結果 |
|---|---|
| 文字1つずつの座標 | 図の中の文字の位置が変わる |
| 線の始点・終点 | 作図（特性要因図・アローダイアグラム）が再現できない |
| 微調整した値 | 手で詰めた余白・行間が戻らない |

**HTML を送れないと言われたら、送る手段を探してもらう。**
共有フォルダ・USB・zip・分割送信。**HTML は数百KB で、テンプレートは 50KB 程度。**

**md だけで組み立てて「できました」と報告しない。**
中身は合っていても、絵が違うものになる。

### 図・表は、種類で扱いが分かれる ★

**HTML に入っているものを、そのまま写せるとは限らない。**
分かれ目は「**絵から元の情報が戻せるか**」。

| 種類 | どうするか | なぜ |
|---|---|---|
| **表** | **変換器がそのまま作る**（ネイティブの表） | 数字が残り、受け取った側が直せる |
| **作図**（特性要因図・系統図・アローダイアグラム） | **変換器が線を写す**（コネクタ） | 線を写せば編集できる図形になる |
| **数値グラフで、HTML に数が書いてある** | **変換器がそのまま作る**（ネイティブのグラフ） | **中にワークシートを持つ。**PowerPoint の中で数字を直せる |
| 数値グラフで、**絵としてだけ描いてある** | **作れない。**HTML に数を足してもらう | 絵からは元の数字が戻らない |

**手で作るのは、最後の手段。**

HTML にこう書いてあれば、**変換器がネイティブのグラフにする。手作業はいらない。**

```html
<svg data-chart="column" data-labels="A,B,C" data-values="62,18,11"
     data-series="不良件数"></svg>
```

対応する型は14種（棒・横棒・積み上げ・折れ線・円・ドーナツ・面・レーダー・散布）。

**数が書かれていない図に出会ったら、Excel で作る前に配布元へ戻す。**
`data-chart` と `data-values` を HTML に足してもらえば、次の変換から自動で入る。
**手で作ると、次に HTML が直ったときにもう一度手で作ることになる。**

どうしても手で作るなら、雛形は `assets/templates/charts/` `qc7/`、
型の選び方は `assets/templates/INDEX.md`。

```
グラフの合格条件:
- [ ] 数値が HTML の表・data 属性と一致しているか
- [ ] 軸・単位・凡例が HTML の記載と合っているか
- [ ] 主旨が、その枚のメッセージと合っているか
- [ ] **元の Excel も一緒に渡せるか。**受け取った側が数字を直せる
```

**絵柄は同じでなくてよい。「数値が違う」だけが不合格。**

**作図の線が1本も入っていなければ、変換の不具合を疑う。**
黙って消える型の事故が実際に起きた（`docs/feedback.md` の原因 C）。
**本数を数え、スライドの外に出ていないかを見る。**

### 図を入れた後は、pptx が成果物になる ★

**図は HTML には戻せない。** Excel のグラフも PowerPoint の図形も、
HTML には書けないため。

```
HTML が正本  →  変換して検査  →  **図を入れる**  →  ここから pptx が成果物
```

**図を入れたら、そのファイルを再変換しない。**上書きで図が消える。

**だから図は最後に入れる。**文言の直しが残っているうちは入れない。
文言を直す必要が出たら、**HTML を直して変換し直し、図を入れ直す。**

**どの版に図が入っているかを、引き継ぎメモに書く。**
書かないと、次に変換した人が図を消す。

### 1. 段階0 — 1枚だけ変換する

**20枚作ってから係数のずれが見つかると、20枚分の手戻りになる。**

```bash
python3 scripts/stage0.py <テンプレ>/001.html
```

HTML の絵・pptx の絵・検査が一度に出る。**両方の絵を並べて見る。**
**ここでずれを潰してから、残りを変換する。**

### 2. 変換

`references/50_build.md` を読んでから実行する。

```bash
python3 scripts/html2pptx.py <作業>/print.html -o deck/deck_rev<n>.pptx
```

**出力に出る「換算係数とその出所」を読む。**
テンプレートの `template-manifest.md` から取れていないときは、
`--px-per-pt` で明示する。**既定値で押し通さない。**

**枚数が合っているか数える。** 出力は実際のスライド数を報告する。

### 3. 検査 ★止まらないが、必ず行う

`references/60_qa.md` に従う。**3つとも回す。1つでも欠けたら「検査した」と書かない。**

```bash

python3 scripts/html_png.py <作業>/print.html -o qa_html
```

**画像を1枚ずつ実際に見る。** 生成できたことは、正しさの証拠にならない。
利用者に「確認してください」と丸投げしない。

**HTML の絵と pptx の絵を並べる。** ずれは片方だけでは出ない。
実績: リード帯の縦位置が HTML は上寄せ、pptx は中央だった。

**絵で違和感があるのに原因が分からないときは、中身を要約する。**

```bash
python3 scripts/probe_pptx.py deck/deck_rev<n>.pptx
```

書体・文字サイズ・枠の自動拡張・表の余白が1つの表で出る。
**unzip して XML を読まない。**毎回書き方が変わって、前回と比べられない。

**各ツールが出す `検査: ... 対象 n... 指摘 n件 前提: ...` の行を、報告にそのまま貼る。**
「確認しました」の代わりにならない。

**出力の末尾だけを読まない。** 不合格の一覧は途中にある。
実績: `tail` で切って「重なり・はみ出しゼロ」と誤報した。**全文を読む。**

**表は、機械の検査だけで済ませない。必ず画像で見る。** ★
PowerPoint は**行の高さを、中の文字に合わせて勝手に伸ばす。**
指定値どおりに置いたつもりでも、開くと数〜十数 px 育つことがある。
`fit_check.py` は指定値で計算しているので、**この育ちは出ない。**
表のあるスライドは、育った行が下の要素を押し出していないかを
`qa_render.py` の絵で確かめる。

## 承認ポイント — どこで止まるか

| 止める | 止めない |
|---|---|
| **段階の切り替え**（利用者の宣言による。こちらから打ち切らない） | 変換のやり直し |
| 元の HTML を上書きする書き込み | 新しい出力ファイルの生成 |
| 資料を外部に送る操作（**公開は禁止**） | 手順2〜4の往復 |
| **再現できない図があったとき、どう埋めるか** | 再現できた図の細部 |

**上記以外は聞かずに進める。** 判断したら理由を1行述べる。承認は待たない。

**止まるときは、その時点で未決のものを全部まとめて出す。**

## 自律判断の基準

### 聞かずに決める

- 出力ファイル名と版番号
- マニフェストから読めた px→pt 係数
- 検査で見つかった明らかな不具合の修正（HTML 側）
- 回帰見本を通すかどうか（**変換器を直したら必ず通す**）

### 必ず確認する

1. **px→pt 係数がマニフェストから読めないとき。**間違えると全項目がずれる
2. **図・線・グラフが再現できないとき。**近いもので埋めてよいかは利用者の判断
3. 検査の道具（Chrome / LibreOffice / 書体）が無いとき。**「検査していない」と明記する**
4. 段階1に戻るかどうか。**戻ると段階2で詰めたものが崩れる**ので、何が崩れるかを先に出す

### 聞き方の型

**全案に メリット・デメリット・コスト を揃え、推奨に理由を1行付ける。**
「何もしない」も1案に入れる。
値を確かめるときは、**間違えるとどうなるか**を添える。
