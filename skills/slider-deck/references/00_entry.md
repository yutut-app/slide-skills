# 00_entry — 入口の判定

**作業の最初に読む。**`scripts/entry_check.py` を通し、出てきた表を**最初の出力**にする。
表が出ていなければ、このスキルの手順に入っていない。

## 1. なぜ最初にやるか

実績として、HTML の正本も書式の登録も無い案件で、確かめずに進めた。
**使えないと分かったのは、利用者に聞かれた後だった。**
同じ案件で、必ず読む参照ファイルも読まず、スキルの検査も通していなかった。
**「必ず読む」と書くだけでは読まれない。**だから入口の表に、読む参照を出す。

## 2. 入口

| 入力 | 入口 | 正本 | 読む参照 |
|---|---|---|---|
| スライドの HTML がある | **(1) HTML から変換** | HTML | `05_receive.md`、`55_revise.md`、`60_qa.md` |
| HTML が無く、pptx がある | **(2) 既存 pptx を土台に、必要な箇所だけ直す** | **その pptx**（利用者の手直しを含む） | `55_revise.md`（**最初から差分修正モード**）、`60_qa.md`、`07_official.md` |
| 既存 pptx の**書式だけ**に合わせたい | slider-reskin | — | slider-reskin の入口 |
| 構成・文言を良くしたい | slider-craft | — | **この機械に無ければ、そう伝える** |
| どちらも無い | **作らない** | — | 何を受け取るべきかを伝える |

**入口(2)では、HTML が正本という前提を使わない。**
「pptx を手で直さない」「直すのは HTML」は入口(1)の決めごと。
入口(2)では pptx を直接直す。**ただし作り直さない**（利用者の手直しを消す）。

## 3. 確かめる項目

| 項目 | 無いとき |
|---|---|
| 入力（HTML / pptx） | 作らない |
| 登録済みのテンプレート | 入口(1)：HTML から作り直す（`05_receive.md`）。入口(2)：**土台の pptx が書式の元**なので要らない |
| 画像化の道具（LibreOffice・PowerPoint など） | **何で代わりに見るかを決める。**代わりが無ければ、見た目は検査していないと明記する |
| 隣のスキル（slider-craft 等） | 構成・文言の依頼に応えられないと、作業の前に伝える |
| 版の扱い | **聞く**（下記） |

### 入口(1)で受け取るもの

| 受け取るもの | 無いとどうなるか |
|---|---|
| HTML 一式（各スライドと `print.html`） | — |
| `images/` | 案件固有の図が出ない（ロゴは手元のテンプレから使う） |
| テンプレート一式（`template-manifest.md` を含む） | px→pt の係数が読めず寸法が狂う。**無ければ作れる**（`05_receive.md`） |
| 引き継ぎメモ（担当が分かれているとき） | どこまで進んだか、何が未決かが渡らない |

## 4. まとめて確認すること ★ここで1回だけ止まる

**1件ずつ聞かない。**表と一緒に、未決をまとめて出す。

1. **入口**はこれでよいか（書式だけ合わせたい／中身から作りたい、なら違う入口）
2. **版の扱い**：別名で出すか、**同じ版に上書きするか**。案件に Rev 等の運用があればそれに従う。
   上書きなら、上書きの前に利用者の手直しを差分で確かめて退避する（`55_revise.md`）
3. 構成・文言の直しが要るときの扱い（slider-craft が無い機械では、ここで応えられないと伝える）
4. 画像化の道具が無いときの代わり

**聞くときは、間違えたら何が起きるかを添える。**
版の扱いを誤ると、利用者が直した版を上書きして消す。

## 5. 公式 pptx スキルとの関係

**このスキルが主導し、公式は道具として使う。**公式が先に動いていても、この表から始め直す。
どの部分を使い、どこをテンプレート優先で上書きするかは `07_official.md`。
