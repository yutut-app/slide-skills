# 07_official — 公式 pptx スキルとの関係

**このスキルが主導し、公式は道具として使う。**公式が単独で主導すると、
書式・検査・版の扱いがこのスキルの意図とずれる。
（全体の CLAUDE.md にも、公式より先にこのスキルを読むと書いてある）

## 1. 技術と思想

公式 `pptx` スキル（`anthropic-skills:pptx`）には、性質の違う2つが同居している。
**技術は委譲し、思想は上書きする。**

| 層 | 中身 | 扱い |
|---|---|---|
| **技術** | pptxgenjs の落とし穴、テンプレートの unzip→XML差し替え、`validate.py` | **公式に委譲する。**再実装しない |
| **思想** | Design Ideas 節（派手なパレット、全スライドにビジュアル要素） | **使わない。**フォント・文字サイズ・配色は**資料テンプレートが決める** |

**このスキルが主導し、公式は道具として使う。**公式が先に動いていても、手順0（入口の判定）から始め直す。
いきなり pptx を作り始めない。

**公式の本文や手順をこのファイルに写さない。**公式は改訂されうるうえ、利用条件で複製を禁じている。
ここに書くのは「何を見て、どちらを優先するか」だけ。

## 2. 衝突しやすい記述と、どちらを取るか

公式の書式の助言は、**テンプレートの無い新規作成**を想定している。
こちらはテンプレートか既存の pptx が必ずあるので、多くはそのまま当てはめると逆に働く。
（2026-11 時点の公式を読んで拾った。公式が改訂されたら、この表を見直す）

| 公式の助言（要旨） | 取る方 | 理由・こうする |
|---|---|---|
| 全幅の帯・端の縦線・カードの片側の線は飾りなので付けない | **テンプレート** | テンプレートや既存の pptx に帯があるなら**消さない。**書式の一部で、消すと他の枚と揃わない。**新たに足さない**のは公式と同じ |
| 見出しの下に線を引かない | **テンプレート** | 同上。ただし**見出しが2行になると線の位置がずれる**のは公式の目視観点と同じで、こちらも見る |
| 文字の大きさの目安（見出し・本文・注記）と、本文の下限 | **テンプレート・元の pptx** | 既存を直すときは元の大きさに合わせる（公式も既存編集ではそう扱う）。入らないときは**文を削る**。大きさで逃がさない |
| 安全な英字書体の一覧、既定書体を避ける | **テンプレート** | 日本語の書体は一覧に無い。書体はテンプレートが決め、無い書体は `fit_check` の前提欄（`書体=不足`）で見る |
| 主題に合わせた大胆な配色、毎枚に絵、レイアウトを毎枚変える | **使わない** | 報告資料は**テンプレートのレイアウトに従い、揃えることを優先する。**文字と表だけの枚も可 |
| 本文を中央に寄せない・見出しの末尾に句点を付けない | 一致 | slider-craft の文体規約と同じ向き。そちらを正とする |
| 1枚1メッセージ、結論を先に、1枚あたりの話す時間 | **使わない（担当外）** | 中身は slider-craft、話す時間は slider-script の担当。ここで構成を変えない |
| 最初の描画で見つけた不具合を直したら止める | **こちら** | `fit_check` の重なり・溢れは**ゼロまで直す。回数で打ち切らない**（`60_qa.md`） |
| 画像にする手順（公式のラッパー） | **こちら** | `qa_render.py` を使う。日本語の文字化けを避けるため PNG に直接変換している |
| 記入例の残骸を英語の見本語で探す | **両方** | 公式の検索は英語の見本語向け。日本語の記入例は `60_qa.md` 2章で探す |
| 語や数字が2行に割れていないか見る | 一致 | 日本語では `jp_wrap_check.py`（行頭の読点・1文字の折り返し）で先に機械で出す |

**迷ったら「テンプレート・元の pptx・利用者の指示」が公式の一般論より先。**
一般論で直した結果、先方の書式から外れるのが最も高くつく。

## 3. 新規作成と既存編集の分かれ道

公式は「新規は生成スクリプト、既存は展開して XML を直す」で道を分けている。
こちらの入口に当てはめると次のとおり。

| こちらの入口 | 公式のどの道具を使うか | 使わないもの |
|---|---|---|
| 入口(1) HTML → pptx | 変換は `html2pptx.py`（こちら）。**ファイルの検査だけ**公式の `validate.py` | 公式の新規作成の手順（生成スクリプト・配色・書式の助言） |
| 入口(2) 既存の pptx を直す | **既存編集の道具を使う。**枚の複製・削除・並べ替え、不要な部品の掃除、文字の抜き出し、一覧画像、`validate.py --original` | 公式の書式の助言（2章の表で「テンプレート」とした行） |

入口(2) で守ること（公式の注意と、こちらの規約が重なるところ）。

- **枚の追加・削除・並べ替えを先に済ませてから、文字を直す。**後から複製すると、直した文字ごと複製される
- python-pptx で文字を入れるときは**段落ごと置き換えない。**書式が落ちる。走り（run）の文字だけを替える
- 上書き・削除の前後で `guard_edit.py` を通す（`55_revise.md` 0章）。**公式の道具には利用者の手直しを守る仕組みは無い**

## 4. validate.py の読み方

既存の pptx から作った版は、**元の pptx を `--original` に渡して回す。**
元から持っている誤りが自分の誤りに見えるのを防ぐため。

| 出た指摘 | 扱い |
|---|---|
| `--original` で消えた（元の pptx にもあった） | **直さない。**元の書式の一部。報告に「既存由来」と書く |
| 構造の指摘（関係・種類・グラフ）は `--original` でも消えない | **元の pptx だけに対しても回し、同じ指摘が出るか比べる。**同じなら既存由来、新たに出たものだけが自分の誤り |
| 新たに出た指摘 | **直す。**指摘に書いてある直し方に従う |

**「validate が通った」だけで「壊れていない」と書かない。**PowerPoint で開けない
グラフでも検査は通ることがある。画像にして見るのは省かない（`60_qa.md`）。

## 5. 公式が先に動いていたら

公式が先に発火して作業を始めていても、**そこで作ったものを正にしない。**
手順0（`entry_check.py` の判定表）から始め直し、公式の道具は上の表の範囲で使う。
すでに書き出した pptx があれば、`guard_edit.py check` で元の pptx と比べてから扱いを決める。
