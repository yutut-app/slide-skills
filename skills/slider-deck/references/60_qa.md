# 60_qa — 検査

slider-deck の手順2〜4で読む（作る側のスキルが自分で確かめるときも読む）。**必ず行う。飛ばさない。**

**利用者に「確認してください」と丸投げしない。** 自分で画像化して見る。
見ずに「できました」と言わない。

## 検査の5段

| 段 | 何を見るか | 道具 |
|---|---|---|
| 0. **レイアウト** | 重なり・はみ出し・溢れ | `fit_check.py check`（機械で出る） |
| 0-2. **日本語と画像** | 行頭の読点・1文字の折り返し・見出しの改行・画像の縦横比と解像度 | `jp_wrap_check.py`（機械で出る。折り返しは推定） |
| 1. 見た目 | はみ出し・重なり・改行崩れ・欠落 | LibreOffice で画像化して**自分の目で見る** |
| 2. 記入例の残骸 | テンプレートの見本が残っていないか | 出てきた pptx を読む |
| 3. ファイル | 壊れていないか | 公式 `pptx` スキルの `validate.py` |
| 4. **先方の目** | **判断できるか** | **配布元の担当。**気づいたら報告する |

## 1. 見た目の検査

### まず、使える手段を確認する

**環境によって画像化の方法が違う。** 無いものを前提にすると検査が飛ぶ。

```bash
python3 scripts/qa_render.py --probe
```

| 環境 | 使える手段 |
|---|---|
| macOS / Linux（LibreOffice あり） | `qa_render.py` がそのまま動く |
| **Windows（LibreOffice 無し・PowerPoint あり）** | **PowerPoint COM。**`pip install pywin32` のうえ `qa_render.py` が自動で使う |
| どちらも無い | **検査していないと明記して、利用者に目視を依頼する。黙って飛ばさない** |

`markitdown` / `soffice` / `pdftoppm` は**無い環境がある。**
手順書に書いてあるからといって、実行できるとは限らない。

### 画像化

```bash
python3 scripts/qa_render.py deck.pptx
```

スライド1枚につき `<案件>/out/latest/qa/deck-01.png` … が出る。xlsx も同じコマンドで扱える。

**PDF を経由しない。** LibreOffice の PDF 出力は、端末に無いフォントを
日本語グリフを持たないフォント（Noto Sans など）に置き換えて埋め込むため、
**日本語が文字化けする**（実際に発生した）。`qa_render.py` は PNG に直接変換し、
複数スライドは1枚ずつに分けてから変換する。

**LibreOffice が無い環境では、検査していないと明記して利用者に目視を依頼する。**
黙って飛ばさない。

### フォント置換に注意

**端末に游ゴシックが無い場合、LibreOffice は別のフォントで描く。**
字幅が変わるため、画像上の見え方は PowerPoint での実物と一致しない。

| 検査項目 | 置換されている端末での信頼度 |
|---|---|
| 図形の位置・重なり・線の突き抜け | **そのまま信用してよい** |
| 色・グラフの形・データラベル | **そのまま信用してよい** |
| 文字のはみ出し・折り返し位置 | **厳しめに見る。**余裕が1文字ぶんなら不合格にする |

端末にどの日本語フォントがあるかは次で確かめる。

```bash
system_profiler SPFontsDataType | grep -E "Full Name: (.*(游|Yu |ヒラギノ|Meiryo|BIZ))"
```

### 見る項目

**画像を1枚ずつ実際に見る。** ファイルが生成されたことは、正しさの証拠にならない。

```
見た目の検査:
- [ ] 文字が枠からはみ出していないか
- [ ] 図形どうしが重なっていないか
- [ ] 線が図形を突き抜けていないか
- [ ] 矢印の先が箱の中の文字に重なっていないか
- [ ] 改行の位置が意味の切れ目か（送り仮名の途中で切れていないか）
- [ ] 2行以上のテキストで、2行目だけ配置がずれていないか
- [ ] データラベルに系列名・カテゴリ名が混ざっていないか（値だけか）
- [ ] グラフが凡例や軸ラベルに潰されていないか
- [ ] 番号（結合点・スライド番号）が重複していないか
- [ ] **軸ラベル・目盛の数値が、グラフの線や棒に重なっていないか**
- [ ] **矢印の先が、指す箱や文字の位置とずれていないか**
- [ ] **凡例と数値ラベルが重なっていないか**（累積比率の「100%」と軸名など）
- [ ] **帯（月・期間など）の上の文字が、帯からはみ出したり重なったりしていないか**
- [ ] 影・3D・グラデーションが付いていないか
- [ ] 空白が画面の3割以上を占めていないか
- [ ] 印刷したとき1ページに収まるか（Excel は横向き・幅1ページ）
```

### 実際に起きた不具合と原因

**同じ原因が繰り返し出る。** 症状を見たら原因を先に疑う。

| 症状 | 原因 |
|---|---|
| 2行目だけ配置がずれる | 改行を1つの run に入れた。**段落に分ける** |
| 線が図形を突き抜ける | 接続点を固定値で置いた。**座標から逆算する** |
| 矢尻が箱の中の文字に重なる | 中心どうしを結んだ。**矩形の縁で止める** |
| 戻り線が別の箱を貫通する | 縦に降ろした。**着地点をずらして1本で結ぶ** |
| ラベルが「項目名: 系列名: 値」になる | `showVal` だけ立てた。**表示項目を全部明示する** |
| 図に影が付いて古く見える | オートシェイプ既定の `<p:style>`。**style 要素を外す** |
| グラフだけ印刷2ページ目に落ちる | 既定の縦向き。**横向き・幅1ページに設定する** |

## 1-2. レイアウトの機械検査

画像を見る前に、機械で出せるものは機械で出す。

```bash
python3 scripts/fit_check.py check deck.pptx
```

**重なり・はみ出し・溢れはゼロになるまで直す。回数で打ち切らない。**
見た目の好みの調整（隙間・配置のバランス）とは区別する。
**機械が拾うのは「文字どうし」と「文字と線」の重なりまで**（`線と文字` は注意欄に出る）。
**図形の中の細部（矢尻の向き・帯の端）は拾えない。**上の観点表で目で見る。
実績: 累積比率と100%、矢印のずれ、月の帯と文字、ラベルと線を、機械も目視も見落とした。

**枠の重なり＝見た目の衝突ではない。**全幅の枠と右上のボックスは
機械では重なるが、絵では衝突していないことがある。**画像で確かめてから直す。**

## 1-3. 日本語の行と画像の機械検査 ★

**fit_check は「入るか」しか見ない。** 入っていても、行頭に「、」が来る、「る」だけが
次の行に落ちる、見出しの1行目が改行で押し出される、という崩れは残る。
実績: 既存の pptx を直した案件で、この3つと画像の縦横比（約3%）・解像度の低下が
**fit_check も目視も通って先方に出た。**

```bash
python3 scripts/jp_wrap_check.py deck.pptx --before <元の>.pptx
```

| 区分 | 見るもの | どう扱うか |
|---|---|---|
| **指摘**（落とす） | 画像の縦横比が 1% を超えてずれる／元より解像度が下がった | 直す。枠の比を画像に合わせるか、切り取りで合わせる。**引き伸ばして合わせない** |
| 要確認 | 行頭の読点・かっこ／1文字だけの折り返し／見出しの改行 | **画像にした絵で確かめる。**折り返しは描画で決まるので、推定は外れうる |
| 要確認 | 解像度が 150dpi 未満 | 元の画像があるなら差し替える。無ければ報告する |
| **指摘** | 日本語の文字に日本語以外の校正言語 | 赤い波線が出る。差し戻し先が `pptx_edit.py lang` で直す |
| 要確認 | 校正言語が未指定 | 既定次第で波線が出る。PowerPoint で開いた絵で確かめる |
| 要確認 | 語の途中の切れ目（カタカナ・英数字・数字と単位・かっこの中）、かっこだけの行、人が入れた改行が語の途中 | 画像で確かめる。**直すのは文**（改行位置を人が入れたなら、人の意図を聞く） |
| 要確認 | ノートに内部メモの語・60字を超える行 | **中身は人が判断する。**pptx を渡すとノートも渡る。差し戻し先は `slider-script` |

**`--before` を渡さないと、解像度の低下は見ていない。**サマリ行の「比較」欄にそう出る。
`slider-pptx-craft` で作った pptx では、元の pptx（人の手直し後の最新版）を必ず渡す。

### 人が付けた書式が消えていないか

**前の版があるときは必ず `diff_slides.py --format` も回す。**「**強調が消えた**」「**改行 n→m**」が出たら、
修正案の表で承認された変更かを確かめる。承認されていなければ**指摘**（差し戻し先 `slider-pptx-craft`）。
文字の差分だけでは、消えた強調は出ない。

**直し方は文を変えること。**図形の幅や文字の大きさで逃がさない。
テンプレートの書式が崩れ、別の枚と揃わなくなる。

### 見出しと中身の整合は、報告だけにする

見出しが言っていることと、中身の図や表がずれていないかは**機械では出せない。**
画像を見るときに読み、ずれていたら**直さずに報告する**。中身は slider-html-craft の担当で、
こちらで書き換えると、利用者が承認した文と食い違う。

### 道具が無い環境では

| 無いもの | 代わりにやること | 報告に書くこと |
|---|---|---|
| LibreOffice・PowerPoint（画像にできない） | `jp_wrap_check` と `fit_check` だけ回す | **「見た目は未検査。推定の要確認 n 件を目で見ていない」** |
| 元の pptx（`--before`） | 縦横比と dpi だけ見る | **「解像度の低下は未検査」** |

**未検査を「問題なし」と書かない。**見ていないことは、見ていないと書く。

## 2. 記入例の残骸を探す

**テンプレートの記入例をそのまま提出する事故が最も多い。**
これは**出てきた pptx を読むだけで分かる**ので、ここで見る。

```bash
# 記入例の残骸を探す
python3 -c "
import sys, glob
from pptx import Presentation
NG = ['カード', '要因1', '要因2', '1次手段', '2次手段', '対策案A', 'グループ見出し',
      '中骨を記入', '評価軸1', '代替手段1', '具体策（誰が', '作業A', '○日', '対象A']
for f in sys.argv[1:]:
    for i, s in enumerate(Presentation(f).slides, 1):
        for sh in s.shapes:
            if sh.has_text_frame:
                for w in NG:
                    if w in sh.text_frame.text:
                        print(f'{f} スライド{i}: 記入例が残っている → {w}')
" deck/*.pptx
```

## 2-2. ここで見ないもの ★

**文章の質・数値の検算・先方の目は、配布元の担当。**
このスキルは**変換と見た目**を見る。

| 見ないもの | どうするか |
|---|---|
| 文体・禁止語・文字量 | **直さずに報告する** |
| 数値の検算（縦計・率・層別の合計） | 同上 |
| 先方が判断できるか | 同上 |

**気づいたことは黙って直さない。** 文言を変えると、
配布元の版と食い違い、どちらが新しいか分からなくなる。
**報告に書いて返す。**

資料を作るスキルが同じ機械にあるなら、そちらの規約に従って直してよい。
**無いなら報告まで。**

## 3. ファイルの検査

公式 `pptx` スキルの `validate.py` を実行する。**本スキルで再実装しない。**

```bash
python scripts/office/validate.py deck.pptx --original template.pptx
```

`--original` には、入口(1) ならテンプレート、**入口(2) なら土台にした元の pptx** を渡す。
付けないと、元から持っている誤りが自分の不具合として出る。
**出た指摘の読み方（既存由来かどうかの見分け）は `07_official.md` 4章。**ここには書かない。

## 4. 先方の目の検査

**配布元の担当**（2-2）。気づいた疑問は**報告に書いて返す。**
**「口頭で補う」で処理しない。** 資料は残り、口頭は残らない。

## 「検査した」の証拠は、サマリ行を貼ること ★

**「指摘ゼロ」と「何も見ていない」は、区別できなければ同じ。**
同じ原因で9回失敗している（`docs/feedback.md` の原因 C）。

検査の道具は、最後に1行出す。**報告にはその行をそのまま貼る。**

```
検査: fit_check  対象 33図形  指摘 2件  前提: スライド=5枚, 行間=図形に書かれた値, 書体=不足(<書体名>)
```

| 終了コード | 意味 | すること |
|---|---|---|
| 0 | 見たうえで、不合格なし | 次へ |
| 1 | 不合格あり | 直す |
| **2** | **対象が0。何も見ていない** | **「問題なし」と報告しない。**入力を確かめる |

**前提の欄を読む。** `書体=不足(…)` と出たら、折り返し位置は当てにならない。
その状態で「確認しました」と言わない。**何を見ていないかを報告に書く。**

**「確認しました」はサマリ行の代わりにならない。**
件数と前提が無い報告は、検査したことの証明になっていない。

## 検査を緩めたら、回帰用の入力を通す

**誤検出を消す改訂は、本物まで消す恐れがある。**
`scripts/regress/` に、過去に壊れた場所の入力が置いてある。

```bash
python3 skills/slider-html-reskin/scripts/html2pptx.py scripts/regress/01_overlap_and_spill.html -o /tmp/r1.pptx --keep-coords --force
python3 scripts/fit_check.py check /tmp/r1.pptx   # 重なり1件・溢れ1件が出るべき
```

**出るべきものが出なくなったら、その改訂が検査を盲目にしている。**
