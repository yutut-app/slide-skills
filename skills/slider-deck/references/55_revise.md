# 55_revise — 再生成と差分修正の切り替え

**手順6（手直し）で読む。**

資料は10回以上直す。**直し方には2つのモードがあり、切り替えを誤ると
利用者の編集を消す。**

## 1. 2つのモード

| モード | いつ | やり方 |
|---|---|---|
| **再生成** | 利用者がまだ手で編集していない | 生成スクリプトか `deck.yaml` を直して、全部作り直す |
| **差分修正** | **利用者が手で編集したファイルを受け取った後** | 該当スライドだけを直す。**作り直さない** |

**生成スクリプトを残す。** 何度も直すことに耐えられるのは、
作り直せる状態を保っているため。1回きりの手作業で作ると、
5回目の修正で破綻する。

---

## 2. 切り替えの判定

**一度でも利用者が編集したら、以後は永久に差分修正モード。**戻さない。

| 状況 | モード |
|---|---|
| 自分が作ったファイルを、自分で直す | 再生成 |
| **利用者から編集済みのファイルを受け取った** | **差分修正。以後ずっと** |
| 利用者が「作り直していい」と明言した | 再生成に戻してよい |
| 編集されたか分からない | **差分修正**（安全側に倒す） |

### 編集されたかを確かめる

受け取ったファイルと、自分が最後に出力したものを比べる。

```bash
python3 scripts/diff_slides.py <自分が出したもの>.pptx <受け取ったもの>.pptx
```

**1枚でも変わっていれば、利用者が編集している。** 差分修正モードに入る。

手順1で「納品後に利用者自身が編集するか」を確認してあれば、
最初から差分修正モードで設計できる（**配布元の規約**（10_intent.md））。

## 3. 絶対にやらないこと

| してはいけない | 何が起きるか |
|---|---|
| **利用者のファイルを上書きする** | 手で入れた修正が消える。**元に戻せない** |
| 編集済みファイルを作り直す | 同上 |
| 「たぶん編集していない」で再生成する | 同上。**分からないときは差分修正** |
| 直したスライド番号を報告しない | 意図しない箇所を触っていないことを示せない |

### 歯止めは機械で持つ

**規約だけでは守られない。** 実際に、この規約を書いた上で利用者の編集済み
ファイルを上書きし、復旧できなくした。ゴミ箱にもスナップショットにも残らず、
git の追跡対象外だった。

`html2pptx.py` は、出力先に既存ファイルがあれば `--force` なしでは書かない。

```
既にある: deck/xxx.pptx
**上書きしない。** 利用者が手で直したものかもしれない。
  別名で出す: -o deck/xxx_20260914-1649.pptx
  意図して置き換えるなら --force
```

**`--force` は、そのファイルが自分の生成物だと確かめてから使う。**
確かめる手段は `diff_slides.py`。自分が最後に出したものと比べ、
1枚でも変わっていれば利用者が編集している。

**生成物と受け取ったものは、名前で区別できるようにする。**
自分の出力には `_generated` のような印を付け、素の名前を空けておくと、
利用者がそこへ置いたものと取り違えない。

### 出力は必ず別名にする

```
受け取ったもの:  提案書_20260914.pptx        ← 触らない
出すもの:        提案書_20260914_rev2.pptx   ← 新しく作る
```

利用者が見比べて、どちらを採るか決められるようにする。
**上書きは、利用者がそう言ったときだけ。**

## 3-2. 調べたことと、こちらの案を分けて書く ★

**報告の中で混ぜない。** 実際に「これは調べた結果ですか」と問われ、
**一部にしか出典が無いことを認めた。**

**案を1つ出すたびに、どこから来たかを書く。**

```
| # | 案 | 出どころ |
|---|---|---|
| 1 | <案> | **調べた**（<発行元・年>） |
| 2 | <案> | **測った**（<何を何件>） |
| 3 | <案> | **こちらの案。**根拠は無い |
```

| 出どころ | 意味 |
|---|---|
| **調べた** | 出典が言える。**出典を書く** |
| **測った** | この資料・この pptx から数えた。**数と取り方を書く** |
| **こちらの案** | **根拠が無い。**そう書く。読み手が採否を決められる |

**「調べた」と書けるのは、実際に調べたときだけ。**
記憶から書いたなら「こちらの案」。**曖昧にしない。**

**全部が「こちらの案」でもよい。** 悪いのは、案なのに調べた結果に見えること。

## 4. 差分の報告

**「3枚目を直しました」と言うだけでは、他を触っていない証明にならない。**
毎回、機械的に差分を出して報告に貼る。

```bash
python3 scripts/diff_slides.py <前>.pptx <後>.pptx
```

### 報告の形

```markdown
## 手直しの結果

直したこと: 4枚目のコスト内訳を追加

| スライド | 変化 | 内容 |
|---|---|---|
| 4 | 文字が変わった | 追加: 治具代 180万円 / 工数 240万円 |

変わっていないスライド: 1, 2, 3, 5, 6

**意図した4枚目以外は触っていない。**
```

**変わっていないスライドの番号も出す。** そこまで書いて初めて証明になる。

意図しないスライドが一覧に出たら、**報告する前に原因を調べる。**
「たぶん再生成のせい」で済ませない。
