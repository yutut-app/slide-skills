# 50_build — 出力（deck.yaml → プレビュー → pptx）

手順4で読む。

## 0. 生成経路を先に決める

**手元にあるものが何かで経路が変わる。** 決めずに始めると、
途中で「このテンプレートは使えない」となって全部やり直しになる。

| 手元にあるもの | 経路 |
|---|---|
| **.pptx / .potx のテンプレート** | **テンプレート直接ルート**（下記）。最も多い |
| **HTML（自分で起こす／受け取る）** | **HTML を編集対象にする**（**配布元の規約**（<slider-craft>/references/48_html.md））。テンプレートは別に要る |
| 何も無い | 汎用テンプレートを使う（**配布元の道具**（gen_deck_templates.py）） |

**社内にあるのはたいてい .pptx。** HTML 前提で組むと、
テンプレートを渡された時点で経路が無くなる。
逆に、**pptx 前提で組むと HTML から始まる仕事で着手できなくなる。**両方持つ。

### テンプレート直接ルートの2手

| 手 | やり方 | 選ぶ条件 |
|---|---|---|
| **A. 既存スライドを複製して中身を差し替える** | テンプレートに見本スライドがある場合、それを複製して文字と図を入れ替える | **見本が実在する。**最も崩れにくい |
| **B. slideLayout からスライドを起こす** | `add_slide(layout)` でプレースホルダに流し込む | 見本が無い。レイアウトだけある |

**A を優先する。** 見本には、レイアウトに書かれていない体裁
（罫線・ロゴ位置・微妙な余白）が入っていることが多い。

### スライドサイズはテンプレートに従う

**16:9（13.333×7.5）に決め打ちしない。**
テンプレートが 4:3（10.833×7.5）なら 4:3 のまま作る。
直すとブランドが崩れ、先方のフォーマット違反になる。

```bash
python3 scripts/fit_check.py budget --template <テンプレ>.pptx
```

文字数の上限も、このサイズから計算し直す（**配布元の規約**（<slider-craft>/references/45_layout.md））。
****配布元の規約**（<slider-craft>/references/40_japanese.md） の文字数は 16:9 での目安であって、絶対値ではない。**

### HTML を編集対象にするかどうか

**HTML は使い捨てのプレビューではない。編集対象として使える。**
その場合の手順は **配布元の規約**（<slider-craft>/references/48_html.md）。**要るのはテンプレートであって、元の pptx ではない。**

| HTML を編集対象にする | `deck.yaml` を正にする |
|---|---|
| **ブラウザで見ながら直したい** | 生成を自動化したい |
| **第三者から HTML を受け取った** | 中身がデータから決まる |
| 人が何度も手を入れる | 機械的に組み直す |

**どちらでも、pptx は派生物。**手で直さない。

画像化については経路に関わらず同じ。**数字を含む図を `<img>` で貼らない。**
表は `<table>`（ネイティブの表になる）、グラフは元ファイルも渡す。
受け取った側が数字を直せなくなる。
手順1で「納品後に利用者自身が編集するか」を確認してあるはず（**配布元の規約**（<slider-craft>/references/10_intent.md））。

## 原則：`deck.yaml` を唯一の正とする

**HTML プレビューと pptx を別々に手で書かない。必ずずれる。**
両方を `deck.yaml` から作る。修正は `deck.yaml` に対して行う。

```
deck.yaml  ──┬──► preview.html （ブラウザで見る。速い）
             └──► deck.pptx    （最終成果物）
```

**出力された pptx を手で直さない。** 再生成で消えるうえ、同じ不具合が次回も出る。
直すのは `deck.yaml` か生成スクリプト。

## 実装の状況

| 経路 | 状態 |
|---|---|
| `deck.yaml` の書式 | **確定**（下記） |
| `deck.yaml` → pptx | **公式 `pptx` スキルに委譲する**（下記の手順） |
| HTML → pptx | **実装済み**（`scripts/html2pptx.py`） |
| テンプレート → 編集用 HTML | **実装済み**（**配布元の道具**（make_html.py）） |

プレビューが無い間は、pptx を作ってから `60_qa.md` の手順で画像化して見る。
LibreOffice があるので、往復は1分程度で回る。

## deck.yaml の書式

`assets/deck.yaml.template` をコピーして使う。

```yaml
meta:
  title: 3号機 治具交換頻度の変更について
  audience: 製造部長、品質保証課長
  action: 治具交換頻度の変更（年2回→月1回）を承認する
  phase: 意思決定依頼
  template: ../../assets/templates/deck/houkoku.pptx   # 無ければ null
  output: deck/2026-09-08_治具交換.pptx

slides:
  - no: 1
    layout: title            # title / message-body / message-visual / table / section / appendix
    heading: 結論            # 体言止め
    message: 治具交換を月1回に変更したい   # 言い切り・全角40字以内・句点なし
    body:
      type: text             # text / bullets / table / image / chart
      items:
        - 判断の期限は9月20日
    notes: |
      話す内容はここに書く。敬体でよい。
      スライドには載せない。

  - no: 2
    layout: message-visual
    heading: 現状
    message: 不良の6割が3号機に集中している
    body:
      type: image
      source: assets/templates/qc7/01_パレート図.xlsx
      note: 2026年1月〜6月、n=600
    notes: |
      パレート図の上位3項目で78%を占める。
```

### フィールドの規則

| フィールド | 規則 |
|---|---|
| `heading` | 体言止め。全角20字以内 |
| `message` | 言い切り。全角40字以内。句点なし。**数値を入れる** |
| `body.type` | **配布元の規約**（<slider-craft>/references/30_visual.md） の対応表で決めた型に対応させる |
| `body.items` | 6行以内、1行全角30字以内 |
| `notes` | 敬体でよい。**ここに書いた内容はスライドに出さない** |
| `source` | 図を作ったファイルへのパス。**出所を追えるようにする** |

**`message` が空のスライドを作らない。** 言うことが無いスライドは消す。

## pptx の作り方

### テンプレートがある場合

**公式 `pptx` スキルの「Editing existing decks and templates」の手順に従う。**
本スキルで再実装しない。要点だけ再掲する。

1. `python scripts/thumbnail.py template.pptx template-thumbs` でレイアウト一覧を作る
   （第2引数を必ず渡す。既定名だと他のデッキの一覧を上書きする）
2. `assets/template-map.md` に、どのレイアウトを `layout` のどれに使うかを書く
3. unzip → `ppt/slides/slideN.xml` を差し替え → zip
4. `python scripts/office/validate.py out.pptx --original template.pptx`

**テンプレートのフォント・配色・余白を上書きしない。** テンプレート準拠が最優先。

### テンプレートが無い場合

pptxgenjs で作る。**公式スキルの gotcha 一覧を読んでから書く**
（hex に `#` を付けない、`pres.layout` を先に設定する、など）。

配色は本スキルの規約に従う。**公式の Design Ideas 節のパレットは使わない。**

```javascript
const NAVY = "1F4E79";   // 主役
const BLUE = "4472C4";   // 副役
const GRAY = "808080";   // 比較対象・主張しない系列
const ACCENT = "C00000"; // 基準線・目標線・逸脱の指摘のみ
```

- スライドサイズは `LAYOUT_WIDE`（13.3 × 7.5インチ）
- フォントは **配布元の規約**（<slider-craft>/references/40_japanese.md） の表に従う
- **改行は段落として入れる。** 1つの run に `\n` を入れると2行目の配置がずれる
- **書体は `latin` だけでなく `ea` にも書く。** python-pptx の `font.name` は
  `<a:latin>` しか書かない。テーマの `ea` が空だと**日本語は script 別フォント
  （既定はＭＳ Ｐゴシック）に落ち、指定した書体が効かない**。実際にそうなっていた
- **Excel のグラフの書体は、保存後に `<c:txPr>` を入れて指定する。**
  openpyxl の `ChartBase` に `txPr` は無く（`ChartSpace` 側の要素）、代入しても
  黙って無視される。**表はテンプレートの書体、グラフだけ別**になる
- **XML を後から触るときは、接頭辞の有無を実測する。** openpyxl は既定名前空間で
  書くので閉じタグは `</chart>`、PowerPoint 由来なら `</c:chart>`。
  決め打ちすると何も起きずに通過する
- スピーカーノートは `slide.addNotes("...")`。スライド上のテキストボックスに書かない

## 図の貼り方

| 図の作り方 | 貼り方 |
|---|---|
| Excel テンプレートで作ったグラフ | **画像として貼らない。**pptx のネイティブグラフとして作り直すか、Excel を別添にする |
| PowerPoint テンプレートで作った図 | スライドをコピーして持ち込む。図形のまま保つ |
| 外部の画像 | 出所を注記に書く |

**図を画像で貼ると、後から数値を直せなくなる。**
やむを得ず画像にする場合は、元ファイルへのパスを `source` に必ず残す。

## 手直しのモード

**利用者が手で編集したファイルを受け取ったら、二度と再生成しない。**
以後は該当スライドだけを差分修正する。詳細は `55_revise.md`。

**利用者のファイルを上書きしない。** 必ず別名で保存する。

## 出力先

```
<作業ディレクトリ>/
├── deck.yaml              中間成果物。これが正
├── build_deck.py          生成スクリプト。**消さない**（再生成できる状態を保つ）
├── deck/                  出力先。**単数形で統一する**
│   ├── 2026-09-14_<件名>.pptx
│   ├── 2026-09-14_<件名>_rev2.pptx   手直し版は別名
│   └── figures/           図の元ファイル（xlsx・pptx）
└── qa/                    検査で作った画像
```

ファイル名に日付を入れる。版が増えたとき、どれが最新か分からなくなる。

**ディレクトリ名は単数・複数を混ぜない。** `deck/` と書いたら全部 `deck/`。
表記がぶれると、別の場所を探して「生成されていない」と誤認する。

**手順書に書いたパスは、実行前に実在を確かめる。**
スキルの導入形態（プラグイン／`~/.claude/skills` 配下／リポジトリ直下）で
実際のパスが変わる。**書いてあるパスを信じて案内しない。**

```bash
ls <案内しようとしているパス> || echo "無い。実際の場所を探す"
```
