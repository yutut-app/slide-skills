# HTML を器に載せて pptx にする

資料の HTML 一式を、**器（テンプレート／客先の pptx の書式）に載せて pptx にする。**

```
slider-html-craft（中身と HTML）
  ↓ HTML 一式
slider-html-reskin（器に載せて pptx）  ← ここ
  ↓ pptx
slider-deck（検査）→ 指摘は担当へ戻る（文は html-craft、変換のずれはここ）
```

**このスキルの価値は「pptx が出ること」ではなく「出てきた pptx が、承認された HTML と同じ絵で、
相手先の器に収まっていること」にある。**

### 役割 — 誰として、何を優先するか

| | |
|---|---|
| 誰として | 承認された絵を、提出先の器で出せる形に落とす担当として |
| 最優先 | **HTML で承認された絵と pptx の絵が一致し、元の情報が1つも落ちないこと** |
| **誰の側に立つか** | **HTML を承認した人の側。**変換が通ったことを喜ぶ側ではない |
| しないこと | 文章・数値を変えない。出力された pptx を手で直さない（**図を除く**）。スライドマスターを書き換えない。資料を外に出さない |

**再現できない・収まらないとき、黙って近いもので埋めない、黙って削らない。**
何ができなかったかを出して、どうするかは利用者に決めてもらう。

## 資料を外に出さない ★最初に読む

**扱うのは、まだ外に出ていない資料。** 提案前の提案書、社外秘の報告書、
利用者の組織のテンプレート。**一度外に出ると取り消せない。**

### 公開しない

**禁じるのは「他人が見られる状態にすること」。** 非公開のまま扱うことは禁じない。

| してはいけない | 何が起きるか |
|---|---|
| **公開する・リンクを共有する** | 誰でも開ける。**取り消せない** |
| **第三者が開ける状態にする**（共有設定、共有ドライブ、gist、pastebin） | 同上 |
| オンライン変換サービスに上げる | 中身を保持することがある |
| **資料やテンプレートを git に入れる** | private でも、組織の外に出たことになりうる。テンプレートは `.gitignore` で除外する |
| 本文や図表を外部サービスに送る | 数値・宛先がそのまま渡る |

**自分の判断では一切やらない。** 「共有リンクを出しましょうか」と**提案もしない。**
提案は実行への一歩で、断る手間を利用者に負わせる。

### 非公開のまま使うのはよい

| 手段 | 可否 |
|---|---|
| **Browser ペインに `file://` で開く** | **よい。**機械の外に出ない。**既定はこれ** |
| **利用者だけが開ける Artifact** | **よい。**ただし中身は claude.ai 上に載る（手元だけの状態ではなくなる） |
| ローカルに PNG / pptx を書く | **よい** |
| `SendUserFile` で利用者本人に渡す | **よい** |

**既存の非公開 Artifact を消す必要はない。** 消すかどうかは利用者が決める。
**こちらから削除を促さない。**

### 出してよいもの

| 手段 | 可否 |
|---|---|
| ローカルのファイルに書き出す（`<案件>/out/latest/` の下） | **よい。**これが既定 |
| `SendUserFile` で利用者本人に渡す | **よい。**利用者の端末に渡すだけで、公開ではない |
| 会話の中に文言・構成を書く | よい |

**「利用者に見せる」と「外部に載せる」を混同しない。**
前者はこの仕事そのもので、後者は禁止。

## 絶対の制約

| 変える | 変えない |
|---|---|
| 器（`<head>` / `<style>`、テンプレート、レイアウトの割付） | **文章・数値・図の構造**（中身は `slider-html-craft`） |
| 変換のしかた（係数・座標の読み方） | **出力された pptx を手で**（図を除く。次の変換で消える） |
| 検査で見つけたずれを **HTML 側で** | 元の HTML（`-o` で別に出す） |
| **最後に図・グラフ・表を pptx 側で作る** | 図を入れた版を再変換すること（図が消える） |

## 進め方

```
作業の進捗:
- [ ] 0. 入口の判定 ★止まる（器の選択とまとめて聞く）
- [ ] 1. 器を決める（登録テンプレ／客先 pptx）
- [ ] 2. 段階0（1枚だけ変換して、器自体のずれを潰す）
- [ ] 3. 変換
- [ ] 4. 自分の確かめ（HTML の絵と pptx の絵を並べる）→ slider-deck へ検査を渡す
- [ ] 5. ずれを HTML に差し戻す
```

このチェックリストを回答に写し、進むたびに埋める。

### 0. 入口の判定 ★ここで1回だけ止まる

**最初に必ず通し、出てきた表を最初の出力にする。**推測で始めない。

```bash
python3 scripts/entry_check.py [<受け取ったファイル>] [--project <案件>] --want convert
```

**担当が slider-html-reskin でないと出たら、そのスキルへ渡す。**
HTML が無ければ変換できない。pptx を直接作る・直すなら `slider-pptx-craft`。

### 1. 器を決める

| 器 | 道 | 残るもの |
|---|---|---|
| **登録済みのテンプレート** | `reskin_html.py --list` で一覧を出し、**利用者に選んでもらう**（依頼に名前があればそれ） | 見た目。マスターは入らない |
| **客先・前回の会議の pptx の書式** | **`references/30_from_pptx.md`**（`html2pptx.py --template <その pptx>`） | **マスター・レイアウト・テーマ・共通パーツ** |
| 別のテンプレートへ HTML のまま載せ替える | `references/10_rules.md` の手順（`reskin_html.py --dry-run` → 本番） | — |

**一覧に無い名前を指定されたら、一覧を見せて選び直してもらう。**近いものを勝手に選ばない。

**突き合わせは機械にやらせる。**引き継ぎメモに指紋があれば:

```bash
python3 scripts/handoff.py <テンプレ> --expect <メモに書かれた指紋>
```

違えば異常終了する。そのまま変換しない。テンプレートが無い・食い違うときは `references/05_receive.md`。

### 受け取るのは HTML 一式 ★

| 渡されるもの | 役割 |
|---|---|
| **HTML 一式**（各スライドと `print.html`） | **正本。これを変換する** |
| テンプレート一式（`template-manifest.md`・`images/`） | 寸法・ロゴ。**無いと寸法が狂う** |
| 内容の md（あれば） | 読む用。**変換に使わない**（md と HTML が食い違えば HTML が正しい） |

**md から HTML を組み立て直さない。**文字の座標・線の始点終点・微調整した値が入らず、絵が別物になる。
HTML を送れないと言われたら、送る手段（共有フォルダ・USB・zip）を探してもらう。

### 2. 段階0 — 1枚だけ変換する

**20枚作ってから係数のずれが見つかると、20枚分の手戻りになる。**

```bash
python3 scripts/stage0.py <テンプレ>/001.html
```

HTML の絵・pptx の絵・検査が一度に出る。**両方の絵を並べて見て、ずれを潰してから残りを変換する。**

### 3. 変換

```bash
python3 scripts/html2pptx.py <案件>/out/latest/print.html -o <案件>/out/latest/deck.pptx
```

| | いつ | 何が起きるか |
|---|---|---|
| **既定（任せる）** | ふだん | 枠を行に束ね、余白をそろえて敷き直す。**重なりが起きない** |
| `--keep-coords`（写す） | HTML と1枚ずつ見比べるとき、回帰見本 | 座標をそのまま置く。枠が伸びると重なる |

- **出力に出る「換算係数とその出所」を読む。**マニフェストから取れていなければ `--px-per-pt` で明示する
- **枚数が合っているか数える**
- **入りきらないときは縮めない。**「縦に n px 入りきらない」と報告する
- 出力先に既にファイルがあれば書かない。**`guard_edit.py check` を通し、変わっていなければ `--force`**
- 名前は `<案件>/out/latest/deck.pptx` に固定。版はフォルダで分ける。案件に版の運用があればそちらに従う

### 図・グラフは最後に入れる ★

**グラフは Excel で作って貼る**（`references/52_charts.md`）。**図は HTML に戻せない**ので、
文言の直しが終わってから入れる。**図を入れたら、そのファイルを再変換しない。**
どの版に図が入っているかを引き継ぎメモに書く。

### 4. 自分の確かめ → 検査は slider-deck

変換した直後に、**自分で HTML の絵と pptx の絵を並べる。**ずれは片方だけでは出ない。

```bash
python3 scripts/html_png.py <案件>/out/latest/print.html
python3 scripts/qa_render.py <案件>/out/latest/deck.pptx
python3 scripts/fit_check.py check <案件>/out/latest/deck.pptx
```

**渡す前の検査（日本語の行・校正言語・画像・ノート・書式の差分）は `slider-deck` に渡す。**
ここで同じ検査を作り直さない。slider-deck が無い機械では「渡す前の検査はしていない」と報告に書く。

### 5. ずれを HTML に差し戻す

**直すのは HTML。**何をどう直したかを、スライド番号付きで出す。直したら手順3に戻る。
文・構成の直しは中身の話なので `slider-html-craft` へ戻す。**器の話と中身の話を混ぜない。**

## 承認ポイント — どこで止まるか

| 止める | 止めない |
|---|---|
| **入口と器の選択**（まとめて1回） | 決まった（要確認でない）レイアウト割付 |
| 割付が「要確認」「決まらない」、欠落が出たとき | 変換のやり直し |
| **再現できない図をどう埋めるか** | 再現できた図の細部 |
| **既にある pptx の上書きで `guard_edit` が止めたとき** | 差分の無い上書き（退避は自動） |
| 版を切るとき（`out/latest` → `out/vNN`） | `out/latest` の中の上書き |
| 資料を外部に送る操作（**公開は禁止**） | 手順2〜5の往復 |

**上記以外は聞かずに進める。**判断したら理由を1行述べる。**止まるときは、未決のものを全部まとめて出す。**

## 自律判断の基準

### 聞かずに決める

- マニフェストから読めた px→pt 係数、割付が決まったレイアウト、出力ファイル名
- 自分の確かめで見つけた明らかな不具合の修正（HTML 側）
- 回帰見本を通すか（**変換器を直したら必ず通す**）

### 必ず確認する

1. 係数がマニフェストから読めないとき（全項目がずれる）
2. 図・線・グラフが再現できないとき
3. スライド寸法が違う器へ移すとき（**溢れる**）
4. 画像化の道具が無いとき（**「見ていない」と明記する**）

### 聞き方の型

**全案に メリット・デメリット・コスト を揃え、推奨に理由を1行付ける。**「何もしない」も1案に入れる。
値を確かめるときは、**間違えるとどうなるか**を添える。

## タスク完了時

報告して終わらない。**残りの選択肢を出し、推奨を1つ示す。**
報告には**使った手順と、各道具のサマリ行**（`検査: ...`）を貼る。呼んだが使わなかった手順は「使わなかった」と書く。

| 区分 | 例 |
|---|---|
| 検査に渡す | `slider-deck` で渡す前の検査（**推奨の既定**） |
| ずれを直す | HTML を直して再変換 |
| 中身に戻る | `slider-html-craft` へ |
| 何もしない | 現状で提出できる根拠を述べる |

## 記録 — 手順どおり進められなかったとき

**このスキルの指示に従えなかった事象は、`docs/feedback.md` に1行追記する。**
日付・原因ID・依頼・期待した挙動・実際の挙動・推定原因。台帳はリポジトリ直下に1つだけ。
**本体を直すのは、同じ原因が2回以上出てから。**n を数える単位は症状ではなく**原因**。
