# 55_revise — 既存の pptx を土台に、直して版を重ねる

**slider-pptx-craft の手順1〜5で読む。**前回の会議の資料から次回分を作るとき、人が直した版を受け取ったとき、
「このパワポを直して」と言われたとき。

資料は10回以上直す。**人（利用者・上司）が pptx を直接直す。直し方を誤ると、その手直しを消す。**

## 0-0. 最初に：最新版と、人の手直しの一覧 ★出力必須

**設計の前提にするのは、手直しの後の最新版。**手直し前の版を前提にすると、人が消したものを足し直す案になる。

1. **最新版を決める。**判定表の「pptx（新しい順）」の先頭が候補。名前（Rev 等）と日付が食い違うなら聞く
2. **自分が前に出したものと比べる。**比べる相手は次の順で探す：`guard_edit` の控え → `out/v<NN>/` の前の版 → `in/` の古い版。
   **どれも無ければ `formats` だけで一覧を作り、「人が消したものは見ていない（比べる相手が無い）」と表の下に書く**

```bash
python3 scripts/diff_slides.py <自分が前に出した>.pptx <最新版>.pptx --format
python3 scripts/pptx_edit.py formats <最新版>.pptx      # 人が付けた強調（赤太字など）と改行の一覧
```

3. **次の表を、案を出す前に必ず出す。**

```markdown
## 人の手直し（<最新版> と <前に出したもの> の差）
| 枚 | 変化 | 中身 | これから守ること |
|---|---|---|---|
| 5 | 文字・強調 | 右の文に赤太字を追加 | 赤太字の範囲を変えない |
| 7 | 消えた | 進行表示を削除 | 他の枚にも付けない |
変わっていない枚: 1, 2, 3, 4, 6
```

**「消した」も手直し。**人が消したものを、次の版で足し直さない。

## 0-1. 直す前に：修正案の表で止まる ★出力必須・ここで必ず止まる

**承認の前に書き込まない。**規約だけでは守られなかったので、**表を出して止まる形にする。**

```markdown
## 修正案（承認をお願いします）
| # | 枚 | 箇所 | 今 | 案 | 書式への影響 | 出どころ |
|---|---|---|---|---|---|---|
| 1 | 5 | 右の文 | 〜が良好 | 〜がおおむね良好 | 赤太字の範囲はそのまま | 依頼 |
| 2 | 6 | 画面の画像 | 旧版 | 元の表の最新版で撮り直す | 枠は残す | 元ファイルの更新 |
直さない枚: 1〜4, 7〜10
```

- **書式への影響**の列を空けない。人が付けた強調・改行に触るかどうかを、直す前に示す
- **出どころ**：依頼／調べた（出典）／測った／こちらの案。混ぜない（下の 3-2）
- 「提案して」「どうするか」と言われたら、**この表で止まる。**直すのは承認の後
- 承認された行だけ直す。**表に無いものを、ついでに直さない**

## 0. 書き出しの歯止め ★

**最初から差分修正モード。**受け取った pptx が正本で、HTML は無い。作り直さない。

| すること | なぜ |
|---|---|
| 必要な枚・必要な枠だけを直す | 利用者の手直しは、どこに入っているか分からない |
| **自分が書き出すたびに `guard_edit.py record` で控える** | 次に上書き・削除するとき、比べる元になる |
| **上書き・削除の前に `guard_edit.py check` を通す** | 入口(2)は python-pptx で書き出すので、`html2pptx.py` の上書き防止が**効かない** |
| 止まったら、上書き・削除せず局所修正に切り替える | 止まった＝利用者が直した枚がある |

```bash
python3 scripts/guard_edit.py record <自分が書き出した>.pptx
python3 scripts/guard_edit.py check  <上書き・削除する>.pptx   # 変わっていれば終了1で止まる
```

実績として、別の版を削除するときに手直しの有無を確かめず、**利用者が直した枚が戻った。**
その前の回では比べて引き継げていた。**同じ人が同じ案件でも、確かめる回と確かめない回がある。**だから機械で止める。

## 0-2. 画像の差し替えと、画面の貼り付け

### 画像に書き込まない ★

**強調の枠・矢印・丸は、画像に焼き込まず、PowerPoint の図形で上に置く。**
焼き込むと、
画像を撮り直したときに枠も作り直しになり、位置を少し動かすこともできない。

**画面の画像は、要点が読める範囲だけを載せる。**全体を縮めて載せると読めない。

### 画像の出どころを残す

**元のファイル（表計算など）が変わったら、撮り直す。**そのために、画像ごとに出どころを案件の作業メモ（`project.md` 等）に残す。

| 枚 | 画像 | 元のファイル | 範囲 | 撮った日 |
|---|---|---|---|---|
| 6 | 画面1 | <元のファイル名> | <シート・範囲> | <日付> |

元のファイルの更新を聞いたら、この表から撮り直す画像を出し、修正案の表に載せる。

### 切り取った画像を差し替える

**枠（位置・大きさ）を残し、画像だけを替える。**枠を作り直すと、周りの図形との揃いが崩れる。
新しい画像の縦横比が枠と違うときは、**切り取りで合わせる。引き伸ばさない。**

```bash
python3 scripts/pptx_edit.py image <pptx> --slide 6 --pic 1 --file 新しい画像.png -o <出力>
```

**中央で切ってよいかは画像による。**表の端や凡例が切れるなら、利用者に見せて切る位置を決める。
差し替えた後は `jp_wrap_check.py <出力> --before <元>` で、縦横比と解像度の低下を確かめる。

### 表計算の範囲を「画面として」貼る

「画面で貼って」「見た目のまま貼って」と言われたら、**表として作り直さず、画像で貼る。**
表に作り直すと、色・罫線・列幅が元の見た目から変わり、先方が見慣れた画面と違って見える。

| 環境 | 画像の作り方 | 確かめた度合い |
|---|---|---|
| 表計算ソフトのある機械 | その範囲を「図としてコピー」し、画像で保存する | **未検証**（この機械では試していない） |
| 無い機械 | **利用者に画面の切り取りを頼む。**こちらで似せて作らない | — |

**解像度は、表示する大きさの 150dpi 以上を目安にする**（`jp_wrap_check.py` の基準と同じ）。
画面の切り取りは表示倍率で解像度が決まるので、小さいときは拡大して取り直してもらう。

## 1. HTML から作った pptx を受け取ったとき（2つのモード）

**この節は、slider-html-reskin で作った pptx に人の手が入ったときの切り替え。**

| モード | いつ | やり方 |
|---|---|---|
| **再生成** | 利用者がまだ pptx を手で編集していない | **受け取った HTML から変換し直す**（`html2pptx.py`） |
| **差分修正** | **利用者が手で編集したファイルを受け取った後** | 該当スライドだけを直す。**作り直さない** |

**pptx を手で直さない。**直すのは HTML で、pptx は変換し直して作る。
作り直せる状態を保っているから、何度直しても崩れない。

---

## 2. 切り替えの判定

**一度でも利用者が編集したら、以後は永久に差分修正モード。**戻さない。

| 状況 | モード |
|---|---|
| 自分が作ったファイルを、自分で直す | 再生成 |
| **利用者から編集済みのファイルを受け取った** | **差分修正。以後ずっと** |
| 利用者が「作り直していい」と明言した | 再生成に戻してよい |
| 編集されたか分からない | **差分修正**（安全側に倒す） |

### 編集されたかを確かめる

受け取ったファイルと、自分が最後に出力したものを比べる。

```bash
python3 scripts/diff_slides.py <自分が出したもの>.pptx <受け取ったもの>.pptx
```

**1枚でも変わっていれば、利用者が編集している。** 差分修正モードに入る。

## 3. 絶対にやらないこと

| してはいけない | 何が起きるか |
|---|---|
| **利用者のファイルを上書きする** | 手で入れた修正が消える。**元に戻せない** |
| 編集済みファイルを作り直す | 同上 |
| 「たぶん編集していない」で再生成する | 同上。**分からないときは差分修正** |
| 直したスライド番号を報告しない | 意図しない箇所を触っていないことを示せない |

### 歯止めは機械で持つ

**規約だけでは守られない。** 実際に、この規約を書いた上で利用者の編集済み
ファイルを上書きし、復旧できなくした。ゴミ箱にもスナップショットにも残らず、
git の追跡対象外だった。

`html2pptx.py` は、出力先に既存ファイルがあれば `--force` なしでは書かない。

```
既にある: out/latest/deck.pptx
**上書きしない。** 利用者が手で直したものかもしれない。
  確かめる: python3 scripts/guard_edit.py check out/latest/deck.pptx
  変わっていなければ --force で置き換える。別名にするなら、名前は案件の版の運用に合わせる（日時は入れない）
```

**`--force` は、そのファイルが自分の生成物だと確かめてから使う。**
確かめる手段は **`guard_edit.py check`**。対象を退避してから、自分が最後に出した控えと比べ、
1枚でも変わっていれば止まる（終了1）。**控えが無ければ、編集されている前提で止まる。**
**削除の前も同じ。**消すのは上書きと同じく戻せない。

**生成物と受け取ったものは、置き場所で区別する。**受け取ったものは `<案件>/in/`、
自分が出すものは `<案件>/out/latest/`（`assets/project-layout.md`）。名前に印を付けて区別しない。

### 版の扱い（名前と上書き） ★入口の判定でまとめて聞く

**既定は「受け取ったものに触らず、別に出す」。**利用者が見比べて、どちらを採るか決められるようにする。
ただし**案件に版の運用があれば、そちらに従う。**どちらかは入口の判定で1回だけ聞く
（`entry_check.py` が名前に Rev 等の形跡を見つけたら、表に出る）。

| 案件の運用 | 出し方 | 前提 |
|---|---|---|
| 運用が無い（既定） | `<案件>/out/latest/` に出す。受け取ったものは `in/` のまま触らない | `assets/project-layout.md` |
| **名前に版を入れる運用**（`…_Rev3.pptx` 等） | 利用者の決めた名前で出す。**版を上げるか、同じ版に上書きするかを聞く** | 名前は利用者の運用。こちらで付け替えない |
| **同じ版に上書きする**と言われた | 上書きする | **`guard_edit.py check` を先に通す。**退避は自動。止まったら上書きせず、変わった枚を報告する |

**上書きは、利用者か案件の運用がそう言ったときだけ。**黙って上書きしない。
**日時を名前に入れない。**日付は `project.md` の履歴へ書く。

## 3-2. 調べたことと、こちらの案を分けて書く ★

**報告の中で混ぜない。** 実際に「これは調べた結果ですか」と問われ、
**一部にしか出典が無いことを認めた。**

**案を1つ出すたびに、どこから来たかを書く。**

```
| # | 案 | 出どころ |
|---|---|---|
| 1 | <案> | **調べた**（<発行元・年>） |
| 2 | <案> | **測った**（<何を何件>） |
| 3 | <案> | **こちらの案。**根拠は無い |
```

| 出どころ | 意味 |
|---|---|
| **調べた** | 出典が言える。**出典を書く** |
| **測った** | この資料・この pptx から数えた。**数と取り方を書く** |
| **こちらの案** | **根拠が無い。**そう書く。読み手が採否を決められる |

**「調べた」と書けるのは、実際に調べたときだけ。**
記憶から書いたなら「こちらの案」。**曖昧にしない。**

**全部が「こちらの案」でもよい。** 悪いのは、案なのに調べた結果に見えること。

## 4. 差分の報告

**「3枚目を直しました」と言うだけでは、他を触っていない証明にならない。**
毎回、機械的に差分を出して報告に貼る。

```bash
python3 scripts/diff_slides.py <前>.pptx <後>.pptx
```

### 報告の形

```markdown
## 手直しの結果

直したこと: 4枚目のコスト内訳を追加

| スライド | 変化 | 内容 |
|---|---|---|
| 4 | 文字が変わった | 追加: 治具代 180万円 / 工数 240万円 |

変わっていないスライド: 1, 2, 3, 5, 6

**意図した4枚目以外は触っていない。**
```

**変わっていないスライドの番号も出す。** そこまで書いて初めて証明になる。

意図しないスライドが一覧に出たら、**報告する前に原因を調べる。**
「たぶん再生成のせい」で済ませない。
