# pptx を直接作り、直す

**pptx が正本の資料**を作り、版を重ねる。HTML は無い。

```
テンプレート／前回の会議の pptx（人の手直し入り）
  ↓ 手直しの一覧 → 修正案の表 → 承認
slider-pptx-craft（局所的に直す・枚を足す）  ← ここ
  ↓ pptx
slider-deck（検査）→ 指摘はここへ戻る
```

**このスキルの価値は「pptx が出ること」ではなく「人の手直しを1つも消さずに、次の版が出ること」にある。**
上司や利用者は pptx を直接直す。会議ごとに同じ資料を直す。作り直すと、その手直しが消える。

### 役割 — 誰として、何を優先するか

| | |
|---|---|
| 誰として | 資料の持ち主（利用者・上司）が育てている資料を、次の版に進める担当として |
| 最優先 | **人の手直し（文字・赤太字・改行・消したもの）を消さないこと** |
| **誰の側に立つか** | **資料の持ち主の側。**こちらが整えたい側ではない |
| しないこと | 作り直さない。**承認の前に書き込まない。**表に無いものをついでに直さない。資料を外に出さない |

**迷ったら、直さずに修正案の表に載せる。**直すかどうかは持ち主が決める。

---

## 資料を外に出さない ★最初に読む

**扱うのは、まだ外に出ていない資料。** 提案前の提案書、社外秘の報告書、
利用者の組織のテンプレート。**一度外に出ると取り消せない。**

### 公開しない

**禁じるのは「他人が見られる状態にすること」。** 非公開のまま扱うことは禁じない。

| してはいけない | 何が起きるか |
|---|---|
| **公開する・リンクを共有する** | 誰でも開ける。**取り消せない** |
| **第三者が開ける状態にする**（共有設定、共有ドライブ、gist、pastebin） | 同上 |
| オンライン変換サービスに上げる | 中身を保持することがある |
| **資料やテンプレートを git に入れる** | private でも、組織の外に出たことになりうる。テンプレートは `.gitignore` で除外する |
| 本文や図表を外部サービスに送る | 数値・宛先がそのまま渡る |

**自分の判断では一切やらない。** 「共有リンクを出しましょうか」と**提案もしない。**
提案は実行への一歩で、断る手間を利用者に負わせる。

### 非公開のまま使うのはよい

| 手段 | 可否 |
|---|---|
| **Browser ペインに `file://` で開く** | **よい。**機械の外に出ない。**既定はこれ** |
| **利用者だけが開ける Artifact** | **よい。**ただし中身は claude.ai 上に載る（手元だけの状態ではなくなる） |
| ローカルに PNG / pptx を書く | **よい** |
| `SendUserFile` で利用者本人に渡す | **よい** |

**既存の非公開 Artifact を消す必要はない。** 消すかどうかは利用者が決める。
**こちらから削除を促さない。**

### 出してよいもの

| 手段 | 可否 |
|---|---|
| ローカルのファイルに書き出す（`<案件>/out/latest/` の下） | **よい。**これが既定 |
| `SendUserFile` で利用者本人に渡す | **よい。**利用者の端末に渡すだけで、公開ではない |
| 会話の中に文言・構成を書く | よい |

**「利用者に見せる」と「外部に載せる」を混同しない。**
前者はこの仕事そのもので、後者は禁止。

## 公式 pptx スキルとの関係

**このスキルが主導し、公式は道具として使う。**既存の pptx の編集技術（枚の複製・XML の扱い・検証）は公式の領域。
どこを使い、どこを書式優先で上書きするかは `assets/content/07_official.md`。**公式の文言やコードは写さない。**

## 中身の規約は共通

伝えたいこと・骨子・1枚のメッセージ・図の意味・日本語の文体は、**`slider-html-craft` と同じ規約を読む。**
置き場所はリポジトリ直下の `assets/content/`（`python3 scripts/paths.py --content` が返す）。**ここに写さない。**

| 決めること | 読む |
|---|---|
| 何のための資料か、相手・場面 | `assets/content/10_intent.md` |
| 骨子（枚の並び） | `assets/content/20_story.md` |
| 図の選び方と、**図の意味が伝わるか**（色・矢印・同じ概念は同じ図） | `assets/content/30_visual.md` |
| 日本語（体言止め・改行・文字量） | `assets/content/40_japanese.md` |
| 数値・用語 | `assets/content/46_numbers.md`、`47_terms.md` |
| 先方の目で見る | `assets/content/80_audience.md` |

## 進め方

```
作業の進捗:
- [ ] 0. 入口の判定 ★止まる（版の扱いとまとめて聞く）
- [ ] 1. 最新版と、人の手直しの一覧（出力必須）
- [ ] 2. 中身を決める（新規・次回分のとき：骨子 ★止まる）
- [ ] 3. 修正案の表 ★必ず止まる
- [ ] 4. 承認された行だけ直す
- [ ] 5. 自分で見る → 差分の報告 → slider-deck へ検査を渡す
```

このチェックリストを回答に写し、進むたびに埋める。

### 0. 入口の判定 ★ここで1回だけ止まる

```bash
python3 scripts/entry_check.py [<受け取ったファイル>] [--project <案件>] --want pptx
```

**出てきた表を最初の出力にする。**担当が違うと出たら、そのスキルへ渡す。
ここでまとめて聞く：**最新版はどれか**（名前と日付が食い違うとき）、**版の扱い**（別に出す／同じ版に上書き。`55_revise.md`「版の扱い」）。

| 始め方 | 土台 |
|---|---|
| **前回の会議の資料から次回分** | 前回の**最新版**（人の手直し後）を複製して土台にする |
| 渡された pptx を直す | その pptx |
| テンプレート・客先書式から新規 | その pptx のマスター・レイアウト（見本の枚は外す）。書体と配色は `read_template_style.py` で読む |

### 1. 最新版と、人の手直しの一覧 ★出力必須

`55_revise.md` 0-0章。**案を出す前に、必ずこの表を出す。**

```bash
python3 scripts/diff_slides.py <自分が前に出した>.pptx <最新版>.pptx --format
python3 scripts/pptx_edit.py formats <最新版>.pptx
```

人が付けた強調・改行・消したものを「これから守ること」として書き出す。**設計の前提は、この表の後の版から取る。**

### 2. 中身を決める

| 場面 | すること | 止まるか |
|---|---|---|
| 依頼された箇所だけ直す | 直す箇所を決める（手順3へ） | — |
| **次回分を作る・新規に作る** | 何を言うか（意図）と骨子を `assets/content/10_intent.md` `20_story.md` で決める。**前回からの変更点を枚ごとに1行で出す** | **骨子で止まる** |

**前回の版にあるものを、聞かずに消さない。足さない。**変える枚と変えない枚を骨子に書く。

### 3. 修正案の表 ★ここで必ず止まる

`55_revise.md` 0-1章の形で出す。**承認の前に書き込まない。**
「提案して」「どうするか」と言われたら、この表で止まる。**書式への影響**と**出どころ**の列を空けない。

### 4. 承認された行だけ直す

**手で XML を触らない。**道具を使う（人の書式の境目を機械で守る）。

```bash
python3 scripts/pptx_edit.py text  <土台>.pptx --slide 5 --find 旧 --replace 新 -o <案件>/out/latest/deck.pptx
python3 scripts/pptx_edit.py image <土台>.pptx --slide 6 --pic 1 --file 新.png -o <出力>
python3 scripts/pptx_edit.py lang  <出力>.pptx -o <出力>.pptx --force     # 日本語の校正言語（赤い波線を出さない）
```

| 道具が止めたら（終了3） | どうするか |
|---|---|
| 書式の境目をまたぐ | 範囲を書式ごとに分けて替える。**どちらの書式にするかは聞く** |
| 改行をまたぐ | 改行の前後で分けて替える。**改行は消さない** |
| 既にある・guard_edit が止めた | 上書きしない。変わった枚を見せて決めてもらう |

**枚を足す**ときは、土台のレイアウトから足す（公式の枚の複製の手順を道具として使う。`07_official.md`）。
**強調の枠・矢印は図形で置く。画像に焼き込まない。**画像を差し替えたら出どころの表を更新する（`55_revise.md` 0-2）。
ノートの中身は `slider-script` の担当。**ノートに作業メモを書かない。**

### 5. 自分で見る → 差分の報告 → 検査を渡す

```bash
python3 scripts/qa_render.py <案件>/out/latest/deck.pptx
python3 scripts/diff_slides.py <最新版>.pptx <案件>/out/latest/deck.pptx --format
```

**画像を1枚ずつ見る。**差分は `55_revise.md` 4章の形で報告に貼る。**意図した枚以外が出たら、報告の前に調べる。**
**「強調が消えた」が出たら、それが承認された変更かを確かめる。**承認されていなければ戻す。

渡す前の検査（日本語の行・校正言語・画像・ノート・溢れ）は **`slider-deck` に渡す。**ここで作り直さない。

## 成果物をどこに出すか

決めごとは `assets/project-layout.md` が正本。見るのは常に `<案件>/out/latest/`。
**案件に版の運用（名前に Rev を入れる、同じ版に上書き）があれば、そちらに従う**（`55_revise.md`「版の扱い」）。
受け取ったものは `<案件>/in/` に置いたまま触らない。

## 承認ポイント — どこで止まるか

| 止める | 止めない |
|---|---|
| **入口・最新版・版の扱い**（まとめて1回） | 手直しの一覧を出すこと |
| **骨子**（次回分・新規のとき） | 承認された行を直すこと |
| **修正案の表**（毎回。承認の前に書き込まない） | 自分で見る・差分を出す |
| 道具が止めたとき（書式の境目・改行・guard_edit） | 校正言語を付ける |
| 版を切る・上書きするとき | `out/latest` の中の自分の出力の更新（控えと一致するとき） |
| 資料を外部に送る操作（**公開は禁止**） | — |

**上記以外は聞かずに進める。**判断したら理由を1行述べる。**止まるときは、未決のものを全部まとめて出す。**
**手順0〜3 の止まる所は、材料がそろっていれば1回にまとめる**（判定表・手直しの一覧・骨子・修正案の表を1つの返事で出す）。分けるのは、前の答えで次の案が変わるときだけ。

## 自律判断の基準

### 聞かずに決める

- 手直しの一覧の作り方、差分の出し方、画像にする枚
- 承認された行の直し方（道具の使い方）
- 日本語の校正言語を付けること

### 必ず確認する

1. **最新版が名前と日付で食い違うとき**
2. **人が付けた書式・改行に触る直し**（修正案の表の「書式への影響」に書いて聞く）
3. 前回の版にあるものを消す・足すとき
4. 画像の切り取りで端の表・凡例が切れるとき

### 聞き方の型

**全案に メリット・デメリット・コスト を揃え、推奨に理由を1行付ける。**「何もしない」も1案に入れる。
値を確かめるときは、**間違えるとどうなるか**を添える。

## タスク完了時

報告して終わらない。**残りの選択肢を出し、推奨を1つ示す。**
報告には**使った手順と、各道具のサマリ行**（`検査: ...`）を貼る。**呼んだが使わなかった手順は「使わなかった」と書く。**
（実績: 使っていない手順を「使った」と記録した）

| 区分 | 例 |
|---|---|
| 検査に渡す | `slider-deck` で渡す前の検査（**推奨の既定**） |
| ノートを作る | `slider-script` |
| 版を切る | `out/latest` → `out/vNN`（利用者の判断） |
| 何もしない | 現状で渡せる根拠を述べる |

## 記録 — 手順どおり進められなかったとき

**このスキルの指示に従えなかった事象は、`docs/feedback.md` に1行追記する。**
日付・原因ID・依頼・期待した挙動・実際の挙動・推定原因。台帳はリポジトリ直下に1つだけ。
**本体を直すのは、同じ原因が2回以上出てから。**n を数える単位は症状ではなく**原因**。
