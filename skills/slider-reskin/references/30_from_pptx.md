# 30_from_pptx — 既存の pptx の書式を土台に、中身を載せる（入口(2)）

手順0で入口(2)と判定したときに読む。**入口(1)（HTML 一式を登録済みのテンプレートへ）とは道具が違う。**

## なぜ入口(1)では足りないか

入口(1)は、変換の土台が**空のファイル**になる（`20_templates.md` 1-2）。
見た目は HTML 側で合わせられるが、**客先のマスター・レイアウト・テーマは出力に入らない。**
受け取った側が PowerPoint で新しいスライドを挿すと、客先のレイアウトが出てこない。

入口(2)は、**書式の元の pptx を複製して土台にする。**マスター・レイアウト・テーマ・
マスター上の共通パーツ（ロゴ・ページ番号・帯）はそのまま残り、元の見本のスライドだけが外れる。

## 1. まず中身の元の形を見る ★分け方の軸

入口(2)で決まるのは「書式の元」だけ。**中身の元がどの形かで、手順が分かれる。**

| 中身の元 | どうするか | 文を変えるか |
|---|---|---|
| **意味づけした HTML**（`<section class="slide" data-layout="…">` を並べた1ファイル） | そのまま 2 へ | 変えない |
| **座標を持つ HTML**（slider-craft のテンプレートで作った一式） | **そのままでは載らない**（変換器が空の土台の経路に入る）。下の「座標を持つ HTML のとき」 | 変えない |
| **別の書式の pptx** | 文字を抜き出して意味づけ HTML に書き起こす（公式の文字の抜き出し、または python-pptx）。**文は写すだけ** | 変えない |
| メモ・文章だけ | **ここでは作らない。**slider-craft で中身を作ってから戻る | — |

### 座標を持つ HTML のとき

利用者が何を求めているかで分かれる。**推測で決めず、手順0でまとめて聞く。**

| 求めているもの | 取る道 | 失うもの |
|---|---|---|
| **客先のマスター・レイアウトが要る**（先方が後で枚を足す、先方の書式審査がある） | 1枚ずつ意味づけ HTML に書き起こして、この入口で載せる | 図形で描いた図は、画像として貼るか表に直す。**崩れる枚を先に報告する** |
| 見た目が合っていればよい | 書式の元を入口(1)のテンプレートとして取り込む（`20_templates.md` 1-2）→ 入口(1) | マスター・レイアウト（上の理由） |

## 2. 書式の元を読む

```bash
python3 scripts/read_template_style.py <書式の元>.pptx
```

書体（見出し・本文、欧文と日本語）、レイアウトごとの枠と文字サイズ、配色が出る。
**日本語の書体が「未指定」なら、実際に使われている書体の欄から決める。**決められなければ報告する。

レイアウトの見た目を確かめるときは、公式 pptx スキルの一覧画像の道具を使う（`skills/slider-deck/references/07_official.md` 3章）。

## 3. 載せる

```bash
python3 skills/slider-deck/scripts/html2pptx.py <中身>.html --template <書式の元>.pptx -o <案件>/out/latest/<名前>.pptx
```

**書式の元そのものを `-o` に渡さない。**書式の元は読むだけのもので、上書きすると先方の原本が消える。
`-o` の先に既にファイルがあるなら、`skills/slider-deck/scripts/guard_edit.py check` を先に通す。

変換の後に割付の表が出る。**`←妥協` の行は、合うレイアウトが書式の元に無かった枚。**

| `←妥協` が出たら | |
|---|---|
| 報告する | どの枚が、どのレイアウトで代わりに作られたか |
| 勝手に直さない | 書式の元にレイアウトを足すのは、先方の書式を変えること。**利用者に聞く** |

## 4. 検査する

slider-deck の検査をそのまま使う（`skills/slider-deck/references/60_qa.md`）。足すのは2つ。

```bash
python3 skills/slider-deck/scripts/fit_check.py check <出力>.pptx
python3 skills/slider-deck/scripts/jp_wrap_check.py <出力>.pptx
python3 skills/slider-deck/scripts/qa_render.py <出力>.pptx
```

| 足すこと | なぜ |
|---|---|
| **書式の元の絵と並べて見る**（`qa_render.py <書式の元>.pptx` も出す） | 共通パーツ（ロゴ・ページ番号・帯）が残ったか、配色・書体が同じかは、並べないと分からない |
| ファイルの検査は `--original <書式の元>.pptx` を付ける | 書式の元が持っていた誤りを、自分の誤りと見分けるため。読み方は `07_official.md` 4章 |

**「合わせた」と報告する前に、絵で見比べる。**変換できたことは、合っていることの証拠にならない。

## できないこと

| | 代わりに |
|---|---|
| 書式の元の**見本のスライドを残したまま**足す（表紙だけ流用、等） | slider-deck の入口(2)（既存の pptx を土台に必要な箇所だけ直す） |
| 書式の元のレイアウトに無い型を作る | `←妥協` として報告し、利用者に聞く |
| 中身の文を直す | slider-craft の担当。**1文字も書き換えない** |

## 手順0でまとめて聞くこと

1. 書式の元はどの pptx か（複数あるとき）
2. 中身の元はどれか、その形（上の1の表）
3. 座標を持つ HTML なら、**客先のマスター・レイアウトが要るか**
4. 出力の名前と版の扱い（`skills/slider-deck/references/55_revise.md`）
