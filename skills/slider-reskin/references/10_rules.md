## 1. なぜ HTML を載せ替えるのか

資料は **HTML が正本、pptx は派生物**（slider-craft `48_html.md`）。

```
HTML  ← 正本。直すのはここ
  ↓ 変換
pptx  ← 派生物。**手で直さない**
```

**pptx を載せ替えると、次の変換で消える。** 直したはずのものが戻る。
以前このスキルは pptx を載せ替えていた。**それは正本を直していなかった。**

```
正しい:  HTML を載せ替える → 変換し直す → 新しいテンプレの pptx
誤り:    pptx を載せ替える → 次の変換で消える
```

---

## 2. 何を変え、何を変えないか

資料テンプレートの HTML は、**`<style>` が器、`<body>` が中身**に分かれている。

| | 変える | 変えない |
|---|---|---|
| `<head>` / `<style>` | **丸ごと移行先のものにする** | — |
| `<body>` | — | **元のまま移す** |

これだけで、座標・文字サイズ・スライド寸法・配色・書体が移行先のものになる。
すべて `<style>` 側にあるため。

**文章を書き換えない。** 中身を直すのは slider-craft の仕事。
**ここで直すのは器だけ。**

## 3. 手順

### 手順1: 選べるテンプレートを出す ★ここで止まる

```bash
python3 scripts/reskin_html.py --list
```

**利用者に選ばせる。こちらで決めない。**

### 手順2: 下見だけ先に出す

```bash
python3 scripts/reskin_html.py <作業ディレクトリ> --to <テンプレ名> --dry-run
```

**書く前に、どのレイアウトに載るかを見る。**
割付が違っていれば、ここで `--layout` を決める。

### 手順3: 載せ替える

```bash
python3 scripts/reskin_html.py <作業ディレクトリ> --to <テンプレ名> -o <出力先>
```

**元を上書きしない。** `-o` は必須にしてある。
戻れなくなると、どちらが新しいか分からなくなる（`49_handoff.md` 2章）。

`images/` と `print.html` も移行先のものを揃えて出す。

### 手順4: 必ず絵で確認する

**載せ替えだけでは終わらない。寸法が変わっているので溢れる。**

```bash
python3 <slider-craft>/scripts/html_png.py <出力先>/print.html -o qa_html
python3 <slider-craft>/scripts/html2pptx.py <出力先>/print.html -o deck/deck.pptx
python3 <slider-craft>/scripts/fit_check.py deck/deck.pptx
python3 <slider-deck>/scripts/qa_render.py deck/deck.pptx -o qa
```

**溢れが出たら直すのは HTML。** pptx を手で直さない。

## 4. レイアウトの決まり方

上から順に、決まった時点で止まる。

| | 決め方 | 強さ |
|---|---|---|
| 1 | `--layout` の指定 | **人が打ったものが最優先** |
| 2 | `<meta name="slide-layout">` の印（前回の載せ替えが書いた） | 強い |
| 3 | **ファイル名がレイアウト名と同じ**（`003.html` → `003`） | 強い |
| 4 | 使っているクラスの一致数で採点 | **弱い。当てにしすぎない** |

### 採点は最後の手段

**全レイアウト共通のクラスは採点から除く。** ヘッダー・フッターは
どのレイアウトにもあるので、入れたままだと点数が底上げされ、差が消える
（実測: 除く前は 5枚中4枚が1点差になった）。

**それでも、中身ページの派生は分けきれない。**
目次・リードあり・フリーはクラスをほとんど共有する。
実測では、ファイル名を伏せると 4/5 枚が1点差だった。

**1点差は「要確認」として指摘に数える。**
当たっていても、外れたときに気づけない差でしかない。
要確認と出た枚は、**絵を見て確かめるか `--layout` で指定する。**

### だからファイル名を変えない

作業中の HTML は、**テンプレートのファイル名をそのまま引き継ぐ**のがよい。
名前が残っていれば手順3（強い）で決まり、採点に落ちない。

## 5. できないこと

| できないこと | なぜ | どうするか |
|---|---|---|
| **溢れを直す** | 寸法と文字サイズが変わる | 載せ替え後に検査し、HTML を直す |
| 本文に直書きしたページ番号 | `<body>` 側にあり、そのまま移る | 手で直す |
| 移行先に無い図版 | `images/` の中身が違う | **欠落として報告される。**画像を用意する |
| 移行先に無いクラス | 元の `<style>` にしか無かった | **欠落として報告される。**移行先に足すか、使うのをやめる |
| 中身の作り直し | このスキルの役目ではない | slider-craft に渡す |

**「載せ替えたので完了」と報告しない。** 検査までが1セット。

---

## 6. 検査

**指摘ゼロと、何も見ていないことを区別する。**

```
検査: reskin_html  対象 5枚  指摘 0件  前提: 移行先=..., 寸法=..., レイアウト=5, 書き込み=...
```

**この行を報告にそのまま貼る。**「確認しました」の代わりにならない
（slider-craft `60_qa.md` / `scripts/checked.py`）。

### 数だけ見ない。値を見る

「対象 5枚 指摘 0件」でも、**割付が全部間違っていれば意味がない。**
割付の表を読む。**決め方の欄が「採点」で「要確認」が付いていたら、絵を見る。**

### 報告の形

| 書くこと | 例 |
|---|---|
| 移行先と寸法 | `<テンプレ名>`（1280x886px） |
| 割付の表 | どの HTML がどのレイアウトに載り、**どう決めたか** |
| 欠落 | クラス・画像 |
| 検査の1行 | 上記そのまま |
| **まだ見ていないもの** | 溢れの検査を回していないなら、そう書く |
