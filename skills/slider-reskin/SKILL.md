# テンプレート差し替え

資料の HTML 一式を、別の資料テンプレートに載せ替える。

**載せ替えるのは HTML。pptx ではない。**
pptx は HTML から変換して作る派生物で、**手で直しても次の変換で消える**
（`slider-craft` の `references/48_html.md`）。**正本である HTML を載せ替える。**

**このスキルの価値は「テーマを変えること」ではなく「相手先のフォーマットで出せる状態にすること」にある。**
プレゼンごとにテンプレートが変わるため、中身を作り直さずに載せ替えられることが要る。

**中身は作らない。** 構成・メッセージ・図解の選定・文章は `slider-craft` の役目。
このスキルは見た目の器だけを付け替える。

### 役割 — 誰として、何を優先するか

| | |
|---|---|
| 誰として | 提出先の体裁に合わせて載せ替える担当として |
| 最優先 | 新しいテンプレートに適合し、**かつ元の資料の情報が1つも落ちないこと** |
| **誰の側に立つか** | **元の資料を書いた人の意図の側。**見た目を整えたい側ではない |
| しないこと | スライドマスターを書き換えない。中身を作らない。資料を外に出さない |

**「誰の側に立つか」が、収まらないときの判断を決める。**
新しいテンプレートに入りきらないとき、**黙って削らない。**
削れば見た目は整うが、元の書き手が載せた根拠が消える。
**何がはみ出たかを出して、削るかどうかは利用者に決めてもらう。**

## 資料を外に出さない ★最初に読む

**扱うのは、まだ外に出ていない資料。** 提案前の提案書、社外秘の報告書、
利用者の組織のテンプレート。**一度外に出ると取り消せない。**

### 公開しない

**禁じるのは「他人が見られる状態にすること」。** 非公開のまま扱うことは禁じない。

| してはいけない | 何が起きるか |
|---|---|
| **公開する・リンクを共有する** | 誰でも開ける。**取り消せない** |
| **第三者が開ける状態にする**（共有設定、共有ドライブ、gist、pastebin） | 同上 |
| オンライン変換サービスに上げる | 中身を保持することがある |
| **資料やテンプレートを git に入れる** | private でも、組織の外に出たことになりうる。テンプレートは `.gitignore` で除外する |
| 本文や図表を外部サービスに送る | 数値・宛先がそのまま渡る |

**自分の判断では一切やらない。** 「共有リンクを出しましょうか」と**提案もしない。**
提案は実行への一歩で、断る手間を利用者に負わせる。

### 非公開のまま使うのはよい

| 手段 | 可否 |
|---|---|
| **Browser ペインに `file://` で開く** | **よい。**機械の外に出ない。**既定はこれ** |
| **利用者だけが開ける Artifact** | **よい。**ただし中身は claude.ai 上に載る（手元だけの状態ではなくなる） |
| ローカルに PNG / pptx を書く | **よい** |
| `SendUserFile` で利用者本人に渡す | **よい** |

**既存の非公開 Artifact を消す必要はない。** 消すかどうかは利用者が決める。
**こちらから削除を促さない。**

### 出してよいもの

| 手段 | 可否 |
|---|---|
| ローカルのファイルに書き出す（`deck/`、`work/`、`qa/`） | **よい。**これが既定 |
| `SendUserFile` で利用者本人に渡す | **よい。**利用者の端末に渡すだけで、公開ではない |
| 会話の中に文言・構成を書く | よい |

**「利用者に見せる」と「外部に載せる」を混同しない。**
前者はこの仕事そのもので、後者は禁止。

## 絶対の制約

**器だけを入れ替える。中身には書き込まない。**

資料テンプレートの HTML は、**`<style>` が器、`<body>` が中身**に分かれている。

| 変える | 変えない |
|---|---|
| `<head>` / `<style>` を丸ごと移行先のものにする | **`<body>` の中身** |
| どのレイアウトに載せるか | 文章・数値・図の構造 |
| （その結果）座標・文字サイズ・寸法・配色・書体 | 元のファイル（`-o` で別に出す） |

**文章を1文字も書き換えない。** 中身を直すのは `slider-craft` の役目。

**これは主張ではなく、毎回測って確かめる。**
移行先に定義が無いクラス・画像は欠落として出る。**手順4を飛ばさない。**

## 進め方

```
作業の進捗:
- [ ] 1. テンプレートの一覧を出して選んでもらう ★止まる
- [ ] 2. 割付を確認する（--dry-run）
- [ ] 3. 載せ替える
- [ ] 4. 検査（HTML の絵 ＋ pptx の絵 ＋ 溢れ）
- [ ] 5. 手直し（**直すのは HTML**）
```

このチェックリストを回答に写し、進むたびに埋める。

### 1. テンプレートの一覧を出して選んでもらう ★ここで止まる

```bash
python3 scripts/reskin_html.py --list
```

テンプレート名・レイアウト数・スライド寸法が並ぶ。

**どのテンプレートを使うかは必ず利用者に選ばせる。**
テンプレートの選択は資料の見え方すべてを決めるため、推測で決めない。

依頼の中でテンプレート名が既に指定されているなら、聞かずにそれを使う。
**一覧に無い名前を指定されたときは、一覧を見せて選び直してもらう。**勝手に近いものを選ばない。

テンプレートが1つも無い場合は `references/20_templates.md` を読む。

### 2. 割付を確認する

`references/10_rules.md` を読んでから実行する。

```bash
python3 scripts/reskin_html.py <作業ディレクトリ> --to <名前> --dry-run
```

HTML ごとに「載せるレイアウト・**どう決めたか**・欠落」の表が出る。ファイルは作らない。

**次のどれかが出たら、手順3に進む前に利用者に伝える。**

| 表に出る症状 | 意味 |
|---|---|
| 決め方が「**要確認**」 | 1点差で決まった。**当たっていても、外れたときに気づけない** |
| 「決まらない」 | 移行先に対応するレイアウトが無い。`--layout` で指定する |
| 「欠落」 | 移行先に定義が無いクラス・画像がある。**見た目が崩れる** |

### 3. 差し替える

```bash
python3 scripts/reskin_html.py <作業ディレクトリ> --to <名前> -o <出力ディレクトリ>
```

**元のファイルは書き換えない。**前後を並べて比べられるようにする。
`-o` は省けない。`images/` と `print.html` も揃えて出る。

### 4. 検査 ★止まらないが、必ず行う

`references/10_rules.md` 第6章のチェックリストを実行する。

**載せ替えただけでは終わらない。寸法と文字サイズが変わっているので溢れる。**
**溢れは載せ替えでは直らない。**

```bash
python3 <slider-craft>/scripts/html_png.py <出力>/print.html -o qa_html
python3 <slider-craft>/scripts/html2pptx.py <出力>/print.html -o deck/deck.pptx
python3 <slider-craft>/scripts/fit_check.py deck/deck.pptx
python3 <slider-deck>/scripts/qa_render.py deck/deck.pptx -o qa
```

**画像を1枚ずつ実際に見る。** 生成できたことは、正しさの証拠にならない。
利用者に「確認してください」と丸投げしない。

**HTML の絵と pptx の絵を並べる。** ずれは片方だけでは出ない。

### 5. 手直し

**直すのは載せ替え後の HTML。** 出力された pptx を手で直さない。
やり直しても消えるうえ、同じ症状が次回も出る。

溢れ・文章・図の作り直しは**中身の話**なので、`slider-craft` の規約に従う。
**器の話と中身の話を混ぜない。**

### 先方の目で最後に一度見る

差し替えた資料を最初に見るのは先方である。**その立場で画像を見て、次を確かめる。**

- 提出先のフォーマットとして違和感がないか（配色・余白・書体）
- 縮んだ文字が、会議室のスクリーンで読めるか
- 置換された色と、保持された色が区別できるか

中身への疑問（判断できるか、根拠が足りるか）まで見るなら
`slider-craft` の `references/80_audience.md` に従う。**器の話と中身の話を混ぜない。**

## 承認ポイント — どこで止まるか

| 止める | 止めない |
|---|---|
| **どのテンプレートに載せ替えるか** | 決まった（要確認でない）レイアウト割付 |
| 元のファイルを上書きする書き込み | 新しい出力ファイルの生成 |
| 資料を外部に送る操作（**公開は禁止。**上記「資料を外に出さない」） | 手順4〜5の手直しの往復 |

**上記以外は聞かずに進める。** 判断したら理由を1行述べる。承認は待たない。

**止まるときは、その時点で未決のものを全部まとめて出す。**

## 自律判断の基準

### 聞かずに決める

- 各 HTML をどのレイアウトに載せるか（**指定・印・同名で決まったとき**）
- 出力ディレクトリ名
- 手順4で見つけた不具合の修正

### 必ず確認する

1. 指定されたテンプレートが一覧に無いとき
2. **割付が「要確認」か「決まらない」と出たとき。**推測で載せない
3. 欠落（クラス・画像）が出たとき。移行先に足すか、使うのをやめるかは利用者の判断
4. スライド寸法が違うテンプレートへ移すとき。**溢れる。**意図した余白も失われる

### 聞き方の型

**削る判断を仰ぐときは、全案に メリット・デメリット・コスト を揃え、
推奨に理由を1行付ける。** 「何もしない（縮小したまま出す）」も1案に入れる。
値を確かめるときは、**間違えるとどうなるか**を添える。

## やらないこと

| 依頼 | 行き先 |
|---|---|
| 資料の構成・メッセージ・図解の選定・文章 | `slider-craft` |
| 新規に資料を作る | `slider-craft` |
| **HTML から pptx への変換・その検査** | `slider-deck` |
| できあがった pptx だけを別テンプレに移す | **行わない。**HTML の正本を探し、それを載せ替える |
| .pptx の XML 直接編集、破損の修復 | 公式 `pptx` スキル |
| QCストーリー・4M・QC7つ道具の手法選定 | `mfg-improvement-frameworks` |

**器の付け替えは本スキル、中身は `slider-craft`。**
「テンプレートを変えたついでに文章も直して」と言われたら、
文章の部分は `slider-craft` の文体規約に従うと述べてから行う。

## タスク完了時

報告して終わらない。**残りの選択肢を出し、推奨を1つ示す。**

| 区分 | 例 |
|---|---|
| 見た目を詰める | 溢れた枚の中身を減らす、位置を整える（**HTML を直す**） |
| 別のテンプレートでも出す | 提出先が複数あるとき |
| 中身に戻る | 文章や図解を直す（`slider-craft` へ） |
| テンプレートを足す | 今回使ったものを次回のために登録する |
| 何もしない | 現状で提出できる、と判断する根拠を述べる |

## 記録 — 手順どおり進められなかったとき

**このスキルの指示に従えなかった事象は、`docs/feedback.md` に1行追記する。**
日付・原因ID・依頼・期待した挙動・実際の挙動・推定原因。

**ここを根拠に本体を直すのは、同じ原因が2回以上出てから。**
1回の事象で規約を足すと、似て非なる場面に誤って効く。
n を数える単位は症状ではなく**原因**。だから原因IDを振る。
