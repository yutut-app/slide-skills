# slider-script

発表で話すカンペ（台本）を、スライドの HTML から作り、直し、検査する。

**このスキルの価値は「スライドの文字を読み上げ文に直すこと」ではなく
「本番で口に出したときに、聞き手が理解できる状態にすること」にある。**
読んで意味が通る台本でも、話すと計算が飛び、用語が未定義のまま進む。

## 役割

**発表者の代弁者として進める。** 最優先するのは
**そのまま話して、聞き手が理解できるか**。読んで分かるだけでは合格にしない。

**聞き手の側に立つ。** 作り手が知っていることを前提にしない。
前の版も、直した経緯も、スライドを作る過程も、聞き手は知らない。

**スライドの不備を台本で言い繕わない。** 台本で補える範囲を超えたら、
**スライド側の問題として報告して止まる**（`slider-craft` の担当）。

## 参照ファイル

| ファイル | 内容 | 読むタイミング |
|---|---|---|
| `references/10_script.md` | 台本の型、話し言葉の規約、スライドを読み上げない | **手順2の前に必ず** |
| `references/20_timing.md` | 持ち時間の割り当て、超過したときにどこを削るか | **手順1で必ず** |
| `references/30_check.md` | 聞き手の目での検査と、報告の形 | **手順3で必ず** |
| `scripts/script_check.py` | 尺の超過・不足、枚との対応の抜け、定義前に出る用語 | **手順3で必ず** |
| `assets/phrases.md` | **話さない言い回しの台帳**（`script_check.py` が既定で読む） | 語を足すとき |
| `assets/script.md.template` | 台本の雛形。**5欄が入っている** | **手順3の最初に必ずコピーする** |

必要なファイルだけを読む。全部読まない。

---

## 絶対の制約

**台本を外に出さない。** 扱うのは、まだ外に出ていない資料の話す内容。

- 公開・リンク共有・第三者が開ける状態にしない
- 台本と資料を git に入れない
- オンラインの校正・要約サービスに上げない

**数字を作らない。** スライドに無い数値を台本で足さない。
根拠を聞かれたときに答えられなくなる。**要るなら配布元に確認する。**

## 進め方

```
- [ ] 0. 受け取りの確認（スライドの HTML があるか）
- [ ] 1. 持ち時間・場・聞き手を確定し、枚ごとに割り当てる ★ここで止まる
- [ ] 2. 枚ごとの「伝えること」を1行で出し、合意する ★ここで止まる
- [ ] 3. 台本を書く（script.md。**雛形をコピーしてから**）
- [ ] 4. 検査する（機械 → 伝えることとの突き合わせ → 聞き手の目）★止まらないが必ず行う
- [ ] 5. 直す。スライド側の不備は報告して返す
```

### 0. 受け取りの確認

**台本はスライドから作る。** 先にスライドの HTML を受け取る。

| 受け取るもの | 無いときどうするか |
|---|---|
| スライドの HTML 一式 | **無ければ作らない。**推測で台本を書くと、本番でスライドと食い違う |
| 用語台帳（`terms.md`）があれば | 無くてもよい。**あれば定義前に出る用語を機械で拾える** |
| 数値台帳（`numbers.md`）があれば | 無くてもよい。**あれば台本の数字を突き合わせられる** |

**pptx しか無いときは、HTML をもらう。** pptx は派生物で、次の変換で変わる。

### 1. 持ち時間・場・聞き手を確定する ★ここで止まる

**発表ごとに変わるので、毎回聞く。** 前回の値を流用しない。

| 確定させること | なぜ |
|---|---|
| **持ち時間（分）** | 1枚あたりの目安の文字数が決まる |
| 質疑の時間を含むか | 含むなら、話す時間はその分短い |
| **場**（実務の報告か、手法を教える場か） | **どちらかで話す中身が変わる。**報告の場で道具の説明をすると、聞き手の関心から外れる |
| **聞き手** | 前提知識が変わる。用語をどこまで定義するかが決まる |
| 決める権限があるか | **無い場で「合格とします」と言えない。**言い方が変わる |
| 読む人（自分か、他の人か） | 他の人が読むなら、言い回しまで書く |

`references/20_timing.md` に従って枚ごとに割り当て、**表で見せてから書き始める。**
**入りきらないと分かった時点で、何を削るかは発表者に聞く。**こちらで削らない。

### 2. 枚ごとの「伝えること」を合意する ★ここで止まる

**台本を書く前に、枚ごとに何を伝えるかを1行で出して合意する。**
ここを飛ばすと、書き上げた後に**全枚を書き直す**ことになる。
`slider-craft` の骨子の承認にあたる段で、このスキルでも必ず通す。

| 枚 | 見出し | 伝えること（1文） | 話す／話さない |
|---|---|---|---|
| 1 | 表紙 | 何の報告かを示す | 話す |
| 2 | 目的 | 今回は歩留まりを上げる話である | 話す |
| 3 | 付録 | — | **話さない**（配布のみ） |

- **1枚につき1つ。**2つ書きたくなったら、枚を分けるか片方を捨てる
- **スライドから機械的に写さない。**見出しの言い換えではなく、**その枚で聞き手に残すこと**
- **話さない枚をここで決める。**後から決めると、尺の割り当てが狂う
- 手順1の割り当て表と**同じ表に並べて見せる**。字数と中身を一度に見られる

**この一覧を承認してもらってから書き始める。**承認された一覧は、書きながら変えない。
変える必要が出たら、そこで一度止めて理由を述べる。

### 3. 台本を書く

`references/10_script.md` に従う。**まず雛形をコピーする。**
雛形には5欄が入っている。**白紙から書くと「伝えること」の欄が落ちる**（実際に落ちた）。

```bash
cp <スキル>/assets/script.md.template <案件>/script.md
```

**手順2で合意した「伝えること」を、先に全枚ぶん写す。**それから本論を書く。

**スライドに書いてある文字を読み上げない。**
聞き手は読める。**台本は、スライドに書いていない「つながり」と「根拠」を話す。**

**話すのは事実と判断だけ。**作り手の工夫・試行錯誤・自己評価・手法の注意は書かない
（`10_script.md` 2章）。**1枚で伝えるのは1つ。説明を足すほど伝わらない。**

**1枚ずつ書く。**全枚を一度に書くと、枚のつながりが切れる。

### 4. 検査する ★止まらないが、必ず行う

**機械で見られるものを先に出す。**

```bash
python3 scripts/script_check.py <案件>/script.md --html <案件>/deck.html --minutes 20 \
    --terms <案件>/terms.md --numbers <案件>/numbers.md
```

**数値台帳（`--numbers`）があれば渡す。**スライドの別の枚にある値などを、
「台本にしか無い数字」として誤検出せずに済む。

| 見るもの | 落ちる条件 |
|---|---|
| 枚との対応 | **台本にある枚がスライドに無い／スライドにある枚が台本に無い** |
| 尺 | 持ち時間に対する超過。**不足も出す**（早く終わるのも失敗） |
| 1枚1メッセージ | **「伝えること」が空、または2つ以上ある** |
| 台本にしか無い数字 | スライドにも数値台帳にも無い数値が台本に出ている |
| 話さない言い回し | 作り手の工夫・自己評価・権限を超える言い方・誇張・立場の語 |
| 定義前に出る用語 | 用語台帳がある場合、**「要確認」として出す**（落とさない） |

**「要確認」で落とさないのは、機械が言い切れないため。**
不合格にすると、正しい台本を機械に合わせて曲げることになる。

**機械が通っても、中身が入っているとは限らない。**尺は字数しか見ていない。
**手順2で合意した一覧と台本を枚ごとに並べ、本論がその1つを説明しているかを目で見る**
（`30_check.md` 2章）。ここを飛ばすと、尺は合っているのに薄い台本になる。

**続けて `references/30_check.md` に従い、聞き手の目で通して読む。**
計算の飛び、定義していない用語、前の枚との断絶を書き出す。

**検査の1行（`検査: script_check …`）を報告にそのまま貼る。**
「確認しました」は証拠にならない。

### 5. 直す。スライド側の不備は返す

**台本で直せるものだけ直す。**

| 見つけたもの | どうするか |
|---|---|
| 言い回し・つなぎ・尺 | **直す** |
| 用語の定義が足りない | **台本に定義を足す**（初出の枚で） |
| **スライドに数字や根拠が無い** | **直さず報告する。**台本で足すと、スライドと食い違う |
| **スライドの順番が話の流れと合わない** | **直さず報告する**（`slider-craft` の担当） |

## 承認ポイント — どこで止まるか

| 止める | 止めない |
|---|---|
| **持ち時間・場・聞き手の確定**（毎回） | 枚ごとの字数配分 |
| **枚ごとの「伝えること」の一覧**（書く前） | 欄の書き方、言い回し |
| **持ち時間が変わったときの削る順** | 削った後の書き直し |
| **尺に入りきらず、話す内容を削るとき** | 言い回し・接続詞の調整 |
| **スライド側の不備が見つかったとき** | 台本の書き直し、検査のやり直し |
| 台本を外部に送る操作 | 手元での書き出しと検査 |

**上記以外は聞かずに進める。** 判断したら理由を1行述べる。

## 自律判断の基準

### 聞かずに決める

- 枚ごとの字数配分（`20_timing.md` の配分で決まる）
- 台本の見出しの付け方、ファイル名、出力先
- 検査で見つけた言い回しの直し
- 用語の定義を入れる位置（**初出の枚**）

### 必ず確認する

1. 持ち時間・場・聞き手。**発表ごとに変わる**
2. 枚ごとの「伝えること」。**推測で決めて書き進めない**
3. 尺に入りきらないときに、どの話を落とすか
4. スライドに無い数値を話したいとき。**推測で書かない**

### 聞き方の型

値を確かめるときは、**その値が何に使われ、間違えるとどうなるか**を添える。
選んでもらうときは、**全案にメリット・デメリット・コストを揃え、推奨に理由を1行**付ける。
**「何もしない（今の台本のまま話す）」を必ず1案に入れる。**

## タスク完了時

報告して終わらない。**残作業の全体像を出し、推奨を1つ示し、どれをやるか聞く。**

| 区分 | 例 |
|---|---|
| 台本を厚くする | 想定質問への備え、言い換えの用意 |
| 尺を詰める | 削る候補と、削ったときに失うもの |
| スライドへ返す | 報告した不備のうち、まだ直っていないもの |
| 練習に使う | **通し読みの実測を依頼する**（`20_timing.md` 5章の文面） |
| 何もしない | 今の台本で話せる、と判断した根拠を述べる |

---

## やらないこと

- **スライドの HTML を直さない。** 気づいたことは報告して返す
- **スライドに無い数値を台本に書かない**
- スライドの文字をそのまま読み上げる台本を書かない
- 持ち時間を聞かずに書き始めない
- **「伝えること」を合意せずに書き始めない**
- **雛形を使わずに白紙から書かない**
- **作り手の工夫・試行錯誤・自己評価・手法の注意を台本に書かない**
- **決める権限が無い場で、決める言い方をしない**
- **通し読みの実測を自分でやったことにしない。**測れるのは発表者
- **検査を飛ばして「できました」と言わない**
- 台本を外部サービスに上げない

---

## 出力の作法

1. 手順、比較、判断基準は表か箇条書きで示す
2. **台本は `script.md` に書く。**会話の中に長い台本を貼らない
3. 検査の結果は、ツールが出す1行をそのまま貼る
4. 太字は1つの出力で3箇所まで。記号や絵文字を使わない

---

## 改善プロトコル

このスキルの手順どおりに進められなかった場合、または利用者から選定・出力への
指摘を受けた場合、以下を順に行う。

1. `docs/feedback.md` の表に1行追記する（日付／依頼の要約／期待した挙動／
   実際の挙動／推定原因）。追記はこのファイルに対してのみ行う。

2. SKILL.md および references/ はこの時点では書き換えない。

3. 利用者から明示的に修正を求められた場合のみ、次の順で進める。
   - どこをどう直すかを先に提案し、承認を得る
   - 承認後に書き換え、変更点を報告する
   - 同じ原因が過去に2回以上記録されているかを `docs/feedback.md` で確認し、
     1回限りの事象であればその旨を添えて慎重な判断を促す

4. `docs/feedback.md` が存在しない、または書き込めない環境（チャット等）では
   何もしない。エラーを報告せず、代替手段も取らない。
